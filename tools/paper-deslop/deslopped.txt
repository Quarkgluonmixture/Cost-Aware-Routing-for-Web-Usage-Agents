# Files that are already deslopped and must STAY error-clean.
#
# This is the ratchet. A real AI-drafted manuscript starts with hundreds of
# error-level Vale alerts; a build that is red from day one gets ignored, and
# an ignored gate protects nothing. So CI blocks only on the files listed
# here, and the full-repo lint is advisory (job summary only).
#
# Workflow: deslop a section, get it error-clean (`vale path/to/file.tex`),
# add it below, commit. From then on a regression in that file breaks the
# build. An empty list is the intended starting point -- zero friction, and
# the blocking set tightens by itself as the paper gets cleaned.
#
# One git pathspec per line: an exact path (`sections/intro.tex`), a
# directory (`sections/`), or a glob (`sections/*.tex`). Only tracked
# .tex/.md files are linted. An entry matching nothing is an error, not a
# silent no-op -- a typo here would quietly protect nothing.
#
# Run locally exactly as CI does:
#   scripts/ratchet_lint.sh          # blocking set
#   scripts/ratchet_lint.sh --all    # advisory, whole repo
#
# P79 notes (vendored install, see VENDORED.md):
#   - paths are repo-relative (docs/checkpoints/paper_drafts/...), resolved
#     from the repo root, not from tools/paper-deslop/;
#   - `make deslop-ratchet` runs exactly what CI runs;
#   - baseline 2026-07-24, `make deslop-ratchet ALL=1`: 553 error-level
#     alerts across the 19 tracked draft files, 384 of them em dashes. That
#     backlog is why nothing is listed yet. (An earlier 551 figure counted
#     only 12 files -- it globbed `paper_drafts/*.md` and missed the seven
