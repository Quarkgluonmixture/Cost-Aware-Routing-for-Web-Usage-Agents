Cost-Aware Routing for Web-Usage Agents

A web agent can read a page as a screenshot, an accessibility tree, or Set-of-Marks. Which representation should it pay for — and can routing between them beat any single one?

01 The phantom routing space

The six observation modes are corners of one 2×2×2 design cube: text channel × prompt style × whether a screenshot is rendered. The whole no-image face is the phantom space — signal of Set-of-Marks, cost of text.

P-SoM = SoM with the screenshot removed. Same marks, same prompt — it just drops the rendered image, so it pays DOM-class input cost (no vision-encoder image tokens) and lower latency. The question this project answers: is a corner of the no-image face worth routing to?

03 Cost is a floor — routing is the lever

All six modes cluster in a $0.065–$0.072 band, yet every single one sits far below the routed ceiling. Cost doesn't separate the modes; complementarity does.

P-SoM is the cleanest arm: +2.34 pp pooled lift, zero heterogeneity (I²=0%). Against the standard null it pools at p=5×10⁻⁶; against the stricter pre-registered floor H₀: θ ≤ +1.0 pp it still clears the gate at p=0.006 (z=2.53). Power 81% on the k=3 archive → projected 97% at the planned k=6. A representation that loses head-to-head is statistically the most valuable thing to route to.

How this was built. Preregistered design (primary gate = one-sided FE inverse-variance pooled superiority test, H₀: θ ≤ +1.0 pp; RE / HKSJ as sensitivity); a selection-bias-controlled 2×2 separating format from prompt style; race-safe distributed experiment orchestration across three compute tiers (aarch64 dev box · dedicated A100 VM self-hosting the benchmark · SGE HPC) with a 6-layer contamination watchdog; schema-versioned JSONL logging; 1,121 test functions guarding the analysis pipeline.

Stack: Python · PyTorch · HF transformers / accelerate · bitsandbytes (bf16 local inference) · OpenAI-style tool-calling over an API proxy · NumPy / pandas / SciPy · Playwright browser env · pytest · SGE/qsub.
