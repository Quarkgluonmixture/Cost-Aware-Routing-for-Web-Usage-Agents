与其挑 mode，不如按难度给步数设上限

学长，昨晚我把 router 这件事从头重新想了一遍，也用现有数据测了一遍。

起因是 REALM 的审稿人 sVJH 说我们没测更复杂的 router，比如用大模型来选 mode、在线学习、跑到一半再切换。我本来想做一个「先看第一步再决定」的 lookahead router 来补这个缺口。

结果发现，靠预测「这道题该用哪个 mode」来提分或者省钱，这条路走不通：数据里能学到的那点信号，比同一个实验重跑一次的随机波动还小。不过顺着同一批数据，找到了一个真正可行的方向：按题目难度分配步数预算，没希望的题早点停下，而不是去猜该用哪个 mode。

下面所有结论都来自已经跑完的 18,294 次运行（11 个 cell × 6 种 mode），外加 18 组同设置的重跑，这次没有新跑实验。

先对一下几个词

mode
agent 看网页的方式。DOM 只给网页结构文本，SoM 是截图加元素编号，Vision 只给截图，P-text / P-prompt / P-SoM 是三种只给文字的变体。
cell
一个网站配一个模型。cls = 分类广告站，red = 论坛站，shop = 购物站，带 _WA 的是 WebArena 的论坛站；B0 = Qwen3-VL-235B，B1 = Qwen3-VL-4B，B2 = Gemma-3-4B，B5 = GPT-5.6。
band
同一个设置原样再跑一次，SR 自己会变多少。cls_B0 是 4.5–7.6pp，red_B0 是 2.0–6.9pp。两个方法的差距没超过 band，就说明看不出真差别。11 个 cell 里只有 5 个做过重跑、有 band。
cap
单次运行允许走的最大步数，默认 30 步。
难度
报告里说的「按难度」，指的是预测出来的「这道题在这个 mode 下能做成的概率」。输入只有第 0 步的页面统计（可交互元素数量、页面文字长度）和题目文字（长度、有没有参考图、十几个关键词），用这个站点已经跑完的成功和失败结果来训练。它不是 VWA 自带的 easy / medium / hard 人工难度标注：那个标注只有 VWA 有，WebArena 没有，而且论文第 5 节已经测过，加进去 AUROC 只提高 0.0024。所以这套方法在 WebArena 上同样能用，11 个 cell 里就包括 WebArena 的两个。

一这次想解决什么

先交代一下背景。REALM 已经接收了，camera-ready 也改完了，下一步是 10 月 12 日通过 ARR 投 NAACL。论文第 5 节试了五种 routing 方法，全都没有赢过「一直用同一个 mode」。我们当时的解释是：「这题该用哪个 mode」的标注，只在至少有一个 mode 做出来的题上才有；成功率越低，能拿来训练的题就越少。所以越是需要 router 的地方，越没有数据来学。三个审稿人里，sVJH 专门指出我们没试更复杂的 router。

9 日白天我先试了最直接的办法：让 GPT-5.6 来当 router。一共四个版本，从只看题目文字，到把失败规律、各 mode 的成功率和成本都告诉它，11 个 cell 全跑了一遍。结果它 85%–95% 的时候都选 SoM，成绩和「一直用最好的 mode」差不多，差距在 −4.8 到 +1.5pp 之间，有 band 的 cell 里全在 band 以内。论文里那条不花钱的关键词规则，10 组里有 6 组比它还好。这里还有两点没有排除：一是给 router 的选项里，SoM 固定排在第二个，描述也是唯一写着「截图加编号列表」的，它 85%–95% 选 SoM 有多少是排版造成的，还没测；二是 cls_B5 这一格，router 和 agent 都是 GPT-5.6，等于自己选自己。

所以晚上想换个思路，做 lookahead：先用便宜的 mode 跑第 0 步，看它写出来的 thought（中位 132–135 个字符）、输出的置信度和看到的页面，再决定要不要换成贵的 mode。这个想法有个很好的前提：第 0 步动作之前，6 种 mode 看到的页面完全一样（224 题全部一致），所以可以直接拿现有数据来评估，不用新跑。多看一步的成本也不高，只占整次运行的 3%–12%。

顺便改正了我前一天的三个判断

  • 我原来说：最好的 mode 和第二好的差得越少，router 越有用。依据是 11 个 cell 上的一个相关系数 −0.696，意思是两者差距越小，router 相对「一直用最好的 mode」的成绩越好。这条站不住，原因有两个。第一，只有 11 个点，重新算是 −0.708，但 95% 置信区间从 −0.94 到 +0.63，连正负都定不下来。第二，更要紧的是，这个负相关不管 router 聪不聪明都会出现：router 只要把一部分题送去不是最好的 mode，成绩就会按两者的差距往下掉。差距大的 cell 掉得多，比如 cls_B5 前两名差 12.9pp，router 的结果是 −2.2pp；差距小的 cell 几乎不掉，比如 red_B0 前两名差距为 0，结果是 +1.5pp。所以它量的是「router 乱选时亏多少」，不是「有没有值得挑的东西」。真正该看的是：差距小的 cell，挑 mode 能拿到的上限是不是更高？这个量和差距的相关只有 +0.37，区间也跨过零。决定上限的其实是「有多少题至少有一个 mode 能做出来」（相关 +0.84），也就是论文里已经讲过的那件事。所以这条不算发现。
  • 我原来说「有 64% 的题，前两步各 mode 的状态还一样」。其实那只是网址一样，页面状态不一定一样。第 0 步动作之后，各 mode 所在的网址就有 27%–70% 不同了。严格来说，只有第 0 步动作之前这一个时间点，可以拿现有数据来拼接评估。
  • 我原来把「每一步都判断的 router」和「跑完再判断」混在一起说。其实应该分三种：做之前判断（只看题目和第一页）、边做边判断（看已经走过的步骤）、做完再判断（整次运行结束以后）。重跑属于最后一种，而且在 benchmark 里得先知道自己失败了才会重跑。

二为什么挑 mode 走不通

这一部分是整个故事的核心。结论是：不是我们的 router 不够聪明，而是数据里 router 要学的那个东西太小了，比随机波动还小，而且在需要做决定的时候根本看不出来。原因有四个。

原因一：能学的信号比随机波动还小

cls_B0 和 red_B0 是仅有的两个 6 种 mode 都各跑了两遍的 cell。我把它们的成败结果拆成四部分：题目本身难不难；每种 mode 整体好不好；某道题是不是正好适合某个 mode，这是 router 要学的；以及重跑带来的随机波动。

换成标注来看就更直观了。在一次运行里，看起来是「这题 SoM 没做出来、别的 mode 做出来了，所以应该换」的题，重跑一遍之后，cls_B0 只有 20/66 还是这样，red_B0 只有 9/43。也就是说，拿这种标注去训练 router，七八成都是在学随机噪声。要把噪声压下去，每道题每种 mode 至少得跑 3 遍（cls）到 9 遍（red）。

原因二：第 0 步什么都看不出来

我们有 18 个设置（某个 cell 的某个 mode，比如 cls_B0 的 DOM）各跑了两遍。对照两遍的结果，有 326 道题是一次成功、一次失败。这不是 bug：模型每次输出都有随机性，同样的输入跑两次，走的路可能不一样。

这 326 道题特别适合用来检验第 0 步有没有信息。平时拿成功和失败的运行来比，总会混进「题目本身难不难」：失败的题往往本来就更难。这里不一样，两次是同一道题、同一个 mode、同一个起始页面，唯一的区别就是那一次运气好不好，题目难度被完全抵消了。

检验的办法很简单：看成功那次和失败那次，第 0 步的信号（模型的置信度、自报的信心、thought 的长度等）哪次更高。如果这些信号能提前说明「这次能成」，成功那次应该明显更常更高；如果没用，就是一半一半，比例在 0.5 左右，和抛硬币一样。

随机性其实从第 0 步就开始了：235B 模型同一个 mode 跑两次，第 0 步做出相同动作的只有 24%–75%。但第 0 步并不决定最后的成败。这也正好解释了论文里那个现象：router 最需要学的那些题，恰好就是重跑时结果会变的题。结果是在 router 做完决定之后才分出来的。

另外，模型第 0 步写的 thought 也没有带来新信息。我把特征分三层叠加：先只用页面统计和题目文字，再加上模型第 0 步的输出，最后加上执行第 0 步之后的页面变化。

原因三：模型更强也没有用

论文第 6 节说过，这个负面结论可能会被更强的模型推翻。cls_B5（GPT-5.6，SoM 成功率 37.1%，是 11 个 cell 里最强的）是第一个可以检验的例子，但结果和预想的相反：

成功率从 27% 提高到 37%，涨的几乎全是 SoM 这一个 mode。其他 mode 能多做出来的题，SoM 基本也能做出来，所以真正需要 router 去挑的题反而少了。与此同时，重跑的随机波动没有下降，还是 12.9%。所以决定性的条件不是模型强不强，而是各个 mode 之间是不是互补。从 11 个 cell 看，需要 router 的题最多也就占 14–16pp，模型再变强也没有继续上涨。这正好可以回答审稿人 4s7L 要的那条曲线：它是先涨后平的，不是一直往上。需要说明的是，cls_B5 只有 DOM 做过重跑；GPT 这一家文字能力强、Vision 只有 12%，这个特点也可能是原因之一。

原因四：换更丰富的标注、把不同模型的数据合在一起，都没有用

我一直在想，我们太依赖「成功 / 失败」这一种标注了，失败的 50%–95% 的运行只贡献了一个 0。能不能用大模型把轨迹、失败原因、「差一步就对了」这些信息综合起来，给出更丰富的标注，或者先做一个 planner？另外，不同模型的数据能不能合在一起用？这几种做法我都用确定性的方法估了上限。大模型来做只会引入更多噪声，不会比这个上限更好。

做法标注本身稳不稳对 router 有没有帮助
按轨迹走了多少成功路径打分，不只是 0/1稳一些：两次重跑的相关是 0.74，原来的 0/1 标注一致性只有 0.22–0.58可学信号和噪声之比，cls 从 0.32 升到 0.49，red 没有变化（0.12）
按失败原因分类（10 多类）很稳：两次重跑的一致性 0.55–0.70用失败原因预测「换个 mode 能不能成」，AUROC 只有 0.34–0.57
「差一步就对了」的运行太少：只占失败的 1%–6%可学信号和噪声之比 0.34 → 0.36，基本没有变化
先让模型想一遍任务（planner）就是第 0 步的 thought不如直接看题目（见原因二）
把不同模型的数据合起来「题目难不难」各模型看法一致，相关 0.46–0.72「这题适合哪个 mode」各模型看法不同，相关只有 0.08–0.24；拿别的模型训练，在 4 个 cell 里有 3 个比随机还差
一句话总结：「这道题难不难」是能学的，而且不管换模型还是换网站都通用；「这道题适合哪个 mode」学不到，而且换一个模型答案就变了。失败的数据也不是白跑：稳定的「怎么都做不出来」那一类，正好是判断「要不要放弃这道题」的训练数据。还有 326 组「同一个起点、一次成功一次失败」的重跑，它们第一次走不同的那一步，天然就是一组偏好对比，适合拿来训练 agent 本身。不过那是另一篇论文的事了。

做之前

只看题目和第一页

「这道题难不难」是真的能看出来的，AUROC 0.6–0.86，而且稳定、能迁移。它适合用来决定「做不做、给多少步」，但决定不了「用哪个 mode」。

边做边判断

看已经走过的步骤

前面几步看不出后面会怎样。第 0 步见上文；论文里在第 3、5、10 步判断要不要提前放弃，AUROC 0.34–0.67，有好几组还不如随机。

做完再定

整次运行结束以后

判断自己失败了，这件事能做到一部分（AUROC 0.4–0.74）。但失败以后重跑能不能成功，概率只有 4%–10%，而且事先看不出来，所以最多只能多出 1pp 左右。

这里单独说一下「收敛到 DOM、Vision、SoM 三个 mode」这个想法。作为部署时的选项，三个 mode 是合理的，也正好对应论文里文字、截图加编号、纯截图这三类。但它不能让 router 变得可学：能拿来训练的题从个位数涨到 8–13 道，仍然只有 2 个 cell 够用；第 0 步之后在三个里选，每个 cell 都和随机换差不多（±1pp）；如果 DOM 本来就是最好的，还会越选越差。另外，如果报这个设置，要说明 WebArena 上会丢掉大部分上限。

我一开始的直觉是：确定性任务的 router 好做，因为成败很清楚；agent 任务失败的原因太多，所以单一分类的 router 难学。看完数据，这个说法要改一下。难点其实不在失败原因多，失败原因的分类反而很稳，只是这些原因都是题目本身的属性。真正的区别有两个。第一是标注有噪声：问答任务里同一个问题问两遍，答案基本一样；这里同一道题同一个 mode 跑两遍，有 10%–14% 结果不同，而 router 最想学的那批题有 82% 会变。第二是做决定和看到结果之间隔着 7 到 19 步随机的操作，问答任务的 router 没有这一段。

四换个思路：按难度给步数设 cap

转折点来自一个想法：我们不一定非要盯着 mode 不放，mode 可以反过来用，用来证明结论在主流的几种表征下都成立。于是我把 router 要决定的事情，从「看什么」换成「最多跑几步」。

这样换有一个很大的好处：每次运行在第几步成功是有记录的，所以「如果只让它跑 k 步会怎样」可以精确算出来，不需要任何拼接假设。成本和耗时也都按每一步的实际数字累加。

钱都花在哪了

最简单的办法是所有题统一设一个 cap。这样已经能省不少了：cap 设 15 步，SR 降 3.1pp，成本省 43%；设 20 步，SR 降 2.4pp，省 28%。但统一的 cap 对「成功得比较慢」的 mode 伤害最大。比如 cls_B1 的 SoM，成功的运行有一成要走到 30 步，cap 一砍就降 6.7pp，而这个 cell 的 band 只有 0–1.8pp。

五种分配步数的办法比一比

我比较了五种办法：一是所有题统一一个 cap；二是随机挑一部分题给少一点的步数；三是按事先判断的难度，把最没希望的一部分题给少一点的步数，其余照常跑满，也就是「分两档」；四是再加一档，最没希望的直接不做，次一点的给 8 步；五是事先预测每道题要走几步，按预测值来定 cap。每种办法把各种参数都扫一遍，取最好的结果：

最严格的检验是：在第一次运行上训练判断难度的模型，把它给出的步数安排原封不动地用到第二次重跑上。18 组重跑的结果如下：

对比一下第三部分：从数据里挖出来的挑 mode 规则，换一次重跑之后没有一条还超过 band。区别在于，按难度分配步数，靠的是「题目难不难」，这个信号稳定，而且不同模型之间通用；它也只改变同一个 mode 跑多久，完全用不到那个比噪声还小的「这题适合哪个 mode」。

有三点要老实说明：(1) 按难度分档比统一 cap 多出来的 1.4pp，来自「见过同类题」。碰到完全没见过的题型时，两者几乎一样（DOM 上是 3.6 对 3.7）。所以 41% 的节省主要是设 cap 本身带来的，按难度分档是锦上添花。(2) 按论文自己的规矩，SR 下降小于 band 只能说「分辨不出来」，不能说「没有影响」。235B 的几个 cell 都在 band 以内，但 4B 那些成功率低的 cell，band 只有 0–2pp，那里的下降是能看出来的。(3) 它和论文里「判断要不要放弃」是一回事，放弃就等于 cap 设成 0。论文里「边做边判断要不要提前停下」没有信号，改成「做之前定好步数」，信号就有了。

已经提前锁定了一次真正的预测

上面所有的证据，都是拿已经跑完的数据回头算的。B1 在购物站的实验还在跑 P-text，后面还排着 P-prompt，这是唯一一个可以「先写下预测、再看结果」的机会。9 号晚上 22:41，我已经把预测锁定了：用购物站已经跑完的数据（B1 的 DOM、SoM、Vision、P-SoM 和 B0 的三种 mode，共 3,038 条）训练，给 434 道题打难度分，预先定好两种分档方案。P-text 和 P-prompt 的结果一眼都没看，已经跑完的 216 条 P-text 也全部排除在检验之外。判断标准也提前写好了：在还没跑的题上，「分两档」的 SR 下降必须同时小于统一 cap 和随机分档。购物站没有 band，所以只看方向，不看大小。不管结果好坏都会如实报告。文件已经带 tag 提交并推送了。

五除了设 cap，还看了哪些方向

设 cap 是这次最主要的收获，但它不是唯一一个跳出「挑 mode」的思路。下面这些方向也都用现有数据看过了，一并汇报：

有用，但幅度不大

两个 mode 答案一致再交卷

它不是用来选 mode 的，而是用来判断「这个答案可不可信」。8 个 cell 全部有效：两个 mode 答案一致时，正确率是 35%；不一致时只有 19%。代价是要花两倍的钱。

有用

选 mode 之前要试多少题

论文第 8 节建议「先在自己的网站上测一下」，但没说要测多少。现在可以回答了，见下面第二张图。

收益很小

跑完判断失败再重跑

比随机重跑多 0.8–1.0pp。失败以后重跑能不能成功，事先看不出来，所以只能多这么一点。

没用

小模型先做，不行再换大模型

235B 和 GPT-5.6 能做对的题不太重合，两家合起来能做对 46%，比 GPT-5.6 单独的 37% 高。但判断「交给谁」只多 0–2pp，那多出来的 9pp 是两个模型都跑一遍换来的。

没用

事先预测要走几步

见上面的表：按预测步数定 cap，在每个节省水平上都不如统一 cap。

不适用

压缩历史记录

我们的框架本来就不保存完整的历史。从第 0 步到整次运行的平均，每步输入只增加 9%–14%，没什么可以压缩的。

还没做，是候选

按「怎么定位元素」来分流

点元素有三种方式：用编号、用网页原生的节点 ID、用坐标。这是唯一一个每一步都有明确标注的方向（大约 1.3 万次动作都知道是否成功），而且它对 SR 的影响和 mode 差不多大。它属于执行层的问题，不属于表征，要不要放进这篇论文，需要学长定。

还没跑

卡住了就换 mode

router.py 里已经写好了，但一直没有实际跑过。离线估算下来会不如一直用 SoM，不过估算毕竟不是实测。

没用

用大模型写更丰富的标注

见第二部分原因四：标注能变得更稳，但换不来「这题适合哪个 mode」的信号。

两个 mode 答案一致，正确率高多少

选 mode 之前，每种 mode 要先试多少题

做法是：先抽 n 道题，6 种 mode 都跑一遍，选其中成功率最高的；然后看它在全部题上是不是和真正最好的 mode 相差不到 2pp。每种情况抽 500 次：

cls_B5（最好的 mode 领先 12.9pp）red_B0_WA（领先 8.7pp）cls_B0（领先 2.2pp）red_B0，用第二次重跑来检验

最后一条线最值得注意。red_B0 就算把 205 道题全都试一遍，选中的 mode 在第二次重跑上也几乎从来不是最好的：第一次最好的 DOM（14.6%），第二次掉到了 11.7%，而第二次最好的换成了 P-SoM。6 种 mode 的成功率都挤在 7pp 以内，每次重跑排名都会重新洗牌。另外两个有重跑的 cell 情况好得多：cls_B1 的三个 mode 各试 50 题，98% 能选对；red_B1 的两个 mode 各试 10 题就够了。所以实际的建议是：先看各 mode 之间的差距有没有超过 band。超过了，每种 mode 试 50–100 道题就能选对，在 235B 上大约是 600 次运行、45 美元；没超过，就不必再试了，挑一个最便宜的文字类 mode 就行。

六业界是怎么做的

我整理了两份 2026 年 7 到 9 月 computer-use agent 领域的综述，存在 docs/literature/raw/ 里。两份都是用 AI 做的检索整理，其中 9 篇论文的 arXiv 编号我逐个核对过，都存在，标题也对得上；但 GitHub issue 和官方文档里的数字没有核对，引用之前要去读原文。下面是它们描述的几个主流系统，router 放在哪一层：

系统看不看 Accessibility Tree看不看截图由谁来选和我们的哪个结果对得上
Claude Computer Use不看主要靠截图没有在两者之间切换的 router—
Claude Browser Use看（页面状态和元素引用）可以看模型自己选工具，具体策略没公开相当于白天试的 GPT-5.6 router，11 个 cell 都在 band 以内
Claude 整体产品能用 API 就用 API，其次 Browser Use，最后 Computer Use按任务类型选接口相当于论文第 5 节那句话：router 最后会选中的那个 mode，本来就应该所有题都用它
OpenAI API 里的 CUA不看主要靠截图没有在两者之间切换的 router—
Codex 桌面版看（AX / UIA）看，默认两个一起拿大模型加上提示词，优先用 AX，不行再用坐标两个一起拿就相当于我们的 SoM：每步输入多 24%–37%，在论文里 8 个 cell 都没超过 band；AX 不行再截图，就是我们一直没跑的「卡住就换」
Gemini CLI默认看只有碰到「黄色按钮」这类描述才看手写规则我们测过这条规则，在 cls_B5 上降了 17.4pp

至于企业里 router 究竟是怎么训练的，公开资料里只有三种做法：

  1. 手写规则，不训练。比如按接口排优先级、Skyvern 的成本阶梯、Gemini 看到颜色描述就截图。
  2. 不单独做 router，而是直接放进 agent 的模型里一起训练。把所有工具都当成可选的动作，用强化学习按任务是否成功来训练，「这一步要不要看截图」只是其中一个动作，所以不需要「该用哪个 mode」的标注。它能绕开我们遇到的问题，靠的是同一道题跑几百次。综述里说 Qwen-CUA 用了约 10 万个 CPU 核来跑这些轨迹，这就是把 10%–14% 的随机波动平均掉的代价，和第二部分算出来的「每道题要跑 3 到 9 遍」是同一件事，只是规模比我们的预算高一到两个数量级。
  3. 单独训练一个轻量的分类器。学术上有 FrugalGPT、AutoMix、Hybrid LLM、RouteLLM 这条线（编号都核对过）。工业界唯一公开的是 GPT-5 在快模式和思考模式之间切换的 router。关于它「用用户切换、偏好和测到的正确率来持续训练」的说法，是我凭记忆写的，官网没有抓到原文，所以标成了未核实。要注意，它选的是模型档位，不是观察方式；它在问答任务上能做成，是因为问答的标注噪声小，而且做决定和出结果之间没有十几步随机的操作。

两份综述都说，computer-use 领域里还没有公开的、单独训练的「选观察方式」的 router，并把这看成一个机会。我们 11 个 cell 的数据给出的结论正好相反：不是没人去做，而是做不出来。在 2%–37% 的成功率下，每一步做决定的时候都没有可用的信息，而「做之前判断」这一层已经被按任务选接口这个做法覆盖了。

NAACL 论文可以这样讲

REALM 讲的是「routing 学不到」。这次的分析可以把它推进一步，讲清楚三件事：哪些东西能学，哪些东西学不到以及为什么，能学的那部分可以拿来做什么。暂定的题目是 Route the Budget, Not the Representation，意思是：与其在各种表征之间挑，不如把步数预算按题目分配好。

  1. 引言：大家默认 router 应该在不同的观察方式之间挑选。业界的做法是优先用结构化文本、必要时再看截图，但还没有人做出能学习的逐步 router。
  2. 实验设置：沿用 11 个 cell × 6 种 mode，外加 18 组重跑。
  3. 拆解（主表）：把结果拆成题目难度、mode 整体好坏、题目和 mode 是否对路、随机波动四部分。router 要学的那部分只有随机波动的 0.12–0.34；标注重跑后只有 20/66 还成立；第 0 步看不出结果；模型更强以后，mode 之间反而更重合。
  4. 十几种方法，同一个上限：REALM 里的五种，加上这次的 LLM router、bandit、lookahead、按信心换、重跑、手写规则、挖规则、更丰富的标注、合并模型，全部只比随机好 1–2pp。
  5. 能学的那部分拿来做什么：「题目难不难」能跨模型迁移，据此可以决定放弃哪些题，也可以决定给多少步。附上成本和 SR 的对比曲线、6 种 mode、11 个 cell、18 组重跑里有 14 组成立、提前锁定的预测检验，以及选 mode 之前要试多少题。
  6. 答案一致性检查：两个 mode 答案一致时更可信，8 个 cell 都成立，但幅度不大。
  7. 局限：11 个 cell 里有 6 个没有 band；按难度分档比统一 cap 多出的 1.4pp 依赖见过同类题；所有结论都是离线算的；跨 benchmark 的比较只有一个模型家族。
  8. 给实际做 agent 的人的建议：先在自己的网站上测一下；给注定失败的运行设上限；把预算按题目分配，而不是在 mode 之间来回挑。
8 月列出的七个可能被审稿人质疑的地方这次分析之后的情况
1 routing 能不能推广题目难度能跨模型、跨网站迁移；题目和 mode 是否对路不能迁移（第二部分原因四）
2 能不能跨网站、跨 benchmark11 个 cell 都用上了；其中 6 个没有 band，靠接下来的第 1、2 项实验补
3 基线够不够强GPT-5.6 已经加进来了，模型更强也没有推翻结论（第二部分原因三）；第 3、5 项实验会继续补
4 router 能不能赢过简单的规则正向（直接用业界规则）和反向（从数据里挖规则）都测了（第三部分）
5 成本和准确率的取舍稳不稳定按成本和按耗时算，两条曲线一致（第四部分）
6 能不能得出更一般的结论按难度分配步数，在 6 种 mode 上都成立
7 很高的 AUROC 是不是人为造成的第二部分原因二已经分清：第 0 步的输出几乎不增加信息，这和「判断要不要放弃」依靠的题目层面的信号是两回事
