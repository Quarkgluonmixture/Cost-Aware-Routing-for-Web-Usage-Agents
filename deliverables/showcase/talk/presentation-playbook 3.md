# Presentation SOP —— 从目标到现场交付

_适用于个人演讲、workshop、showcase、进展汇报与决策汇报。Workshop 暂按主题讲解与演示处理，本文不涉及学员学习效果、练习与考核设计。
自包含：附录 A–E 是可复制的模板；HTML 与兜底页可直接打开，脚本需要按说明配置。
保留旧章节编号以兼容已有引用；§8 留空。场次文档仍负责各自的内容和进度，本文只负责通用方法。_

**怎么用：**先填 §0 的场次简报，按 §0b 走一遍；需要做什么产物，再查对应章节。小型汇报不必把所有模板都建一遍。

**规则分四层：**

- **底线**：事实与证据匹配；准确标明产品、数据和演示状态；不把案例表现推广成未经验证的普遍结论；遵守本场的信息展示边界。
- **默认建议**：一页一事、先写内容骨架、出声计时、关键环节准备兜底。可以根据目的调整。
- **个人偏好**：纸白 HTML、Charter 配系统字体、中文操作提示配英文口播。适合时沿用，不限制工具和语言。
- **案例经验**：某场有效的政治判断、叙事技巧和操作方法。放在 §7 的案例库，不自动升级成通用禁令。

## 0. 先定目标，再选形式

### 场次简报：准备前先填这一页

1. **任务与承诺**：为什么现在讲？已答应的交付、日期是什么？本场明确不解决什么？
2. **听众**：谁参加、知道多少、关心什么、谁能作决定？不要默认房间一定有哪几类人。
3. **希望产生的结果**：结束后，希望听众理解什么、认可什么，或决定什么？用一句话写清。
4. **核心主张**：为了这个结果，最值得保留的一句话是什么？主张、建议与已验证事实分别标明。
5. **证据与边界**：支持主张的材料在哪？哪些是实测、估计、假设或计划？哪些信息可以展示和分发？
6. **约束**：总时长（含问答）、语言、现场/远程、投影/共享窗口、材料提交格式、是否预审、设备与权限依赖。
7. **收束与后续**：需要什么请求或行动？没有请求时，用什么结论收束？由谁、何时承接后续？

这些业务事实不一定在仓库中；缺失时向主办人或相应负责人确认。准备阶段先确认时段，并写清未知项与暂定假设。

### 先按目的选内容骨架

| 场景 | 默认主线 | 收束方式 |
| --- | --- | --- |
| 主题演讲 / workshop 讲解 | 为什么值得关注 → 核心概念或方法 → 例子 / 演示 → 适用边界 | 核心结论、资料入口或后续讨论 |
| Showcase | 使用者的任务 → 产品如何完成 → 有价值的结果 → 当前可用范围 | 试用入口、反馈问题或下一次沟通 |
| 进展汇报 | 原先承诺 → 实际交付与证据 → 偏差和影响 → 下一步与阻塞 | 明确承接人；需要帮助时提出具体请求 |
| 决策汇报 | 要作的决定 → 可选方案与取舍 → 证据和不确定性 → 建议 | 谁决定什么、何时决定、未决定的影响 |

这是起手骨架，不要求每次逐项讲完。技术听众也可能需要入门解释；决策者也可能需要看细节。按本场的信息缺口选材料。

### 再选呈现形式

| 形式 | 适用条件 | 需要准备 |
| --- | --- | --- |
| 片子 + 讲解 | 图、论证或解释能直接服务目标 | 提纲 / 备注、片子；必要时备用参考页 |
| 现场 demo | 亲眼看到行为能增加理解或可信度，且时间和环境允许 | 操作步骤、经过验证的演示路径、独立可用的兜底 |
| 录播 demo | 需要控制时长、固定画面、异步审阅，或现场依赖不稳 | 视频、旁白 / 提纲、录制检查、静态备份 |
| 单页简报 | 小范围讨论，或听众要反复查阅多个相关议题 | 单页材料、讲述顺序、细节链接 |

有能跑的东西，不等于本场必须演。需要预审，也不等于必须录播：提纲、片子或一次走查可能已经够用。
汇报可以有 roadmap，只要它回答本场需要的时间、依赖或资源问题。日期有承诺依据才写成承诺，否则标明假设。

## 0b. 总流程（按依赖走）

1. 填场次简报，先处理依赖别人响应的时长、权限、格式和预审要求。
2. 定一个主张、内容顺序和收束；列出证据、疑问与不能主张的内容。
3. 写提纲或台本骨架；为每段说明它对本场目标有什么用。
4. **按需**制作 demo、图表或案例，核验后再用它们做片子。不为没有 demo 的场次制造 demo。
5. 做观众看的材料，同时保留证据来源；确定本场需要的操作与兜底文件。
6. 出声计时、练关键转场和操作，做一次听众视角的审阅；据问题修改，再确认修改后的版本。
7. 在实际展示条件下检查画面、音频、链接与兜底，冻结本场要用的材料。
8. 按目标收尾：记录决定、疑问与后续行动，交付观众真正需要的材料。
9. 归档本场版本，记录结果与原因；只有确认适用条件的经验才进入本文。

准备投入按重要性与风险安排，不把某场一天做完当成通用工期。

## 1. 体系：职责分清，文件按需

| 职责 | 唯一负责的内容 | 独立成文件的条件 |
| --- | --- | --- |
| 计划 / 权威文档 | 场次简报、主张与证据、边界、后续要求 | 内容复杂或需要多人审阅 |
| 片子 / 单页 | 观众看的论点、图和必要证据 | 本场需要视觉材料 |
| 台本 / 演讲者备注 | 嘴里说的、停顿、转场、问答的口头答法 | 需要精确措辞、录播或复杂转场 |
| Runbook | 环境、入口、操作 ID、命令、恢复办法 | 现场有多步操作或技术依赖 |
| 兜底 | 原路径不可用时还能支持核心主张的材料 | 有 demo、视频或其他易中断依赖 |

**轻量版**：一份场次提纲 + 片子备注即可；没有片子时可只用提纲。
**完整版**：按职责拆文件，正文保持链接，不复制环境表、操作 ID 和问答全文。
轻量版把这些职责设为同一文件的不同小节，仍只维护一份事实。

数字与定义来自证据产物；片子和口播可以重复同一结论，但应由同一来源生成，或显式登记引用并检查。
“不能重复”针对的是独立维护事实，不禁止观众同时听到和看到核心主张。
计划保存问题的证据与判断依据；台本只维护其口头答法并链接来源。Runbook 保存动作，台本只引用稳定步骤名。
复杂场次可从同一来源生成一份只读的现场提示单，不再手改生成副本。

## 2. 内容怎么定

1. **本场任务决定框架。** 上次反馈是线索，不是裁决；先判断当时的听众、职责与任务是否仍相同。
2. **开场交代为什么现在讲。** 给必要背景和本场结论 / 问题；个人经历、悬念和自我定位都按需要使用。
3. **每段只承担一个作用。** 支持主张、解释机制、呈现取舍或推动决定；承担不了的删掉或移到参考材料。
4. **按信息缺口选深度。** 尊重既有工作，清楚区分已有能力、你的增量与仍需他人完成的部分，不靠贬低旧方案制造价值。
5. **事实、推断、建议分开。** 相关性不写成因果，能力存在不等于应当启用，原型可用不等于已部署。
6. **重要主张配证据。** 可来自仓库、正式文档、公开原始来源或负责人确认；记录来源、日期和适用口径。
   能预先核验就预先核验，不要求每句话都能在台上十秒复算。不要引用未核过的模型转述。
7. **保留必要边界。** 只讲会影响听众理解或决定的限制；不要求所有数字都写“暂定”，也不把所有裁掉的内容逐一解释。
8. **请求与目标匹配。** 决策汇报优先一个明确决定；确有多个请求时标优先级、承接人和期限。主题讲解可以用结论收束。
9. **准备尖锐问题。** 包括证据够不够、和什么比、当前能用什么、代价和依赖是什么。未知项写清怎么确认，不编答案。

## 3. 片子（slides）

- **默认一张一事。** 标题表达结论或问题，图形支撑它；核心句可以同时说出与显示，不把整段讲稿贴上屏。
- **字数是提醒，不是可读性的证明。** 英文页可从少量文字起步；中文、代码页、参考页按用途调预算。
  使用附录 E 时，在脚本的 `BUDGET` 中统一设置预算；它按英文词 / 中日韩字符混合计数，不能替代视觉检查。
- **图形按内容选。** 矩阵适合受控比较；流程适合任务路径；时间轴适合计划；截图适合固定画面、细节标注和前后对照。
  现场产品更清楚时切产品，截图更清楚时用截图，不设截图禁令。
- **数字先钉口径。** 什么算一人 / 一次 / 一组，输入与版本是什么，统计范围和单位是什么？图与清单从同一来源生成。
  案例数不能偷偷变成整体表现；效率结论需要相应的比较依据。
- **按听众清理术语。** 首次出现解释必要术语，删除无用内部代号；不要用“禁止第一人称”代替编辑判断。
  讲者提示、私人备注和不适合外发的名字不混进观众材料。
- **让画面能被看清。** 检查最小文字、对比度、配色含义、裁切和屏幕共享后的尺寸；颜色之外加文字或符号区别状态。
- **工具和风格是选项。** 个人默认：单文件 HTML、纸白底、Charter + 系统无衬线 + mono；也可用 PowerPoint、Keynote 或 Slides。
  以主办方格式、协作与交付需求为准。单页可采用已有的 report-dashboard 模板。
- **现场版和会后版用途不同。** 稀疏片子需要讲述才能成立时，会后另附简短说明和来源链接；不能假定转发 deck 就足够。
- 多轮修改后检查标题、转场、引用与图表是否还一致；结构已经失效才重组，不要求“十几轮之后全部删掉重写”。

## 4. 台本

- 提纲、演讲者备注、逐字稿按需要选。个人默认中文提示、英文口播，场次语言不同时照实际语言写。
- 精确措辞只锁定核心主张、边界和请求；其余保留自然说话的空间，不固定必须背几句。
- 每段写：目的 → 要点 / 台词 → 画面或操作步骤名 → 转场。操作 ID 与命令只住 runbook。
- 标出需要停顿和让观众看画面的地方，停多久通过彩排确定。
- **保底版本先写好。** 保留核心结论、必要证据和本场请求；按价值裁剪展开、案例和 demo，不给某种形式永久豁免。
- 字数与语速只能预估；最终以出声计时为准，加上操作、停顿、问答和切换，不套固定加成比例。
- 被打断时判断：影响理解的现在答；能延后的记录并说明何时回来。答完用一句话回主线。
- 不知道就说不知道，同时说明由谁、用什么信息能确认。口头答法放台本，证据链接回计划。
- 模型可以起草，最终用你说得顺的表达；不要求每场都由你全文重写。

## 5. Demo

### 设计与证据

- **先写这一拍证明什么。** 可以展示能力、解释机制、走完整任务或比较方案，不必都是“故障 → 修复”。
- **明确状态。** 已部署产品、本地实现、原型、模拟依赖、合成数据、历史录制分别标明；不要把局部演示讲成端到端已上线。
- **真实执行只是起点。** 记录案例如何选择、输入条件、版本和演示范围。挑选的例子证明该条件下的行为，不自动证明成功率或代表性。
- 需要比较时尽量控制变量，条件有变化就说明；矩阵只在它能帮助解释时使用。
- 演示随机系统时，区分为可重复演示固定条件与为了好看反复挑结果。需要主张通常表现时另用覆盖范围明确的评估证据。
- 故障演示可用隔离环境中的可控注入，也可复现真实故障；说明注入点和它能代表什么。不要为了叙事去修改共享环境的凭证或状态。
- 反转叙事是可选技巧。可以先展示表象，再揭示机制；相关限制须在推出结论前说明，不误导听众对成熟度和范围的判断。

### 现场操作与兜底

- 权限和环境尽早实跑确认。用稳定 URL / ID，不靠列表位置；用独立演示数据集或固定入口，避免靠“所有人不再运行”维持顺序。
- 减少无关切换，提前登录，标签按讲述顺序排列。缩放和字体按实际屏幕确定，不能靠固定百分比保证看清。
- 演前重新检查入口、音频和结果是否仍对应本场版本；刷新产物后同步证据引用、旁白和兜底。
- 默认兜底是能离线打开的截图、短片、PDF 或已保存输出。它应覆盖核心主张，且不依赖刚刚失败的服务。
- 预先规定何时切兜底。默认不当场调试，简短说明这是已保存的演示，再继续。
- 聚焦测试的红绿对照只适用于技术听众与回归保护这个论点；它仍依赖运行环境，不是“无栈兜底”。
  在预先隔离并验证的环境运行，或展示保存输出；不要现场用 `git checkout` 覆盖工作文件来切换结果。

### 录播

- 按叙事段落拆短片，长度服从本场时限，不固定三拍或每拍时长。必要时讲架构，必要时用终端证据。
- 录前核对输入、产物、引用与演示路径；使用附录 E 时，读清 `--check` 的覆盖范围，检查通过后仍需人工回看。
- 终端尺寸、语言、声音、分辨率以观众能看清听清为准。录屏前关闭通知，检查路径、历史输出和账号信息。
- 可以删无关等待，不能把剪辑后的时长当性能证据；影响结论的跳步和依赖应说明。
- 原始日志保留在受控位置，分享版另行整理。删行是为了相关性或信息边界，不为躲避合理比较问题。
- 字幕按语言、静音播放和观看条件决定；审阅字幕是否改错技术词或数字。
- 全片回看后才交付，核对实际发出的版本。视频默认放仓库外；截图、日志也按本场数据边界管理。
- 视频不能播放时，切到本地可打开的静态材料；原始终端输出过长时，另做有来源的可读摘录，保留原件。

## 6. 彩排与放行

**默认练法，可按场次缩放：**

1. 完整出声讲一遍并计时，记录卡壳、冗余、画面等待和超时位置。
2. 修真正影响理解的内容与表达，再确认修改后的版本；不要一边无限改稿一边假定原计时仍有效。
3. 单练关键转场、请求、问答返回和点击路径；录一段回看声音与节奏。
4. 做一次听众视角审阅：背景是否够？核心主张是否清楚？证据是否支持它？当前可用范围和下一步是否明确？
   可请同事看，也可自己按角色走查；这不是 workshop 的学习效果评估。
5. 在实际展示方式下检查全屏、屏幕共享、投影比例、音频、链接和离线兜底；导出材料单独检查。

**放行条件：**核心主张有来源；重要限制已说明；完整版本在时限内；短版讲得通；关键画面可读；关键依赖已验证；出事能继续。
来不及满足时，删减范围或换形式，不用“做了几遍彩排”代替这些条件。

会前按主办方需要发材料或说明目标、形式和请求，不强制只发一句话。为设备检查与休息留时间，最后一刻只改事实错误或阻塞问题。
彩排反馈按事实、理解、偏好分类处理；采纳影响目标的反馈，遇到与事实或边界冲突的建议说明原因。

## 7. 收尾与归档

- **按本场目标交付后续**：汇报记录决定、负责人、期限和未决项；showcase 提供可用入口与反馈渠道；主题讲解 / workshop 提供资料与待回答问题。
- 会后尽快交付，具体时间服从承诺和核验需要；先确认内容可分享、链接可访问。归档里写“已决定”之前核实确实有人作了决定。
- 保存实际展示和实际发出的版本；旧版本需避免误用时，在产物内部加过期提示。
- 活文档的事实更新要同步其派生表示；已发出的历史版本保留，另附更正，不无差别改写历史。
- 记录目标有没有达成、反馈来自谁、什么因素影响结果。场次记录留在该场文档或 LOG，本文不维护场次进度。
- 新经验进入通用规则前写清适用条件。尚未验证的做法标为建议，不记作发生过的成功经验。

### 案例库：解释来源，不代替本场判断

- **2026-08-28 内部技术 demo**：材料充分仍被评为“这是后面的事”。可迁移的教训是先确认当前交付任务，不是以后禁止 roadmap。

# 下半部：动手流程

## 9. 片子怎么做（需要 HTML 时从附录 A 起手）

1. 从 §0 简报和台本骨架提取主张、每段用途、必要证据与收束，不固定页数或幕数。
2. 每页先写结论 / 问题，再选择图、截图、比较、流程或短文字；图表数值连接同一证据来源。
3. 用附录 A 时，把页面保存成 `slides.html`，替换示例内容、页面标题和语言，给每页稳定的 `id`。
4. 个人默认风格可沿用；组件不够用就按内容调整，不为了模板把所有叙事压进矩阵。
5. 要自动核对数值时，按附录 E 标记引用位置并配置来源；未标记的数值必须人工核验。
6. 用稳定页名对齐台本。重新排序后核对转场和图示，不把序号当唯一身份。
7. 数词检查只是提醒；实际看一遍小字、拥挤、长标题和远端画面。检查 HTML 刷新后定位、打印 / 导出分页和所有要发出的文件。
8. 交付前把示例文案和占位内容全部替换；保留仅用于问答的参考页，但主讲流程不要误入。

## 10. Demo 怎么做

### 10a. 现场版

1. 写清每拍的目的与证据边界：能力展示、完整任务、机制解释或对比，选一种主线。
2. 实跑环境与权限；选可验证、能稳定展示的路径，优先隔离演示数据和资源。
3. 记录输入、版本、条件、输出与选例原因；对比时注明控制变量，非对比时按任务顺序组织。
4. 跑完保存证据，核查它确实支持主张。没有跑通就缩小主张、换形式或明确缺口。
5. 写 runbook：稳定步骤名 → 入口 / ID → 操作 → 预期画面 → 失败处理。台本只引用步骤名。
6. 制作独立可用的兜底，标明来源和执行状态；完整走一遍切换。
7. 冻结本场输入和材料；演前只核对入口、版本与显示，不依赖列表行号不变。

### 10b. 录播版

1. 每段写一个目的和观众必须看到的结果；决定画面用产品、图解还是终端。
2. 写旁白、屏幕动作、段尾停留和信息边界。关键数字与计划、片子采用同一来源。
3. 需要自动化时配置附录 E；运行 `--check`，处理实际失败，不能通过吞异常取得通过。
4. 冷启动走一次路径，确认可重录；正式录制时按段捕获，保留必要状态说明。
5. 回看片子、音频、字幕、通知与敏感内容；如果证据变了，重录受影响片段并同步兜底。
6. 准备本地静态备份。发审阅人时说明希望他确认什么、何时需要答复，核对最终文件。

## 11. 台本怎么写（从附录 C 起手）

1. 写开场、各段目的和收束，按 §0 的目标选结构。
2. 填自然口语；需要精确表达的句子逐字写，其他用要点。
3. 标画面页名 / runbook 步骤名、停顿和转场，不复制操作表。
4. 在台本维护尖锐问题的口头答法，链接计划里的证据；轻量版可直接合在同一文件。
5. 写短版和裁剪顺序，保护本场结果所需的内容，不预设 demo 不能删。
6. 出声计时，修绕口和超时；内容变化后重新确认相关段落。
7. 定稿后核对页面、步骤、数字、边界与问答一致，准备一份真正方便现场看的备注。

## 附录 E · 检查与捕获骨架 `run_demo.sh`

只用 Python 标准库。保存后用 `bash run_demo.sh --check`、`bash run_demo.sh --capture` 或 `bash run_demo.sh 1`。
所有相对路径以脚本所在目录为基准。先把 `CONFIG` 替换成自己的配置；占位配置会拒绝运行。

**检查契约：**

- `fields` 明确列出要比对的 JSON 顶层字段，包括输入身份、版本与关键结果。缺失、null、类型变化或值变化都失败；不声称比较未登记字段。
- `metrics` 是需要核验的上屏引用，映射到产物字段及 Python 格式串。片子和计划引用均写成
  `<span data-metric="total">132</span>`；Markdown 中使用同一原始 HTML 写法，标记内只放值，不嵌套标签。
- `documents` 对每份材料列出本应出现的引用 ID。逐份核对每次标记的值，必需引用缺失、额外或未知 ID 都失败。
  **普通文字、图中数字、截图、旁白、视频和没有标记的数字不在自动检查范围内**，必须人工核对，或由同一来源生成。
- `BUDGET` 是正文与参考页预算的唯一配置点。为防中文被计成零，按 Unicode 中日韩字符逐字加其他语言词计数；这不是语言学分词或阅读时间估计。
  页面必须使用非嵌套的 `<section class="slide">`；检查空 deck、空页面与逐页预算。检查不证明最终画面可读。
- 每拍需配置具体允许退出码与输出标记；超时、意外退出码、缺标记、空输出均失败。没有“忽略所有失败”。
- `--capture` 先完成检查，再执行各拍；输出保存在新目录，不覆盖旧证据。全部成功才生成 `COMPLETE.json`；失败目录不可当成可用兜底。
  捕获保留 stdout/stderr 原文，不静默滤行。命令须在隔离环境运行，并只输出本场允许保存的内容；脚本不是脱敏器或系统沙箱。
- 重算命令中的 `{output}` 会替换成独立临时目录里的路径，其他参数原样传递。它必须向该路径输出 JSON，不写回权威产物。

        {"path": "slides.html", "metrics": ["total"], "slides": True},
        {"path": "plan.md", "metrics": ["total"], "slides": False},
    ],
    "beats": {"1": {"argv": ["<command>"], "codes": [0], "marker": "<result marker>"}},
    "timeout_seconds": 120,
}
BUDGET = {"main": 50, "backup": 80}  # 本场可调整；预算仅提示内容密度。


def require(ok, message):
    if not ok:
        raise ValueError(message)


def execute(argv):
    return subprocess.run(argv, capture_output=True, timeout=CONFIG["timeout_seconds"], check=False)


def typed_equal(a, b):
    if type(a) is not type(b):
        return False
    if isinstance(a, dict):
        return a.keys() == b.keys() and all(typed_equal(a[k], b[k]) for k in a)
    if isinstance(a, list):
        return len(a) == len(b) and all(typed_equal(x, y) for x, y in zip(a, b))
    return a == b


class Material(HTMLParser):
    # 支持模板的平面 slide section 与纯文本 metric span；不猜复杂页面的可见性。
    def __init__(self):
        super().__init__(convert_charrefs=True)
        self.metrics = []
        self.metric = None
        self.pages = []
        self.page = None
        self.hidden = None

    def handle_starttag(self, tag, attrs):
        attrs = dict(attrs)
        require(self.metric is None, "metric 内不可嵌套标签")
        if tag in ("script", "style"):
            self.hidden = tag
        if tag == "section":
            require(self.page is None, "slide 内不可嵌套 section")
            classes = attrs.get("class", "").split()
            if "slide" in classes:
                self.page = {"backup": "backup" in classes, "text": []}
        if "data-metric" in attrs:
            require(tag == "span" and bool(attrs["data-metric"]), "metric 必须是具名 span")
            self.metric = [attrs["data-metric"], []]

    def handle_endtag(self, tag):
        if self.metric is not None:
            require(tag == "span", "metric 结束标签错误")
            self.metrics.append((self.metric[0], "".join(self.metric[1]).strip()))
            self.metric = None
        if tag == self.hidden:
            self.hidden = None
        if tag == "section" and self.page is not None:
            self.pages.append(self.page)
            self.page = None

    def handle_data(self, data):
        if self.hidden is not None:
            return
        if self.metric is not None:
            self.metric[1].append(data)
        if self.page is not None:
            self.page["text"].append(data)

    def finish(self):
        self.close()
        require(self.metric is None and self.page is None, "未闭合的 metric 或 slide")


def content_units(text):
    # Unicode 名称覆盖汉字（含扩展区）、假名和韩文，避免中文计零。
    cjk = lambda ch: unicodedata.name(ch, "").startswith(("CJK", "HIRAGANA", "KATAKANA", "HANGUL", "IDEOGRAPHIC"))
    count = sum(cjk(ch) for ch in text)
    rest = "".join(" " if cjk(ch) else ch for ch in text)
    return count + len(re.findall(r"[^\W_]+(?:[',.%/§-][^\W_]+)*", rest, flags=re.UNICODE))


def check():
    fields, metrics, docs = CONFIG["fields"], CONFIG["metrics"], CONFIG["documents"]
    require(bool(fields) and bool(metrics) and bool(docs), "检查范围不能为空")
    require(any(d["slides"] for d in docs), "未登记 deck")
    used = {name for d in docs for name in d["metrics"]}
    require(used == set(metrics), "引用配置含未知 ID 或未使用的指标")
    require(all(s["field"] in fields for s in metrics.values()), "引用字段必须参加重算比对")
    require(any("{output}" in arg for arg in CONFIG["recompute"]), "重算命令缺少 {output}")
    kept = json.loads(Path(CONFIG["kept"]).read_text(encoding="utf-8"))
    with tempfile.TemporaryDirectory(prefix="presentation-check-") as tmp:
        output = str(Path(tmp) / "fresh.json")
        argv = [arg.replace("{output}", output) for arg in CONFIG["recompute"]]
        result = execute(argv)
        if result.returncode != 0:
            sys.stderr.write(result.stderr.decode("utf-8", errors="replace"))
            raise ValueError(f"重算失败，退出码 {result.returncode}")
        fresh = json.loads(Path(output).read_text(encoding="utf-8"))
    require(isinstance(kept, dict) and isinstance(fresh, dict), "产物必须是 JSON 对象")
    for field in fields:
        require(field in kept and field in fresh, f"缺字段: {field}")
        require(kept[field] is not None and fresh[field] is not None, f"空字段: {field}")
        require(typed_equal(kept[field], fresh[field]), f"重算不一致: {field}")
    expected = {name: format(kept[spec["field"]], spec["format"]) for name, spec in metrics.items()}
    for doc in docs:
        material = Material()
        material.feed(Path(doc["path"]).read_text(encoding="utf-8"))
        material.finish()
        required = set(doc["metrics"])
        found = {name for name, _ in material.metrics}
        require(found == required, f"{doc['path']}: 引用 ID 缺失或多余")
        for name, value in material.metrics:
            require(name in expected and value == expected[name], f"{doc['path']}: 引用不一致 {name}")
        if doc["slides"]:
            require(bool(material.pages), f"{doc['path']}: 没有 slide，拒绝空过")
            for n, page in enumerate(material.pages, 1):
                text = " ".join(page["text"]).strip()
                units = content_units(text)
                limit = BUDGET["backup" if page["backup"] else "main"]
                require(units > 0, f"第 {n} 页为空")
                require(units <= limit, f"第 {n} 页 {units} 单位超过预算 {limit}")
                print(f"slide {n}: {units}/{limit}")
    print(f"CHECK PASS: {len(fields)} fields, {len(docs)} documents; marked citations and text budgets only")


def beat(name, folder=None):
    spec = CONFIG["beats"][name]
    require(bool(spec["codes"]) and bool(spec["marker"].strip()), f"{name}: 缺退出码或结果标记")
    result = execute(spec["argv"])
    stdout = result.stdout.decode("utf-8")
    stderr = result.stderr.decode("utf-8")
    if folder is not None:
        (folder / f"beat{name}.stdout.txt").write_text(stdout, encoding="utf-8")
        (folder / f"beat{name}.stderr.txt").write_text(stderr, encoding="utf-8")
    else:
        print(stdout, end="")
        print(stderr, end="", file=sys.stderr)
    require(result.returncode in spec["codes"], f"{name}: 意外退出码 {result.returncode}")
    require(bool(stdout.strip()) and spec["marker"] in stdout, f"{name}: 空输出或缺结果标记")
    return {"beat": name, "exit_code": result.returncode}


def main():
    require("<" not in json.dumps(CONFIG), "请先替换 CONFIG 占位配置")
    require(len(sys.argv) == 2, "用法: --check | --capture | 拍号")
    mode = sys.argv[1]
    if mode == "--check":
        check()
    elif mode == "--capture":
        check()
        require(bool(CONFIG["beats"]), "没有要捕获的拍")
        root = Path("captures")
        root.mkdir(exist_ok=True)
        folder = Path(tempfile.mkdtemp(prefix="capture-", dir=root))
        print(f"捕获目录（全部完成前不可用）: {folder}", flush=True)
        completed = [beat(name, folder) for name in CONFIG["beats"]]
        (folder / "COMPLETE.json").write_text(json.dumps(completed, ensure_ascii=False, indent=2), encoding="utf-8")
        print(f"CAPTURE COMPLETE: {folder}")
    else:
        require(mode in CONFIG["beats"], "未知拍号")
        beat(mode)


if __name__ == "__main__":
    try:
        main()
    except (OSError, ValueError, KeyError, TypeError, subprocess.TimeoutExpired) as exc:
        print(f"FAILED: {exc}", file=sys.stderr)
        raise SystemExit(1)
