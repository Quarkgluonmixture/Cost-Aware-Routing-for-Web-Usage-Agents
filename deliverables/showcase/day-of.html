板前怎么讲

顺着印出来的海报从上往下讲，边说边指。海报上写 DOM / SoM / Vision，展板电脑和中间那条写 READ / BOTH / LOOK，讲到中间那条时对应一次就够。

90 秒走读

①
指标题条

A web agent can look at a page — a screenshot — read it as text, or both. The richer the view, the more each step costs. The question is when that's worth paying for.

②
指中间 THE SAME TASK, SEEN TWO WAYS（task 76）

One task, two ways: change the price of my bike listing. Reading the page text — that's DOM on the poster — the agent finishes in twelve steps. With screenshots only — Vision — it loops back to the same form and gives up after twenty-six. Same start, and both outcomes repeat on a rerun.

③
一口气扫过面板 1–4

Across eight website-and-model settings, no single view wins everywhere, and the views don't solve the same tasks. They behave differently — with only the screenshot, the agent scrolls far more — and on the VisualWebArena settings they fail differently: the text-only views fail in ways you can name; the views with the screenshot just never get there.

④
指面板 5 SO BUILD A ROUTER? NOT SO FAST.

So build something that picks the view per task? Every learned choice here gains success only by spending more. The shaded corner — cheaper and no worse than always using the cheapest view — gets no learned choice in any of the eight settings; even perfect hindsight gets there in only one.

⑤
指面板 6 AND THIS IS WHY

Here's why. An example of which view was right only exists when the task gets solved, and these agents solve two to thirty-six percent of tasks. The more there is to gain from choosing, the fewer examples there are to learn from.

⑥
指展板电脑

On the laptop: three recorded tasks in all three views — or type your own and watch it run live. Nothing there is scored; every number on the poster comes from recorded runs.

按 Run 之前：

First step in about twenty seconds.

只有 20 秒时（① ④ ⑤ 合成一句）

Web agents can look, read, or both, and richer views cost more. Picking per task would pay in hindsight — but nothing we trained beats always using the cheapest view on both success and cost, because the examples to learn from only exist when the agent already succeeds.

海报说过头的地方，嘴上这样讲

海报已经印好改不了。左边是纸上写的，中间别说，右边照着说。

纸上别说这样说
面板 4 蓝色那组 IMAGE-ONLY"image-only""the views with the screenshot"：这组是 Vision 和 SoM，SoM 也带文字标注
面板 4 图注 image-only toward stalled progress把「卡住」当成结论"nothing stands out — they fail there the way they fail everywhere"；这个规律来自 VWA 的 6 个设置
面板 3 图注 Vision scrolls ~4× more"four times more in every setting""the medians are four to five times apart, and Vision scrolls most in every one of the eight"
面板 5 横轴 −0.1 … 0.6把刻度读成美元或百分比"to the right is more expensive"：这条轴是成本比的对数
面板 5–6 的 oracle、routing labels、pp这些内部用词"perfect hindsight" · "examples of which view was right" · "more tasks in a hundred"
面板 2 韦恩图（三种纯文本看法）"each view solves tasks no other view does""they overlap but don't coincide"：纯文本这几种各自独有的题数在重跑噪声以内
聊天里提到 +16和「重跑一次能多解几道」放在一起比"up to sixteen more tasks in a hundred, in hindsight, with five extra views"；公平的比较只有一个设置：多加一种看法 +7.14，重跑一次 +4.46 到 +7.59

板前最可能被问的四个

「0 of 8 是不是训练数据太少？」

We tested that. More data pushes the learner toward perfect hindsight — and perfect hindsight itself reaches the win region in one of eight. More data can't cross a line hindsight doesn't cross. The failing settings would need at least two to four times more tasks.

「always-cheapest 是每道题选，还是固定？」

Fixed. The one view that costs least on average in that setting, used for every task.

「+16 是真系统做到的吗？」

No — that's perfect hindsight, an upper bound. What a learned choice actually reached is panel five: none in the win region.

「那做产品的今天该怎么办？」

On these benchmarks, always using the cheapest view is hard to beat on both counts. Pick one view for your task mix. A learned per-task choice isn't there yet — improve the agent first, collect reliable examples, then learn when to look.

其余问答与每个数字的口径：SHOWCASE_PREP.md §4 / §5，不能说的话：§6。答不上来就直说，并告诉对方用什么数据能查到。

演讲怎么讲

开讲前 5 分钟（14:40，在讲台）MacBook

十页流程

粗体是必须照原话说的句子（核心主张、边界、请求），其余照意思说。页面按 id 称呼。

页面这页讲什么手上要说准的句子
opening为什么值得听：看网页有三种方式，价钱不同，这是量出来的说完按 →"When is expensive perception worth paying for? … Let me show you one task first."
demo同一道题、三种看法、三种账单；learned choice 恰好选了唯一失败的那栏。说清这是录制的回放先讲三栏是什么；点一下 iframe 空白处；只按 →，共 10 下；到底再按 → 自动翻页。⛔ 不按空格、不按 1/2/3/4"Same task, three ways of seeing it, three different bills." "One recorded run per view — nothing on this screen is live." "A learned choice, trained without this task, picked READ. The one view that failed."（停一下）
question提出本场问题，预告四步；收尾时回答它念四个路标时从左到右指"If you build a web agent, that's the question: should it look, read, or both — and can it learn to choose?"
behaviour① 看法一换，agent 做的事就换：只给截图时翻页约占 30% 的步数，其余看法约 6%，打字少一半→边界：不说「每个设置都是四倍」
failure② 失败方式也不同：纯文本看法输在能点名的原因上，带截图的看法没有突出的原因→"This pattern comes from the six VisualWebArena settings." 不拿两组互比，不说「因为」
hindsight③ 事后选对，每个设置都往右移 3.5 到 16；但要对着重跑读→"But hindsight flatters. In the one setting where we reran every view, adding a second view bought about seven tasks in a hundred — and simply rerunning the same view bought four and a half to seven and a half."
learned④ 学不会：学到的选择 0 of 8，事后最优也只有 1 of 8，所以问题主要不在分类器「only one of eight」后停一下，不翻页"Zero of eight learned choices land there. And even perfect hindsight reaches it in only one of eight."
why例子只在做对时才有：成功率 2–36%，每个设置 15–97 个可用例子，6 个里只有 2 个够训练→y 轴是数量，不说 percent
not-yet边界 + 三个请求看向做 agent 的人；说完停一下"So I'm not claiming routing is unlearnable — just not yet, at these success rates." "Three asks. Come to the board and type a task … tell me which view you use … lend us a stronger agent."
close回答 question 页→"Look, read, or both? It depends on the task — and nothing we trained knows it yet." "Come and find me at the board. Thank you."
reference备用：39 秒录屏，不在主讲流程里R 打开；→ 回到 close—

短版（约 6 分钟）

opening → demo（只讲 LOOK 和 READ）→ question → behaviour → failure → learned（末尾加一句「例子只在做对时才有」）→ not-yet → close。

什么时候用：10 分钟含问答，或者主持人提醒时间不够。

超时就按这个顺序砍

① question 只念问题，不念路标 → ② why 并进 learned 末尾一句 → ③ hindsight 只留「每行都往右移」和「但事后看会夸大」→ ④ demo 里 BOTH 一句带过。

被打断：一句话答完，接 "— so, same task, three views, three bills." 回到主线。

完整台词：talk/rehearsal-script.md（v2）。⛔ 台上不调试，⛔ 永远不说 "it worked this morning"。
