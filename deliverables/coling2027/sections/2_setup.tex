\section{Setup}\label{sec:setup}

\paragraph{Sites and tasks.} We use three sites of VisualWebArena \citep{koh2024visualwebarena}: classifieds (224 scored tasks), reddit (203) and shopping (432). We add the reddit site of WebArena \citep{zhou2024webarena} (104 tasks: the 106 minus the two unachievable tasks, whose reference answer is ``N/A''). VWA-reddit and WA-reddit are different task sets on the same application, so they are not two independent benchmarks. Scored sets are the collected tasks minus protocol exclusions written as rules over task configuration and, for one reddit task, over agent trajectories (Appendix~\ref{app:universe}).

\paragraph{Backbones and cells.} B0 = Qwen3-VL-235B (API-served), B1 = Qwen3-VL-4B and B2 = Gemma-3-4B (both served locally), and B5 = GPT-5.6 (API, classifieds only) \citep{bai2025qwen3vl,gemma2025gemma3,openai2026gpt56}. A \emph{cell} is one site $\times$ backbone pair. The eight core cells, each run in every observation mode, are VWA-classifieds and VWA-reddit $\times$ \{B0, B1, B2\}, plus WA-reddit $\times$ \{B0, B1\}. B5-classifieds and the two shopping cells extend them (\S\ref{sec:screenshot}, \S\ref{sec:routing}) and are never pooled with the eight.

\paragraph{Observation modes.} The deployment question has three answers (Figure~\ref{fig:system}): \textbf{DOM} (the page's accessibility tree as text), \textbf{Vision} (the raw screenshot, with an empty text payload) and \textbf{\SoM} (a set-of-marks screenshot plus the list of marked elements as text; \citealp{yang2023som}). Three further modes carry no screenshot and serve only for comparison; the one used throughout is \textbf{\PSoM}, which is \SoM\ with the screenshot removed. Marks and prompt are the same, so \SoM$-$\PSoM\ isolates the image (Appendix~\ref{app:modes} lists all six). ``Text'' modes withhold the \emph{page} screenshot only: a reference image that is part of the task (``find this item'') is given in every mode.

\paragraph{One plain agent.} One model call per step emits a thought, an action and its arguments; the prompt holds the instruction, the mode's system prompt, the last eight steps and the current observation. There is no planner, memory, reflection or retry policy, so conditions differ in the observation and in how actions reach the browser. Lacking element ids, Vision clicks by coordinates, and such clicks succeed less often in this harness than element-id clicks. Decoding is greedy, the viewport is 1280$\times$720, and the text observation covers only the current viewport and is never truncated. The nominal budget is 30 steps, but a parser defect let some extra actions through, mostly for GPT-5.6 (Appendix~\ref{app:harness}). Appendix~\ref{app:contract} gives the full contract.

\paragraph{Reruns.} We reran identical conditions, 27 registered same-condition pairs in all. In three cells (VWA-classifieds B0, VWA-reddit B0 and WA-reddit B1), every mode was run twice. A rerun uses the same tasks and code on freshly reset sites, so it exposes what one run of the agent does not determine. In our data a rerun changes between 0 and 14\% of outcomes, depending on mode and cell (Appendix~\ref{app:sixarm}). Sites are reset before every run; within a run only classifieds resets between tasks, so reddit and shopping carry state from earlier episodes (Appendix~\ref{app:harness}).

\paragraph{Scoring and cost.} The evaluators are binary. Results come from the first run of each condition unless stated otherwise, and intervals on differences between modes are 95\% paired task-bootstrap intervals. Cost is per episode, in US cents: the API charge for B0 and B5, and for B1 and B2 a token-priced proxy for local serving. The proxy charges hardware amortisation plus electricity per input and output token (per-cell values in Table~\ref{tab:cells}). Costs are compared within a cell and never pooled across cells. \S\ref{sec:routing} repeats the routing analysis under GPU-time and wall-clock cost.
