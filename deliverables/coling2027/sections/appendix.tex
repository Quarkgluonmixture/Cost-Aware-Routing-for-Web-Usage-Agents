\section{Task universes and exclusions}\label{app:universe}

Scored sets are the collected tasks minus protocol exclusions written as rules over task configuration: classifieds 224 of 224; VWA-reddit 203 of 205 (one task whose evaluator never checks the requested action, and one cross-site task answerable from memory); shopping 432 of 435. For every site the collected tasks are the benchmark's tasks minus those it marks as not applicable (WebArena-reddit: 104 of 106). Every analysis records the task set it was built on and fails if denominators differ.

\section{Agent and run contract}\label{app:contract}

Every condition uses the same agent loop and settings; only the observation mode and backbone vary. Decoding is greedy (temperature 0, at most 4096 new tokens per step). The browser viewport is 1280$\times$720, and the page is observed 0.5\,s after each action. The prompt holds the task instruction, the mode's system prompt, the last eight steps (thought, action, result) and the current observation; the text observation (accessibility tree or marked-element list) is never truncated. The nominal step budget is 30; three consecutive unparsable outputs end an episode. B1 (Qwen3-VL-4B-Instruct) and B2 (Gemma-3-4B-it) run locally from pinned model revisions; B0 (Qwen3-VL-235B-A22B) and B5 (the mid-price GPT-5.6 tier) are reached through a hosted API under a fixed model identifier. Each run uses seed 42, starts from freshly reset sites, and records the code version, configuration and environment with every episode. The exact prompts and configuration files are in the supplementary material.

\section{The six observation modes}\label{app:modes}

Four modes carry no page screenshot and cross two factors: the text payload (the accessibility tree, or the flattened list of set-of-marks elements) and the prompt family (DOM or SoM). DOM is tree + DOM prompt; P-prompt is tree + SoM prompt; P-text is marks + DOM prompt; \PSoM\ is marks + SoM prompt. \SoM\ adds the annotated screenshot to \PSoM; Vision is the raw screenshot with an empty text payload. A task's own reference image, when it has one, is given in every mode.

\section{The intent rule}\label{app:rule}

A task is flagged if its intent matches
\begin{flushleft}\footnotesize
\verb!\b(image|picture|photo|screenshot)\b|!\\
\verb!\bcolou?r of\b|!\\
\verb!\bhow many\b[^.]{0,40}\bin (?:the|this)\b!

(case-insensitive) and the task carries no reference image. It flags 71 of 224 classifieds tasks, 63 of 203 VWA-reddit tasks, 56 of 432 shopping tasks and 5 of 104 WebArena-reddit tasks. It was written while auditing reddit failures; classifieds is out-of-sample.

\section{Harness defects and how cells were filtered}\label{app:harness}

\begin{itemize}\setlength{\itemsep}{1pt}
  \item \textbf{GPT-5.6 Vision}: the run used a broken coordinate contract and is excluded.
  \item \textbf{GPT-5.6 step budget}: when the model emitted several valid actions, the parser executed one but booked the step as a free wait. Summed over a whole condition GPT-5.6 had 50--90 such steps (1.2--2.4\% of its steps; most of them executed an action, and some episodes reached 31--32 counted steps), B2 had 2--24, and B0 and B1 none. It affects \SoM\ and \PSoM\ alike.
  \item \textbf{Reddit state}: subscriptions persist across the episodes of a run. Of the reddit successes scored by the subscribed-forum list, six were credited although the episode never visited the target forum, three of them for B2 with DOM; \S\ref{sec:deploy} reports the B2 comparison with and without them. The audit cannot detect an episode that reaches an already-subscribed forum and leaves without acting (one such case is confirmed on WebArena-reddit).
  \item \textbf{Shopping search box}: typing into a search box that already holds a query submitted old + new text (``chair'' + ``chair with wheels'' $\to$ ``chairchair with wheels'') in 43\% of such submissions, far more often in text modes than in Vision. A detector reproducing the defect's per-mode counts marks affected episodes; the \emph{clean} shopping cells drop every task affected in any mode (B0 keeps 368 of 432 tasks, B1 192).
  \item \textbf{Shopping state}: the category grid order differs between runs (42 order-sensitive tasks dropped), and the wishlist is not reset between tasks (4 tasks dropped).
\end{itemize}

\section{Estimators}\label{app:estimators}

\paragraph{Frontier.} For a cell with arms $m$ of mean cost $c_m$ and success rate $s_m$, $F(c)$ is the upper concave envelope of $\{(c_m, s_m)\}$, cut at the highest-success arm (constant beyond it) and equal to the cheapest arm's success below the cheapest cost. Every point of $F$ is reached by sending a random share of tasks to each of two arms. A policy with mean cost $c$ and success $s$ has excess $s - F(c)$.

\paragraph{Router curves.} Features are standardised within each training fold and fed to an L2-regularised logistic regression ($C=1$); predictions are out-of-fold over five folds of distinct tasks. \emph{Per-arm heads}: for each threshold $\tau \in \{0, 0.05, \dots, 1\}$ a task goes to the cheapest arm (by training-fold mean cost) whose predicted success is at least $\tau$, and to the training fold's best arm if none is. \emph{Triage}: one model predicts whether any arm solves the task; for each quantile $q \in \{0, 0.05, \dots, 1\}$ of its score, tasks below the quantile go to the cheapest arm and the rest to the best arm.

\paragraph{Pooled gain.} Within a cell, cost is normalised as $u = (c - c_{\min})/(c_{\max} - c_{\min})$ over the fixed arms, which makes cells with different cost units comparable without pooling their costs. The gain at $u$ is the envelope of the fixed arms together with the curve's points minus the envelope of the fixed arms alone, on 101 grid points; the pooled curve is the equal-weight mean over cells and its statistic is the maximum over $u$. The null permutes each task's outcomes and costs against its features and refits the whole curve ($B=1000$; $p=(k+1)/(B+1)$; for the pooled statistic each null draw is averaged over cells before the maximum).

\paragraph{Deployable policy.} In each outer fold the threshold (or quantile) is the one with the largest excess over the \emph{training} tasks' own frontier, using in-sample predictions on those tasks; it is then applied to the held-out fold. The five folds' decisions form one policy over all tasks, scored against the full-sample frontier. Intervals resample tasks and rerun the whole pipeline ($B=1000$, 5th and 95th percentiles); pooled intervals average the cells draw by draw.

\paragraph{No-interaction null and decision study.} For the task $\times$ mode $\times$ run array with $r=2$ runs, the two-way random-effects ANOVA gives $\hat\sigma^2_{\text{err}} = \mathrm{MS}_{\text{err}}$ and $\hat\sigma^2_{\text{int}} = (\mathrm{MS}_{\text{int}} - \mathrm{MS}_{\text{err}})/r$. The null matrices are drawn with curveball trades over the task-by-(mode, run) 0/1 matrix, which preserve every row and column total (four chains, each with 50 trades per row of burn-in and 5 per row between kept draws, 2000 draws in all; for the six-mode analysis a second sampler with four-fold thinning checks mixing). The reliability of a label averaged over $k$ runs is $\hat\sigma^2_{\text{int}}/(\hat\sigma^2_{\text{int}} + \hat\sigma^2_{\text{err}}/k)$, and the runs needed for 0.5 are $\lceil \hat\sigma^2_{\text{err}}/\hat\sigma^2_{\text{int}} \rceil$.
