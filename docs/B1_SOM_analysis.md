# B1 Baseline SoM模式失败原因手动归类（Classifieds）

分类维度：**SoM表征结构性缺陷** vs **模型能力问题** vs **DOM/SoM共性问题**
后续用途：B1 baseline 原始数据，Phase 1/2/3 对比参照基准，不在 baseline 中修复。

---

## 一、SoM 表征结构性缺陷

> SoM 模式特有的、换更强模型也难以完全规避的表征层问题。

### 1.1 SoM 标注遮挡关键视觉区域

- 青色 mark 框（#00BCD4）直接覆盖在缩略图左上角，遮住关键视觉区域
- 7600 条 listing 的 gallery 视图中，每张缩略图本身就很小（~200×170px），加上 mark 后更难准确感知颜色、车型等视觉特征
- 标注色统一为青色，在包含颜色描述的任务中存在标注色与目标颜色混淆的风险（如将红色 Toyota 86 误判为"白色车"）

### 1.2 SoM marks 丢失空间布局信息

- SoM marks 列表是线性的（纯序号），模型无法从中恢复 2D grid 位置关系
- 列表页的多列布局在 mark 列表中退化为一维序列，空间推理能力丧失

### 1.3 深度滚动场景的 element ID 幻觉

- SoM 模式在深度滚动场景下，viewport 外元素不可见，模型可能引用不存在的 element ID
- 这是该表征模式的已知成本

### 1.4 文字捷径强化 text-over-vision bias

- SoM marks 文字标签直接给出了商品标题等信息，相当于给了模型"捷径"——不需要看图就能获取信息
- 70px 缩略图的视觉信号权重远低于 SoM marks 的文字标签权重
- 结果：模型系统性忽略视觉细节（颜色、图片内容），主要依赖 [SOM_MARKS] 文本索引进行决策

*Finding: 在 4B VLM 上，SoM 标注截图未能有效引导模型利用视觉信息。这与大模型（GPT-4V）上 SoM 的有效性形成对比，暗示 SoM 表征对模型视觉能力有最低门槛要求。*

## 二、模型能力问题

> 属于模型推理/策略局限，脚手架层面无法修复。

### 2.1 搜索策略失效

- 搜索词泛化：模型使用过于宽泛或直接搬用任务描述文本作为搜索词
- 搜索关键词失效后无法切换其他定位方式，陷入重复搜索循环
- 未使用过滤器，依赖关键词搜索遍历

### 2.2 视觉 grounding 能力不足

- 任务说 "guitar in the red case" → 模型仅做 token-level 关键词匹配（"guitar" ≈ "Guitar Rig"），找到含 "guitar" 的 listing title 即认定为目标
- 完全没有用视觉去看缩略图确认视觉属性（如"是否是红色琴盒里的吉他"）
- 列表页缩略图尺寸小（约 100×100px），4B 模型很难从缩略图里可靠识别细粒度视觉特征
- 真正需要的能力是：扫描所有缩略图 → 找出视觉匹配的那个 → 关联 listing

*这是模型能力问题，非脚手架缺陷——恰好说明 SoM 模式对于需要细粒度视觉 grounding 的任务，4B 模型仍然力不从心。*

### 2.3 推理与判断错误

- 仅凭当前单条结果价格高/低，直接认定为全站最贵/最便宜/最新（缺乏翻页或全局比较意识）
- 看到第一页少数结果就给出计数答案，未翻页确认
- 误判价格是否处于区间内（数值比较错误）
- 商品价格等信息提取错误（从标签文本中抽取数值出错）

### 2.4 执行终止判断错误

- 未点进详情页就调用 finish（对 url_match 类任务影响有限，对 program_html 类任务直接失败）
- 历史记忆不足导致循环：缺乏已访问 item 记录，重复对列表第一个结果进行操作

## 三、DOM/SoM 共性问题

> DOM 和 SoM 模式共享的结构性限制。

### 3.1 视觉信息结构性不可达

- Classifieds 站点的商品描述文本不进入 AXTree，导致 DOM 和 SoM 条件均无法读取嵌入描述中的数值型答案
- Vision 条件理论上可通过截图读取，但受模型能力限制

### 3.2 过滤器 UI 可操作性不足

- 进入过滤器页后无法定位价格输入框
- 只能输入价格下限或上限，无法进行组合搜索
- 过滤条件 UI 在 DOM/SoM marks 中结构混乱，导致操作失败

*与"模型不知道用过滤器"区分：这里是知道要用但做不到*
