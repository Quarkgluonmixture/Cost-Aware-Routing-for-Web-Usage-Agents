# B1 Baseline DOM模式失败原因手动归类（Classifieds）

分类维度：**脚手架/DOM结构性缺陷** vs **模型能力问题**
后续用途：B1 baseline 原始数据，Phase 1/2/3 对比参照基准，不在 baseline 中修复。

---

## 一、脚手架 / DOM结构性缺陷

> 即使换更强的模型，在 DOM-only 模式下也难以解决的问题。

### 1.1 动态 UI 后 element_id 失效（下拉/弹窗）

每步刷新 accessibility tree 是正确机制，失败来自两个子类型：

- **子类型 A（模型行为）**：点击下拉后，模型用上一步推断出的旧 element_id 操作，而非读取新 AT 里的真实 ID → 操作无效。
- **子类型 B（AT 表达力）**：下拉展开后 listbox/option 层级复杂，模型无法在新 AT 中识别正确的可点击节点。

*对应修复路径：Phase 3 M1（select fallback）；Phase 1 SoM on 可缓解（坐标交互不依赖 element_id）*

### 1.2 视觉信息结构性不可达

- 缺乏颜色/图片认知：任务要求匹配参考图中的视觉属性（颜色、款式、图片内容），DOM 中不含图片语义，结构性无法完成。
- 无法选中颜色筛选器/类别选择框：相关 UI 控件在 accessibility tree 中不可操作或未暴露。

*对应修复路径：Phase 1 A1（SoM/hybrid 观测模式）*

### 1.3 过滤器 UI 可操作性不足

- 进入过滤器页后无法定位价格输入框
- 只能输入价格下限或上限，无法进行组合搜索
- 过滤条件 UI 在 DOM 中结构混乱，导致操作失败

*与"模型不知道用过滤器"区分：这里是知道要用但做不到*

## 二、模型能力问题

> 属于模型推理/策略局限，脚手架层面无法修复。

### 2.1 搜索策略失效

- 搜索关键词失效后无法切换其他定位方式，陷入重复搜索循环
- 搜索范围过广时出现无关商品，模型持续搜索相同/类似词而不收敛
- 未使用过滤器，依赖关键词搜索遍历，导致无法确认目标（知道过滤器存在但没用）
- 误将任务描述文本（"最贵的物品"、"exact item name"、价格区间描述）或过于具体的词直接作为搜索词
- 应该填入城市名称而非大洲名称

### 2.2 推理与判断错误

- 仅凭当前单条结果价格高/低，直接认定为全站最贵/最便宜/最新（缺乏翻页或全局比较意识）
- 误判价格是否处于 a 和 b 之间（数值比较错误）
- 商品价格等信息提取错误（从 DOM 文本中抽取数值出错）

### 2.3 执行终止判断错误

- 未点进详情页就调用 finish（对 url_match 类任务影响有限，对 program_html 类任务直接失败）
- 历史记忆不足导致循环：缺乏已访问 item 记录，重复对列表第一个结果进行操作

### 2.4 从不 scroll up

69/69 次 scroll 操作全部向下（dy>0），0 次向上。当目标元素被滚过（y<0，在 viewport 上方）时，agent 无法回滚定位，导致：
- 反复 click viewport 外的元素（如 task_18 step 6-8，element_bbox y=-54）
- 继续向下滚动寻找已经滚过的内容

已在 prompt 中添加 scroll 方向说明（`dy>0 scrolls DOWN, dy<0 scrolls UP`），但 task 27/28（加载了新 prompt 后运行）仍然没有出现 scroll up 行为，表明 **prompt hint 对 4B 模型的 scroll up 行为改善有限**，属于模型能力局限。
