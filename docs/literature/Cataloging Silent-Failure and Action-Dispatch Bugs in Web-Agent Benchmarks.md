# Cataloging Silent-Failure and Action-Dispatch Bugs in Web-Agent Benchmarks

## Executive Summary

The empirical evaluation of multimodal Large Language Models (LLMs) and autonomous web-usage agents relies fundamentally on standardized benchmark frameworks. These digital environments serve to translate probabilistic agent action generations into deterministic browser operations. However, a critical systemic vulnerability persists within the execution pipelines of these standard evaluations: the widespread prevalence of silent-failure and action-dispatch bugs. In these scenarios, an agent formulates and issues a syntactically valid and semantically correct action, the framework attempts execution, and the action fails to induce a state change in the page geometry or Document Object Model (DOM). Critically, the runner records an unsuccessful action flag without raising a programmatic exception or providing trajectory-level feedback to the agent. The failure is entirely "silent," corrupting the execution trace and misrepresenting the agent's actual reasoning capabilities.

This comprehensive research report systematically maps the entire landscape of known silent-failure vulnerabilities across the foundational web-agent benchmark family, encompassing frameworks such as WebArena, VisualWebArena (VWA), BrowserGym, Mind2Web, SeeAct, and OSWorld. The analysis reveals that silent failures are not sporadic edge cases or minor anomalies. Rather, they are systemic architectural artifacts arising from the fundamental impedance mismatch between semantic accessibility trees (AXTree) and pixel-coordinate rendering geometries. The cataloging effort identifies dozens of documented vulnerabilities, which can be synthesized into a precise taxonomy of execution failures that plague contemporary evaluation protocols.

The most profound and academically impactful revelation from this synthesis is the differential bias these bugs exert across various agent representation modalities. Agents relying purely on DOM or AXTree representations encounter these bugs at drastically different rates compared to Set-of-Mark (SoM) or pure vision-based agents. Specifically, algorithmic execution paths relying on bounding box center calculations—such as the `union_bound` geometric center dispatch utilized in VisualWebArena—disproportionately penalize DOM-centric agents. When an AXTree node corresponds to a multi-line inline element or a structural parent container, the geometric center calculation frequently resolves to whitespace or non-interactive background elements. This causes the navigation to fail silently while unfairly depressing the agent's success rate metric. Current evidence suggests that this architectural flaw can skew cross-mode success rate comparisons by factors ranging from 1.5× to 6.5×, heavily contaminating comparative claims in recent literature.

The top three most pervasive and paper-impactful bug categories identified in this analysis include:

1. **Coordinate Dispatch and Bounding Box Anomalies**: Geometric center calculations that fail spectacularly on non-rectangular, multi-line, or structurally occluded elements.
2. **AXTree-DOM Structural Mismatches**: Discrepancies where elements are semantically actionable in the accessibility tree but visually occluded or intercepted by overlapping overlays in the rendered DOM.
3. **Native UI and OS-Level Interruptions**: Execution failures occurring when interacting with native browser components (such as `<select>` dropdowns) that escape the synthetic pointer event context of automation tools like Playwright.

Current literature from the 2024 to 2026 period exhibits an increasing, though fragmented, awareness of these infrastructural limitations. Advanced environments and recent research are beginning to implement post-action verification loops, completeness verifiers, and custom execution bypasses to filter out environmental noise. However, the exact quantification of differential bias across agent modes remains a significant gap in foundational benchmark papers.

The subsequent sections of this report provide an exhaustive per-benchmark catalog of these bugs, a forensic review of developer operational logs, an analysis of adjacent automation literature spanning decades of UI testing, a synthesized taxonomy with recommended audit techniques, and strategic positioning recommendations for empirical research addressing these systemic flaws.

## The Landscape of Silent-Failure Vulnerabilities Across Web-Agent Benchmarks

The foundational benchmarks utilized for evaluating web agents frequently rely on translating semantic intentions into programmatic browser interactions. A detailed catalog of documented bugs, limitations, and methodological critiques reveals a pattern of silent execution failures across almost all major frameworks. The reliance on geometric mapping and coordinate arithmetic is a primary locus of these failures.

For instance, the VisualWebArena source code explicitly extracts the bounding box (`union_bound`) of an identified element and calculates its center coordinate to execute a `page.mouse.click(x, y)` command via Playwright. If the targeted element is a parent container (such as a `<li class="listing-card">` containing multiple nested text nodes and images) or a multi-line `<a>` tag, the mathematical geometric center frequently falls precisely in the structural padding or line gaps between child elements. Consequently, the `document.elementFromPoint` resolution performed natively by the browser engine targets the parent container or the background canvas rather than the interactive hyperlink. The framework registers the action as executed, the runner continues its loop, but the page state remains static. VisualWebArena's foundational paper explicitly acknowledges that bounding boxes are "unreliable" for precise evaluation , yet the framework preserves this exact mechanism for action execution.

Furthermore, benchmarks like AgentBench and WebSuite have consistently reported high variance in execution success rates that cannot be solely attributed to the cognitive reasoning capabilities of the tested models. In VisualWebArena, human participants achieve an 88.7% success rate, whereas early vision-language models struggled to surpass 16.4%. While a portion of this gap is due to reasoning deficits, a statistically significant portion of these failures stems directly from action translation mechanics.

The mechanisms underlying these bugs expose a significant vulnerability in cross-modal comparisons. When an agent represents the page as a pure DOM tree, it formulates actions targeting semantic nodes. The automation framework must then translate that semantic node into a two-dimensional physical coordinate to dispatch the interaction. This translation relies on the browser's bounding box calculation—the smallest rectangle encompassing all parts of the element. However, bounding boxes are geometric simplifications. If an element is non-rectangular, such as an `<a>` tag that wraps around an image or drops to a second line of text, the bounding box spans the empty space between the lines.

When the `get_element_center()` function calculates the mathematical middle of this box, the coordinate often falls on empty background pixels. The browser's native hit-testing algorithm interprets a click at this empty coordinate as an interaction with the parent `<div>` or the document body. The runner detects no errors because a click was successfully dispatched to a valid coordinate, but the agent's intended navigation silently fails.

Conversely, Set-of-Mark (SoM) agents operate under a fundamentally different execution paradigm. In SoM, the framework visually injects bounding box markers or numerical tags directly over the rendered interactive elements *before* the screenshot is taken. The agent then selects the numerical tag. Frameworks often handle SoM action execution by mapping the tag directly to the underlying DOM node and executing a JavaScript `.click()` or a precise `page.locator("[bid=N]").click()` , thereby bypassing the brittle coordinate math entirely. This architectural discrepancy explains why DOM-based agents experience drastically higher silent failure rates (by observed margins of 1.5× to 6.5×) compared to SoM agents, artificially suppressing their measured capabilities in comparative studies.

## Forensic Analysis of Developer Discourse and Operational Logs

Beyond formally published academic literature, the raw source code repositories of these benchmark frameworks contain extensive operational logs documenting silent failures. An analysis of issue trackers, pull requests, and developer discussions provides precise, highly technical insights into the mechanics of actionability failures and the philosophies governing benchmark maintenance.

The `ServiceNow/BrowserGym` repository presents some of the most detailed and forensic accounts of pointer interception and execution failures. In Issue #201, developers investigated a critical scenario where an agent targeted a specific AXTree combobox (element `a1033`) during a WorkArena filtering task. The action executor verified the element, confirming it was visible, enabled, and stable, and successfully scrolled it into view. However, the detailed execution logs revealed that the pointer event was consistently intercepted by an overlapping element (an `<a>` tag with the identifier `bid="a1034"`). The framework retried the click action multiple times before ultimately timing out.

Critically, the maintainers evaluated this execution trace and determined it was *not a bug*, but rather an "inherent difficulty" of the benchmark. They suggested that the agent must learn to utilize a screenshot-coordinate workaround to bypass the interception. This administrative decision explicitly confirms a testing paradigm where structural mismatches between the semantic AXTree and visual CSS layouts are intentionally left unresolved in the environment. Agents utilizing strictly semantic targeting are structurally guaranteed to encounter silent failures in these scenarios, as the framework offloads the burden of overcoming overlapping z-index geometries onto the agent's visual learning capabilities.

A more profound and structurally unsolvable limitation is documented in BrowserGym Issue #375. This issue details the phenomenon where native HTML `<select>` dropdowns render their option lists as OS-level popups rather than standard DOM elements. When a web agent dispatches a `mouse_click()` to the coordinates of an opened dropdown option, the synthetic mouse event generated by Playwright cannot breach the native window component context. The event is "silently swallowed," resulting in the dropdown opening on the initial click, but the subsequent option selection failing entirely without generating an error trace.

## Historical Context: Architectural Insights from Adjacent Web Automation Literature

The profound challenges observed in modern web-agent benchmarks are not historically novel phenomena; rather, they represent a recurrence of fundamental issues long documented in the browser automation, accessibility, and UI testing ecosystems. Software engineering frameworks such as Selenium, Cypress, and Playwright have spent decades engineering robust workarounds for the unreliability of coordinate-based interaction and structural DOM mismatches. Analyzing this adjacent literature provides the critical theoretical foundation necessary to understand why web-agent benchmarks fail so silently.

### Playwright Actionability Mechanisms and Synthetic Events

Playwright's execution model relies on a highly structured "Actionability Matrix" to guarantee that an element can receive an interaction before dispatching a synthetic event. Before a standard `locator.click()` command is executed, Playwright auto-waits for the target element to pass five distinct programmatic checks: the element must be Visible, Stable, Enabled, Editable (if applicable to the input type), and crucially, it must "Receive Events".

The "Receives Events" check is the primary locus of silent failures in autonomous agent environments. Playwright verifies this requirement by computing the intended action point (typically the geometric center of the element's bounding box) and executing a hit-target detection test, which operates equivalently to the native JavaScript `document.elementFromPoint(x, y)` function. If another element—such as a sticky navigation header, a transparent tracking overlay, an intercepting wrapper `div`, or a CSS pseudo-element—captures the pointer event at those specific coordinates, Playwright determines that the target element is not receiving events. Under standard software testing protocols, Playwright will wait dynamically for the obstruction to clear until a global timeout is reached, at which point it raises a formal `TimeoutError`.

However, in web-agent evaluation environments, these timeouts are frequently caught by the benchmark's execution wrapper logic. To prevent a single testing script from crashing an entire evaluation loop containing hundreds of agent trajectories, the wrapper catches the exception, sets the agent's observation variable `action_success=False`, and returns the unchanged page state. The agent remains entirely unaware that an invisible overlay caused the failure, creating the classic silent failure signature. Furthermore, benchmarks often bypass these safeguards entirely by utilizing raw `page.mouse.click(x, y)` commands combined with rudimentary bounding box arithmetic (as seen directly in VisualWebArena's execution loop). This intentionally circumvents Playwright's locator stability checks, injecting actions directly into the coordinate void regardless of the underlying DOM state.

Additionally, Playwright utilizes the Chrome DevTools Protocol (CDP) to inject synthetic pointer events. While highly reliable for standard DOM nodes, synthetic events fundamentally differ from trusted native OS events. This architectural distinction is precisely why native `<select>` dropdowns fail. When a `<select>` opens, the browser delegates the rendering of the option list to the host operating system's window manager. The OS-level popup exists completely outside the CDP's purview; thus, synthetic coordinate clicks pass harmlessly through the popup, hitting whatever DOM element lies beneath it, completely unrecorded.

### W3C ARIA Accessibility Tree Semantics

A profound structural factor contributing to AXTree-DOM mapping mismatches lies in the W3C specifications governing the Accessibility Tree. Web-agent benchmarks frequently feed models a parsed version of the AXTree to provide semantic understanding without the overwhelming noise of raw HTML. However, the ARIA (Accessible Rich Internet Applications) documentation explicitly dictates how bounding boxes, parent-child relationships, and visibility are calculated for accessibility APIs, creating significant divergences from visual rendering.

According to W3C guidelines, elements assigned specific semantic roles (e.g., `role="presentation"` or `role="none"`) act as purely decorative layers. The specification mandates that these elements are either excluded from the accessibility tree entirely or strip their children of independent semantic meaning. For example, a complex interactive SVG graphic, a stylized multi-layered button, or an element utilizing the `use-element` shadow tree might be collapsed into a single actionable node in the AXTree to simplify screen reader navigation.

When an autonomous web agent parses the AXTree observation, it perceives a single, unified interactive node. It mathematically formulates an action to click that node. However, the browser's DOM rendering engine still respects the complex visual geometry of the underlying hidden child elements. If an agent calculates the bounding box of the semantic parent and dispatches a coordinate click to its center, that geometric center might fall upon a purely decorative gap, an unclickable CSS padding zone, or a nested text node masked by an `overflow: hidden` property. The Accessibility Object Model (AOM) explainer documentation explicitly notes the immense technical difficulty of introspecting a computed accessibility tree and mapping it reliably back to standard DOM coordinates for automated programmatic interactions.

### The Line-Gap Anomaly and `document.elementFromPoint`

The most insidious manifestation of coordinate failure involves inline DOM elements, specifically hyperlinks (`<a>` tags) or styled `<span>` tags that wrap across multiple lines of text. The browser rendering engine calculates the bounding box of a wrapped inline element as a single continuous rectangle encompassing the minimum $x$ and $y$ coordinates of the first line of text and the maximum $x$ and $y$ coordinates of the final line of text.

If a hyperlink spans from the end of line one to the beginning of line two, its bounding box forms a massive rectangle that covers the text, the whitespace between the lines, and potentially unrelated text caught in the rectangular intersection. If the benchmark framework's math forces a click at the absolute center of this bounding box—calculating $x_{center} = \frac{x_{min} + x_{max}}{2}$ and $y_{center} = \frac{y_{min} + y_{max}}{2}$ —the coordinate almost inevitably targets the whitespace line-gap. Consequently, the browser's `document.elementFromPoint` resolution evaluates the empty whitespace, resolving to the parent paragraph `<p>` or the foundational page `<body>`. The click event fires perfectly at the mathematical center, but the semantic target is entirely missed. This mathematical phenomenon is the direct root cause of the §106 bug.

## Methodological Responses in Recent Web-Agent Evaluations (2024–2026)

The escalation of silent failures has prompted significant methodological shifts in the most recent generations of web-agent research. Empirical evidence from literature spanning 2024 to 2026 indicates that benchmark unreliability is no longer viewed as negligible edge-case noise, but rather as a systemic architectural flaw requiring explicit, complex mitigation layers built directly into the evaluation harnesses.

### Post-Action Verification and Execution Tooling

Recent frameworks have introduced specialized auxiliary agents and robust algorithmic verification loops dedicated solely to ensuring execution reliability. The OSWorld benchmark (Xie et al., 2024), which serves as a highly complex multimodal agent environment spanning web and desktop applications, implements extensive execution-based evaluation protocols. Rather than relying on simple state tracking, OSWorld utilizes 134 unique custom execution functions to verify state mutations directly against the operating system or application backend, ensuring that an agent's action truly impacted the environment rather than trusting the browser's superficial DOM state.

To combat execution stagnation and the hallucination loops caused by silent failures, sophisticated orchestration architectures like Agentic Lybic have deployed continuous feedback-driven quality assessment via explicit Finite-State Machines (FSM). Agentic Lybic routes logic between predefined controller situations such as `REPLAN` and leverages rigorous error recovery protocols that proactively detect execution anomalies and force the agent to adapt its strategy.

Furthermore, methodologies evaluating complex environments introduce mandatory post-action validation tooling. As detailed in recent literature analyzing OSWorld, advanced agent systems employ a "Loop Breaker Agent" designed to analyze trajectory histories and detect repeated, identical behaviors that indicate execution stagnation (a direct and primary symptom of silent failures). Concurrently, a "Completeness Verifier" module cross-examines the management agent's completion claims against verifiable UI-observable evidence, often using secondary vision models to ensure pixel-level changes occurred. This dual-module approach effectively forces the agent to bypass buggy execution paths by recognizing when an action fails to mutate the state, forcing a replanning sequence and preventing the agent from being penalized by framework-induced silent failures.

### Trajectory Validation vs. Outcome Scoring

Recognizing the brittleness of outcome-based scoring in the presence of framework bugs, recent literature increasingly advocates for trajectory-level matching as a superior evaluation metric. HAL's comprehensive infrastructure analysis (Kapoor et al., 2026) provides concrete empirical evidence that environment state drift and screenshot capture unreliability inherently corrupt live GUI evaluations. To mitigate this, benchmarks are beginning to evaluate the syntax, logical correctness, and semantic intent of the agent's chosen action sequence, rather than solely measuring the final binary execution outcome.

This methodology is evident in frameworks like AgentBench and Voyager, which evaluate action execution by requiring models to generate executable Bash commands or Python code, validating the logical construction of the command independent of its downstream execution success in a brittle sandbox. If an agent operating in a web framework issues a semantically correct command to click the geometric center of an element, trajectory-level scoring models grant partial or full credit, acknowledging that the underlying automation framework's coordinate math caused the silent misfire, not the agent's reasoning deficit.

Despite the deployment of these advanced orchestration layers, the fundamental acknowledgment of differential bias across agent representations remains glaringly sparse in contemporary literature. While OSWorld and WebArena track aggregate human-to-AI performance extensively , the specific penalization rates for pure DOM-based agents versus SoM-injected agents in the presence of coordinate mapping bugs are rarely isolated or quantified in foundational benchmark papers.

## Synthesized Taxonomy of Action Execution Vulnerabilities and Recommended Audits

Based on the synthesis of source code execution paths, GitHub operational trace logs, adjacent automation literature, and the methodological modifications observed in recent benchmarks, the silent-failure vulnerabilities in web-agent environments can be categorized into a comprehensive, highly structured taxonomy. This theoretical framework is crucial for researchers aiming to anticipate undocumented bug variants, standardize audit methodologies, and design robust evaluation protocols.

### 1. Coordinate Dispatch and Bounding Box Anomalies

- **Definition**: Failures originating fundamentally from the translation of an element's semantic identity (its AXTree node or HTML tag) into a two-dimensional geometric interaction point. This occurs primarily because rendering engines and accessibility APIs define spatial boundaries differently.
- **Representative Bugs**: The VisualWebArena `union_bound` geometric center calculation (`get_element_center()`) mathematically missing multi-line inline elements or structural parent containers, precisely as documented in the user's §106 bug.
- **Audit Technique**: Cross-reference the agent's requested element bounding box with the direct output of a synthetic `document.elementFromPoint(x, y)` call executed at the calculated coordinates prior to dispatch. If the returned DOM element does not match the intended semantic element ID, flag the instance as a dispatch anomaly.
- **Known Fixes**: Frameworks must inject custom JavaScript to compute the first rendered DOM rect of an element (`element.getClientRects()`) instead of aggregating the union bounding box, mathematically guaranteeing the generated coordinate falls on rendered pixels.

### 2. AXTree-DOM Structural Mapping Mismatches

- **Definition**: Scenarios where elements exist as semantically actionable nodes within the parsed Accessibility Tree but are visually occluded, sized to zero pixels, or physically intercepted by overlapping structural elements in the rendered DOM hierarchy.
- **Representative Bugs**: The BrowserGym Issue #201 scenario, where a targeted AXTree combobox was perfectly valid semantically, but the physical click was intercepted by a sibling `<a>` tag serving as a decorative visual wrapper with a higher z-index.
- **Audit Technique**: Prior to event dispatch, dynamically query the DOM for z-index layering and opacity at the target coordinate. Utilize Playwright's native `receives events` actionability check; if the check fails but the element exists unequivocally in the AXTree, an occlusion mismatch is occurring.
- **Known Fixes**: Utilizing direct DOM locators (e.g., `page.locator().click()`) with Playwright's `force: true` flag to explicitly override interception checks, or utilizing JavaScript `element.click()` injection to trigger the event listener while bypassing visual geometry calculations entirely.

### 3. Native UI and Out-of-Context OS Interruptions

- **Definition**: Interaction attempts with OS-level components or browser-native elements that successfully escape the automation framework's synthetic pointer boundaries, resulting in events being swallowed by the host operating system.
- **Representative Bugs**: BrowserGym Issue #375, where native HTML `<select>` dropdown popups silently swallow Playwright's `mouse_click()` events because the synthetic pointer cannot breach the OS-level window context.
- **Audit Technique**: Monitor action target tag names continuously during execution. If an action targets a `<select>`, `<input type="file">`, or a native calendar date-picker, trigger an immediate logging alert for potential context escape.
- **Known Fixes**: Implement custom bypass functions (such as the proposed `select_option_at()`) that programmatically update the element's internal value property and dispatch a native `change` event, rather than simulating physical mouse clicks.

### 4. Evaluator State Drift and False Negatives

- **Definition**: The benchmark framework's internal state-tracking mechanisms desynchronize from the actual dynamic page state. The evaluator fails to register valid actions due to backend tracking collisions or latency, generating false negatives.
- **Representative Bugs**: Dictionary key collisions in state-change trackers (as documented in the user's §105 bug), or high-fidelity environment delays where rapid agent actions outpace DOM stabilization, causing tracking lags as seen in WebArena.
- **Audit Technique**: If the framework records `action_success=False` but a subsequent full-page screenshot diff or HTML structural delta calculation indicates a significant mutation occurred, suspect evaluator state drift immediately.
- **Known Fixes**: Implementing robust DOM stabilization wait protocols (such as Playwright's Network Idle metrics) prior to state validation, and utilizing post-action completeness verifiers powered by vision models, as pioneered in OSWorld.

### 5. Actionability Check Masking and Timeout Swallowing

- **Definition**: The agent interacts with an element during a transient, non-actionable state (e.g., an element animating, or a button disabled pending network validation). The automation framework's internal timeout triggers but is caught and masked by the benchmark runner.
- **Representative Bugs**: WebVoyager's execution timeout masking, where an agent repeatedly targets an unready element until the `max_iter` loop exhausts ; Playwright timeout exceptions being caught by broad `try/except` blocks in the wrapper logic.
- **Audit Technique**: Ensure that automation framework warning logs are exposed directly to the test output console. Any occurrence of a `TimeoutError` in the backend execution trace should explicitly flag the trajectory as encountering an environment error rather than silently returning `action_success=False` to the agent.

## Strategic Recommendations for Academic Positioning

The exhaustive cataloging of execution vulnerabilities establishes a highly robust theoretical foundation for positioning empirical observations regarding the visual-web-agent routing ecosystem. Contextualizing specific framework patches within this broader literature ensures that academic claims of novelty are both highly defensible and rigorously scoped.

The identification of the `§105 swatch radio dict-key collision` and the `§106 click dispatch via union_bound geometric center` fits precisely within established taxonomical categories. The §106 bug is a canonical **Type 1 Coordinate Dispatch Anomaly**, echoing the profound structural mathematical flaws inherently present in bridging AOM semantics with pixel rendering. The §105 bug aligns directly with **Type 4 Evaluator State Drift**.

When drafting the analytical claims for the present research on cost-aware routing and cross-mode success rate (SR) comparisons, the following strategic positioning is highly recommended:

### Defensible Claims of High Novelty

- **Quantifying Differential Mode Impact**: The analysis clearly indicates that existing literature (such as the WebSuite descriptive critique and the BrowserGym issue discussions) identifies that coordinate clicks fail , and the original VisualWebArena paper concedes bounding boxes are "unreliable". However, the existing academic corpus *does not* systematically quantify how these specific execution bugs create a differential bias across varied agent representations. Claiming to be the first to systematically audit and empirically quantify the statistical penalization of pure DOM-based agents versus Set-of-Mark (SoM) agents—specifically highlighting the observed 1.5×–6.5× variance in success rates—is highly defensible and represents a significant methodological contribution to the field.
- **Isolating Infrastructure Noise from Agent Capability**: By mathematically applying the §105 and §106 bug fixes and executing a rigorous, controlled re-run of the benchmarks, the research effectively isolates true algorithmic reasoning deficits from infrastructural execution noise. This contribution directly answers the urgent calls in recent literature—most notably the HAL infrastructure analyses  and the methodological shifts seen in OSWorld —for vastly more stable execution environments. It proves that a significant portion of what the community previously categorized as agent hallucination or reasoning failure was, in fact, mechanical framework collapse.

### Claims to Avoid (Overreach)

- **Discovery of Silent Failures**: It is imperative to strictly avoid claiming the foundational discovery of silent action failures within automated browsers. As documented extensively in this report, UI testing tools like Playwright and Selenium have mapped point-receives-events failure modes for over a decade. Furthermore, recent papers like WebSuite have extensively detailed symptomatic benchmark brittleness, and BrowserGym maintainers have openly discussed intercepted clicks as known environmental difficulties.
- **Discovery of `union_bound` Unreliability**: The VisualWebArena authors explicitly acknowledged in their foundational ACL 2024 text that bounding box measurements are inherently unreliable for strict evaluation. The novelty of the present research lies not in discovering that the core math is flawed, but in proving mathematically *why* it fails specifically on multi-line elements, proving exactly *how* it contaminates cross-mode SR comparisons across different LLM modalities, and providing the precise architectural patch required to stabilize the evaluation protocol moving forward.

By grounding the experimental patches within the extensive, multi-decade history of W3C ARIA specifications, Playwright actionability matrices, and documented GitHub execution traces, the research seamlessly bridges the critical gap between software engineering infrastructure and the theoretical evaluation of artificial intelligence capabilities. This rigorous contextualization ensures the findings command high credibility and direct relevance to the future design of multimodal agent benchmarks.
