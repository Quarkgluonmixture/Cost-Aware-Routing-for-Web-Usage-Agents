## Framing claims worth carrying
- Two Pareto fronts: universal-native (pixels → mouse/keyboard: coverage, slow/expensive/brittle) vs semantic-first (AX/API → semantic action → vision when insufficient: fast/stable/verifiable, incomplete coverage).
- Vision's cost is not the screenshot: it is that every GUI state transition waits for expensive model cognition, more serial turns, more verification/recovery; AX's value is lower perception/grounding entropy, execution robustness, and cheap ($0-LLM) verification.
- AX is not automatically cheap (Browser Use fixed toolset ~6,600 tokens vs CU ~4,500; raw AX trees can be tens of thousands of tokens; Citrix `get_app_state` ~5 s) ⇒ a router must read AX coverage/latency/freshness/consistency, not just availability.
- Proposed experiment: A vision-always · B AX-always · C AX+vision-always · D AX → heuristic vision fallback · E cost-aware learned router; log per-step AX/screenshot ms, tokens, prefill/decode ms, turns, retries, modality conflicts.
- Stated gap: no public system has a per-step learned interface router minimising cost + λ·latency + μ·failure subject to success ≥ τ; current systems use visual-predicate triggers (Gemini), model self-selection (Stagehand/Codex/Claude), or task-class heuristics (Skyvern).
