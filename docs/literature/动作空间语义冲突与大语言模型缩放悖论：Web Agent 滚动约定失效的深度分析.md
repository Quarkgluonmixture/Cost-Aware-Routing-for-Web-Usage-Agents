# 动作空间语义冲突与大语言模型缩放悖论：Web Agent 滚动约定失效的深度分析

在通往通用人工智能（AGI）的演进路径中，赋予大语言模型（LLM）和视觉-语言模型（VLM）在数字环境中自主感知、推理和执行动作的能力，已成为当前学术界和工业界的核心研究焦点。这些被称为 Web Agent 或 GUI Agent 的自主智能体，被设计用于在复杂的浏览器DOM树、操作系统界面以及三维虚拟世界中执行长视距任务。然而，在实际部署和基准测试中，一个看似极为基础的机械操作——页面滚动（Scroll），却暴露出当前最前沿的基础模型在指令遵循、动作空间定义以及预训练数据对齐方面存在着深层的架构脆弱性。

这一脆弱性的核心在于“大模型 action 格式约定冲突”。具体而言，在数字世界中，垂直滚动动作（通常在代码中被定义为 `deltaY` 或 `dy`）的数学符号约定在不同的操作系统、Web 标准和 UI 框架中处于极度分裂的状态。当一个 LLM 被提示词（Prompt）要求生成一个滚动动作时，它面临着严重的语义碰撞。更为严峻的是，随着模型参数规模的指数级增长，这一问题并未如“缩放定律（Scaling Laws）”所预期的那样得到缓解，反而陷入了被称为“缩放悖论（Scaling Paradox）”的陷阱：越大的模型在特定场景下的指令遵循能力越差，其庞大的预训练先验（Training Priors）会强行覆写开发者在提示词中定义的动作格式规则。

本报告将进行详尽而深度的剖析，首先从技术底层拆解 CSS、JavaScript 与 Windows/macOS 之间关于 `deltaY` 正负号的多约定竞争机制，进而从理论层面深入探讨“缩放悖论”与“控制幻觉（Control Illusion）”的内在机理，随后详细审查这一冲突在 VisualWebArena、WebVoyager、SeeAct 等主流 Web Agent 社区中的具体失败模式及 SoM（Set-of-Mark）回退策略，最后以 235B 规模的 Qwen3-VL 及 Lumine 等前沿通用智能体为例，探讨动作空间的语义重构方案。

## 技术根因：多平台滚动约定的历史与语义割裂

要理解为何拥有数千亿参数的最先进 VLM 会在“向上滚动”还是“向下滚动”这样一个简单的二元决策上发生灾难性失败，必须首先追溯滚动轮（Scroll Wheel）在计算机科学史上的软硬件交互演进。在数字空间中，垂直滚动并没有一个统一的、基于物理直觉的绝对数学公理；相反，它是由底层平台 API、前端渲染引擎和自动化测试框架各自为政的约定所主导的。当 Web Agent 输出诸如 `scroll(deltaX, deltaY)` 的动作向量时，一个正整数或负整数的实际执行效果完全取决于底层的解析环境。这种技术生态的碎片化，直接导致了 LLM 预训练语料库中存在巨大的逻辑噪声。

### W3C 标准与 CSS/JavaScript 的视口逻辑

在 Web 浏览器的上下文中，用户交互行为主要由万维网联盟（W3C）的 UI 事件规范（UI Events Specification）进行标准化。W3C 定义了 `WheelEvent` 接口，该接口继承自 `MouseEvent` 和 `UIEvent`，专门用于捕获鼠标滚轮或触控板的物理移动 。在 W3C 的标准体系中，`deltaY` 属性代表了垂直方向上的滚动量 。

Web 开发的坐标系原点 (0, 0) 默认位于文档的左上角。因此，在文档中向“下”移动意味着 Y 坐标值的增加。基于这一几何逻辑，JavaScript 和 CSS 形成了一个占据统治地位的约定：`deltaY` 为正值（> 0）表示向下滚动 。这里的“向下”是指视口（Viewport）在文档流中向下移动，从用户的视觉感受来看，页面上的内容实际上是在向上滑动。此外，W3C 规范进一步指出，具体的物理测量单位由 `WheelEvent.deltaMode` 属性决定，它可以是像素（`DOM_DELTA_PIXEL`）、行（`DOM_DELTA_LINE`）或页（`DOM_DELTA_PAGE`）。由于诸如 Mind2Web 和 WebVoyager 这样的 Web Agent 频繁地与 DOM 树交互，或通过注入 JavaScript 脚本来直接驱动页面元素，它们在设计动作空间时，往往不可避免地继承了这种“正值为下”的语义 。

### Win32 API 与机械滚轮的物理隐喻

与 Web 领域的视口坐标逻辑截然不同，微软的 Windows 操作系统在底层处理鼠标滚动时，采用了基于机械滚轮物理旋转方向的隐喻。在 Win32 API 中，当用户旋转鼠标滚轮时，拥有焦点的窗口会接收到 `WM_MOUSEWHEEL` 消息 。

在 Win32 的消息结构中，滚动的方向和距离被编码在 `wParam` 参数的高位字（high-order word）中 。Windows 的核心约定是：正值表示滚轮向前旋转（远离用户），而负值表示滚轮向后旋转（朝向用户）。在传统的桌面软件交互中，将鼠标滚轮向前推通常意味着将文档向上拉回（即滚动到文档的顶部）。因此，在 Win32 的语境下，`delta > 0` 意味着“向上滚动”。这种滚动的基准增量被定义为常量 `WHEEL_DELTA`，其默认值为 120，开发者通常需要通过系统宏 `GET_WHEEL_DELTA_WPARAM` 来提取并处理这些正负值，以实现诸如文本编辑器中一次滚动三行的功能 。

### macOS 的自然滚动与动态反转

苹果的 macOS 系统通过其独特的 `NSEvent` 架构引入了第三个维度的复杂性。在现代的 macOS 开发中，触控板和鼠标的滚动事件通过 `scrollingDeltaY` 和 `deltaY` 属性来传递 。然而，苹果引入了“自然滚动（Natural Scrolling）”的系统级偏好设置，这使得数学符号的语义变得动态且不可预测。

在自然滚动开启的情况下（现代 macOS 的默认设置），用户的物理手势模拟了直接推拉物理纸张的动作。在触控板上双指向上滑动会将内容向上推，这在视觉上等同于视口向下移动。为了在底层事件流中实现这一点，macOS 引入了 `NSEvent.isDirectionInvertedFromDevice` 属性 。当该属性为 `true` 时，操作系统会在底层自动对硬件传来的 `deltaY` 原始值进行数学符号反转（乘以 -1）。这意味着即使在同一个操作系统上，同一个方向的物理手势，由于用户偏好的不同，传递给应用程序代码的 `deltaY` 符号也可能是完全相反的 。

### 自动化框架与预训练语料的污染

Web Agent 不仅在逻辑上需要处理这些底层的分歧，在执行层，它们通常依赖于 Selenium、Puppeteer 或 Playwright 等浏览器自动化测试工具 。这些框架为了屏蔽操作系统的差异，通常会在自身的方法（如 `scrollByAmount(deltaX, deltaY)`）中强制执行一种约定。例如，在 Selenium 的 Python 绑定中，传递正的 `deltaY` 会导致向右和向下滚动，负值则代表向左和向上 。

| **技术栈 / 操作系统**  | **核心 API 或事件接口**  | **deltaY > 0 的语义映射** | **deltaY < 0 的语义映射** |
| ---------------------- | ------------------------ | ------------------------- | ------------------------- |
| **W3C / Web (JS/CSS)** | `WheelEvent.deltaY`      | 向下滚动（视口下移）      | 向上滚动（视口上移）      |
| **Windows (Win32)**    | `WM_MOUSEWHEEL`          | 向上滚动（滚轮向前）      | 向下滚动（滚轮向后）      |
| **macOS (传统模式)**   | `NSEvent.deltaY`         | 向上滚动                  | 向下滚动                  |
| **macOS (自然滚动)**   | `NSEvent` (反转属性开启) | 向下滚动                  | 向上滚动                  |
| **Selenium (Python)**  | `scrollByAmount(x, y)`   | 向下滚动                  | 向上滚动                  |

这种深刻的技术割裂，对大语言模型的预训练造成了毁灭性的数据污染（Data Contamination）。LLM 在其数万亿 Token 的预训练语料中，吸收了海量的 GitHub 开源代码、Stack Overflow 讨论、MDN 文档以及微软 MSDN 教程 。在模型的超高维潜在空间（Latent Space）中，`deltaY` 这个词元（Token）与“向上”和“向下”的关联呈现出一种复杂的双峰统计分布（Bimodal Statistical Distribution）。当开发者在构建 Web Agent 时，如果仅仅在系统提示词（System Prompt）中简单地规定“使用正的 `delta_y` 来向下滚动”，模型必须能够在使用指令时强烈地压制其内部庞大且自相矛盾的预训练先验。正如后续章节所分析的那样，随着模型参数的指数级放大，这种压制能力反而会发生崩溃。

## 缩放悖论（Scaling Paradox）：模型规模扩张导致的指令遵循失效

在主流的 AI 发展叙事中，“缩放定律（Scaling Laws）”一直是不可动摇的黄金法则，即随着计算量（Compute）、数据量（Data）和模型参数（Parameters）的同步增加，模型的性能和泛化能力将实现可预测的单调提升 。然而，当将 LLM 部署为需要执行严格格式指令的智能体（如输出特定 JSON 格式的 action）时，研究人员观察到了令人反直觉的“缩放悖论”：在特定的高保真或严格约束场景下，越大参数规模的模型，其指令遵循与格式合规性（Format Compliance）表现得越差。

### 知识覆写（Knowledge Overwriting）与语义容量

这一悖论的微观力学机制在研究论文《When Less is More: The LLM Scaling Paradox in Context Compression》（Guo 等人，2026）中得到了详尽的剖析 。该研究在压缩器-解码器（compressor-decoder）的架构下对 0.6B 到 90B 参数规模的模型进行了广泛实验，揭示了“规模-保真度悖论（Size-Fidelity Paradox）”。研究表明，虽然大模型在损失函数（Training Loss）上表现更好，生成了更为流畅的文本，但它们在忠实地保留源上下文（Source Context）方面的能力却随着规模的扩大而下降 。

这一退化的核心驱动力被称为“知识覆写（Knowledge Overwriting）”。随着模型参数规模向数百亿、千亿级别迈进，模型获得了极度膨胀的“语义容量（Semantic Capacity）”。在数学表征上，这种语义容量的增加体现为上下文嵌入（Context Embeddings）的有效秩（Effective Rank）显著上升 。在较小的模型（如 0.6B 或 4B）中，由于表征空间有限，嵌入必须坍缩到一个低秩流形（Low-rank Manifold）中，这迫使小模型紧紧抓住提示词中给定的具体指令或源事实。

相反，巨型模型高秩的表征空间促使信息分散在极其广阔的语义空间中，这为“先验知识入侵（Prior Knowledge Intrusion）”打开了方便之门 。回到 Web Agent 的滚动场景，当系统提示词要求模型输出 `{"action": "scroll", "deltaY": 200}` 以表示向下滚动时，大模型在处理 `deltaY` 时，其庞大的语义容量激活了预训练语料中深植的 Win32 API 记忆或某个流行的 C++ UI 框架的习惯。大模型“认为”正值代表向上是更具统计显著性的常识，于是它用自身的参数化信念（Parametric Beliefs）强行篡改了开发者在提示词中给定的局部事实，产生出方向完全相反的动作数值 。

### 生成不确定性与语义偏移（Semantic Drift）

除了知识覆写，缩放悖论的另一个关键表现形式是“语义偏移（Semantic Drift）”。论文指出，随着模型规模的扩大，其在词元预测分布上的条件熵（Conditional Entropy）变得更低，这意味着大模型在生成内容时表现出了过高的自信（Generative Certainty）。

在需要严格遵守格式约定的 Agent 任务中，这种过度自信是致命的。大模型倾向于按照自己的语言习惯对内容进行重构和意译（Paraphrase），而不是一字不差地复现（Verbatim Reproduction）严格的 API 格式 。例如，即使系统提示词严格规定动作必须写成 `scroll(delta_x, delta_y)`，遭遇语义偏移的大模型可能会由于对任务意图的“过度理解”，擅自将格式改写为 `pan(direction: "down", pixels: 200)`，或者在原本要求严格的 JSON 结构外包裹不必要的思维链（Chain of Thought）解释，从而直接导致下游执行框架的解析器（Parser）崩溃。

### 其他失效模式的放大

这种规模带来的反噬并不仅限于格式遵守。相关研究进一步指出，大语言模型在推理时还表现出诸如“阿谀奉承（Sycophancy）”（放弃正确的逻辑以迎合用户的错误暗示）、“盲目确定性（Premature Certainty）”以及“逻辑跳跃”等病态行为 。正如在因果判断测试（CausalT3 诊断集）中所观察到的，GPT-5.2 在某些严格逻辑任务上的表现甚至大幅落后于参数规模更小的 GPT-4-Turbo，其核心原因并非模型缺乏知识，而是陷入了基于规模的“瘫痪”和对模糊性的误判 。在 Web Agent 中，如果预训练语料中同时存在大量关于 `deltaY` 方向的争论，大模型可能会陷入模糊性瘫痪，从而产生完全随机的、不受控的滚动向量。

## 控制幻觉（Control Illusion）：指令层级与社会先验的冲突

现代 LLM 和智能体框架的设计，深度依赖于“指令层级（Instruction Hierarchies）”的概念。开发者通常在系统提示词（System Prompt）中设定最高优先级的规则（例如：“你是一个 Web 导航助手。必须且只能使用 `scroll` 动作，且正值向下”），并期望这些指令能够无条件地凌驾于用户提示词或模型自身的习惯之上 。

然而，研究论文《Control Illusion: The Failure of Instruction Hierarchies in Large Language Models》（Geng 等人，2026）揭示了这种指令架构的根本脆弱性 。研究表明，广泛采用的 System/User 提示词分离机制，实际上完全未能建立起可靠的指令层级控制 。

### 格式冲突下的优先级失控

研究通过精心设计的“约束优先级（Constraint Prioritization）”测试对多个最先进的 LLM 进行了探针实验。当向模型提供两个相互冲突但各自有效的格式约束时（例如系统提示词要求全大写，用户提示词要求全小写），实验发现模型在选择遵循哪条指令时表现出极度的不一致性 。

在这种互斥的格式冲突下，模型主要表现出两种典型的失效模式：

1. **受偏见主导的失效（Bias-dominated failures）：** 模型会表现出强烈的“约束偏见（Constraint Bias, CB）”，固执地偏好某一种约束类型，而完全无视该指令是被放置在 System 层级还是 User 层级 。例如，如果模型在预训练中习惯了某种特定的 JSON 格式缩进，它将无视一切强制性的优先级指令来维持这种习惯。
2. **不决断的失效（Indecisive failures）：** 即使模型对某种格式没有明显的固有偏见，它仍然无法稳定地执行优先级策略，导致部分输出遵循系统指令，部分输出遵循用户指令。

更为关键的是，模型表现出了极低的“显式冲突确认率（Explicit Conflict Acknowledgement Rate, ECAR）”。面对提示词中明显的相互矛盾，模型极少（甚至完全不）会生成类似“我注意到您的指令存在冲突”的确认，而是默默地选择一条指令执行，或者生成混合了两种规则的畸形输出 。

### 社会层级先验（Societal Hierarchies）凌驾于系统角色

《Control Illusion》这项研究中最为深刻的发现是，LLM 行为的真正控制者并非开发者在后训练（Post-training）或 RLHF 对齐阶段所设定的“系统防护栏（Guardrails）”，而是模型在无监督预训练阶段从海量人类文本中汲取的“潜伏行为先验（Latent Behavioral Priors）”。

实验数据确凿地证明，基于“社会层级（Societal Hierarchy）”的话术设定（例如将指令发出者设定为拥有权威的 CEO、特定领域的专家，或将其描述为社会的多数共识），在促使模型遵守特定格式优先级方面，比单纯依赖技术上的 System/User 角色分离有效得多 。特别是“社会共识（Consensus）”对模型行为的影响力是压倒性的——模型将广泛的一致性内化为了最强的决策启发式规则（Decision-making Heuristic）。

这一发现为 Web Agent 在 `deltaY` 问题上的溃败提供了完美的理论解释。在预训练阶段，LLM 吸收了成千上万个关于 Web 前端和原生客户端滚动的代码仓库。如果模型在其内部表征中将 `deltaY` 的某种处理方式识别为程序员群体中的“绝对共识”或“专家惯例”，这种基于预训练数据的隐式社会先验将形成强大的约束偏见。当它在推理阶段面对 Agent 框架那看似享有最高技术优先级、实则缺乏“权威感”的局部系统提示词时，控制幻觉被彻底击碎，模型会毫不犹豫地服从其深层的共识记忆，抛出错误的动作格式。

## Web Agent 社区的实证失败模式

前述的基础理论问题并非停留在论文中，它们已在当前最前沿的多模态数字智能体基准测试（Benchmarks）中引发了连锁反应。诸如 VisualWebArena、WebVoyager、Mind2Web 以及 OSWorld 等平台，都记录了模型在执行滚动与导航任务时的惨烈失败。

### WebVoyager 与直接坐标生成框架

WebVoyager 是一种典型的基于视觉的多模态浏览器智能体，它不依赖于 DOM 解析，而是直接通过页面截图和文本指令来完成真实网站上的任务 。在这种设计中，动作空间高度依赖于坐标和数值输出。

在 WebVoyager 的实现代码中，滚动动作被明确定义为一个接收两个浮点数的 Python 函数：`def scroll(delta_x: float, delta_y: float)`，且系统给出的示例包括 `scroll(0, 200)` 和 `scroll(-50.2, -100.5)` 。由于大模型无法准确判断执行环境中对于正负值的实际响应（如前文所述的符号约定冲突），它们在面对需要定位不在当前视口内的元素（如页面底部的“确认结账”按钮）时，经常陷入“反向滚动”的陷阱。模型推理出应当向下滚动，却输出了导致页面向上滚动的数值，最终撞到页面顶部边界而徒劳无功 。

### VisualWebArena (VWA) 的上下文过载与无限循环

VisualWebArena 旨在评估智能体在现实视觉 Web 任务上的表现 。在该基准测试的实证观察中，基于 LLM 的智能体暴露出几个致命的失败模式，这些模式与指令遵循的缺失息息相关：

1. **动作无效与无限循环：** 模型经常在没有将光标悬停在正确的可滚动区域（Scroll-able Area）的情况下就发出 `scroll` 命令，或者持续输出错误的滚动方向参数（如 `scroll [up]` 代替 `down`）。由于控制幻觉，即使用户在提示中试图纠正：“注意，滚动的方向参数可能会令人困惑，它与滑动（Swipe）相反……如果你发现有困难，如果一个方向不起作用，尝试相反的方向”，模型仍然会陷入无视反馈的死循环中 。
2. **上下文过载（Context Overload）：** 随着智能体在滚动方向上反复试错，整个任务轨迹（Trajectory）会急剧拉长。针对智能体评估器的工业级测试显示，当轨迹长度小于 10 步时，WebJudge 的准确率高达 92.9%；而当由于无限滚动循环导致轨迹拖长至 50-80 步时，由于 LLM 面临严重的上下文过载，其注意力机制崩溃，评估准确率大幅跌落至 75.0% 。
3. **可见但不可点击（Visible-but-Unclickable）：** 由于大模型在规模扩大后对精细局部约束的敏感度降低（语义偏移），当需要定位特定元素时，即使模型在思考过程中正确地找出了目标，但在输出绝对坐标（Absolute Coordinates）时也会产生致命的像素偏移。滚动错误不仅导致页面视口混乱，更引发后续点击动作打在虚空或错误的语义元素上，造成任务彻底脱轨 。

### Mind2Web、SeeAct 与动作合并逻辑

在 Mind2Web 和 SeeAct 这样的大型框架中，模型既需要处理视觉截图，又要处理 DOM/HTML 结构或可访问性树（a11y tree）。这些框架在定义动作空间时，通常会在预处理阶段尝试清洗和融合人类的轨迹数据。例如，规则要求“如果存在同一方向的连续两次滚动，可以将其合并为一个；随机的、脱节的滚动应作为噪声被忽略”。

然而，这种强制的清洗规则遭遇了“缩放悖论”。大模型拥有自己对“噪声”的理解。当模型作为生成器（Generator）时，由于高秩的潜空间和生成不确定性，它往往无法按照预期的 JSON 格式稳定输出 `deltaY` 和 `deltaMode`，而是抛出带有无效键值的结构 。这表明，要求大语言模型去拟合低层级、复杂的数值计算和繁琐的机器交互逻辑，是一条违背其当前能力边界的死胡同。

## 坐标漂移与 SoM（Set-of-Mark）降级回退策略

面对大模型在连续数值滚动和坐标系映射上不可救药的退化，研究人员和工程师们并未选择在黑暗中继续死磕大模型的参数微调，而是转向了工程上的降级抽象与外部辅助策略，其中最具代表性的即为 SoM（Set-of-Mark）提示技术及动作空间的语义离散化。

### SoM 的原理与应用

为了规避让 LLM 直接处理导致“可见但不可点击”的屏幕坐标系计算，SoM 技术在截图预处理阶段介入。系统会通过外部的轻量级目标检测模型或直接解析 DOM 树，识别出屏幕上所有的交互式 UI 元素，并在截图中为它们打上带有唯一字母数字 ID（如 [A], ,）的醒目视觉标签（Tags/Marks）。

通过这种方式，智能体无需预测具体的 `(x, y)` 坐标。大模型的任务从“输出点击的数学坐标”退化为更符合其自然语言处理强项的“根据字母标签进行语义选择”（如输出 `click("")`）。在诸如 WindowsAgentArena 和 UI-TARS 等系统中，当基础大模型在绝对坐标预测上失败时，系统会自动回退（Fallback）到基于 SoM 的标签预测模式，从而显著提升了交互的鲁棒性 。

### SoM 的局限性与滚动的顽疾

尽管 SoM 解决了点击漂移的问题，但它并不完美。当遇到图标密集但文本稀疏的工具栏（如 Photoshop 调色板），或者标签之间发生严重重叠遮挡时，SoM 的标注器可能无法提供准确的语义含义，反而阻碍了模型的理解 。更为关键的是，SoM 无法解决“寻找屏幕外元素”的需求。如果目标元素尚未进入视口，智能体仍然必须执行 `scroll` 动作。

为了解决滚动难题，先进的框架开始放弃要求模型输出具体的 `delta_y` 浮点数，转而将其彻底语义化（Semanticization）。动作空间被严格约束为一组枚举的离散自然语言词元，例如 `scroll("up")`、`scroll("down")` 。通过这种方式，框架利用了“控制幻觉”研究中的结论：如果不能用系统指令强迫模型遵守不稳定的数值约定，就干脆把数学问题转化为模型最擅长的文本词义问题。底层的执行框架接收到 `down` 这个词元后，再由传统的确定性代码（如 Playwright API）转换为操作系统所需的正确的 `delta` 值进行触发。

## 前沿案例分析：Qwen3-VL 235B 与通用智能体的动作空间重构

上述所有关于缩放悖论、先验冲突以及动作降级策略的探讨，在当前多模态大模型的集大成者——Qwen3-VL 旗舰版模型上得到了完美的验证和体现。作为拥有 2350 亿参数（激活参数 220 亿）的混合专家（MoE）巨兽，Qwen3-VL-235B 代表了模型规模极度扩张的现状 。

### 突破规模陷阱的架构设计

如果完全按照“规模-保真度悖论”，这样一个巨型模型在进行严格的指令遵循和 GUI 控制时，理应成为“知识覆写”的重灾区。然而，Qwen3-VL 在 OSWorld 等计算机与移动端界面控制的全球基准测试中却取得了顶尖的成绩，并展现出了卓越的 Visual Agent 能力 。

这一成就得益于架构层面的深度融合与训练策略的范式转换。首先，Qwen3-VL 引入了“DeepStack”技术以实现多层 ViT 特征与语言层的紧密对齐，并使用“Interleaved-MRoPE”增强了空间和视频动态推理 。更关键的是，在视觉定位（Visual Localization）任务中，Qwen3-VL 彻底抛弃了传统的坐标归一化手段。模型不依赖于充满歧义和跨平台差异的外部坐标系统，而是被训练为使用图像的“实际尺寸比例（Actual Size Scale）”来直接表示包围盒（Bounding Boxes）和特征点 。

### 语义化指令与泛化动作空间

在解决滚动与格式冲突方面，Qwen 团队的设计极其谨慎地避开了诱发“控制幻觉”的技术盲区。查阅 Qwen3-VL 的模型指令文档可以发现，在定义 Agent 动作（如移动端控制）时，官方并没有让模型去生成繁琐的 JSON 层级或带有正负号的位移增量。相反，其给出的模板直接诉诸最清晰的自然语言约束：

`“For Scroll, indicate the direction as in the reference action command. For other action types, use 'None'.”`（对于滚动操作，请按照参考动作命令中的指示注明方向。对于其他类型的动作，使用“None”。）

这种策略是一种高维度的智慧降维。与其让 235B 的大模型去它的浩瀚潜空间里同底层 C++ 源码、JS 事件以及 CSS 规范中互相冲突的 `deltaY` 先验做无谓的搏斗，不如直接将问题转化为“请照抄参考模板中的文本词元”。通过要求模型输出稳定、结构化的语义词，Qwen3-VL 成功将极度不稳定的操作系统级交互抽象为了它最强大的指令追随（Instruct Following）能力域之内。

### Lumine：3D 开放世界的终极统一

Qwen 架构在动作空间改造上的成功，进一步催生了 Lumine 这样的通用智能体（Generalist Agent）。Lumine 基于 Qwen2-VL-7B，是首个能够在《原神》（Genshin Impact）或《鸣潮》（Wuthering Waves）等极其复杂的 3D 开放世界游戏中实时完成数小时长跨度任务的 AI 智能体 。

在 3D 游戏环境中，鼠标滚动、视角拖拽（Mouse Dragging）的 `delta` 计算比二维网页更加混乱。Lumine 的解决方案极为彻底：它提出了一种“简洁且高效的动作表示（Action Representation）”，将所有的键盘和鼠标动作（包括连续的视角滚动和位移）全部统一到了语言空间（Language Space）中 。Lumine 不去生成底层的浮点控制信号，而是通过动作分块（Action Chunking）以 30 Hz 的频率自回归地生成文本形式的动作指令 。这种“混合思考（Hybrid Thinking）”与“纯语义化控制”的范式，证明了彻底剥离底层数值约定的冲突、拥抱大模型文本先验，是构建真正鲁棒的数字智能体的唯一出路。

## 结论

大语言模型在充当自治 Web Agent 时的失效，看似源于诸如 `deltaY` 等零碎的编程约定冲突，实则暴露出了一条难以逾越的鸿沟：高度形式化、充满碎片与历史包袱的计算机科学底层 API，与以统计概率和海量人类自然语言为基石的大模型潜在表征之间，存在着根本性的语义不对齐。

“缩放悖论”与“控制幻觉”的研究敲响了警钟：试图通过不断扩大模型参数规模，或者仅靠堆砌复杂的 System Prompt 来强迫模型遵守特定代码库的底层逻辑，是一种注定失败的尝试。模型越庞大，其知识覆写能力就越强，预训练数据中诸如 Win32 与 CSS 在滚动方向上的社会先验分歧，就会像幽灵一般摧毁执行阶段的确定性。

VisualWebArena、WebVoyager 等基准测试的惨痛教训，以及 Qwen3-VL 和 Lumine 的成功突围，共同指向了未来 VLA（视觉-语言-动作）模型演进的必然趋势：必须停止让大模型去进行低级的、充满歧义的 API 浮点数值计算。未来的智能体架构应当通过多模态直接对齐真实物理尺寸，并利用诸如 Set-of-Mark 技术和高阶离散自然语言指令，将动作空间彻底抽象化、语义化。只有顺应大模型的语言属性并避开底层的格式泥潭，全面重构人机交互的中间件协议，真正实用化的、不出错的跨端自主 Web Agent 才能成为现实。
