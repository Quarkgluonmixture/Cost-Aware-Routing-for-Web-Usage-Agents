## 2. Confidence / Entropy 信号提取

### 2.1 为什么必须做

这是 Phase 2 confidence-based routing 的**前置数据依赖**。文献中两篇直接相关工作验证了其基础设施地位：

| 论文 | 用法 | 效果 |
|------|------|------|
| **AVR** (arXiv:2603.12823) | VLM logprob 作为置信度，低于阈值 → 升级到更强模型/表征 | 成本降低 78%，准确率仅降 0.8pp |
| **CATTS** (arXiv:2602.12276) | margin-gated confidence（top-1 − top-2 logprob），低 margin → 多采样投票 | token 降低 56%，成功率反升 4.7% |

### 2.2 对 P79 的三个不可替代角色

1. **路由决策的量化依据**：当前 router 仅靠 DOM 节点数 + 连续无变化步数（外部观测），logprobs 直接回答"模型对当前 action 有多确信"
2. **小模型置信度校准的研究空白（文献 Gap 6）**：4B 模型的 logprob 是否与成功率单调相关？是否 overconfident？可构成论文实证贡献
3. **Phase 2 阈值设定的数据基础**：数千步的 (logprob, success) 样本可用 ROC 曲线精确设定路由阈值，避免凭经验盲设

### 2.3 提取的 6 个信号

| 信号 | 维度 | 用途 |
|------|------|------|
| mean_logprob / min_logprob | 绝对信心 | 模型对 action 的整体/最弱信心 |
| mean_margin / min_margin | 区分度 | top-1 vs top-2 的选择确定性 |
| mean_entropy / max_entropy | 分布散度 | 全分布不确定性（捕捉 margin 遗漏的多候选散射） |

文献指出：raw logprob 不可靠（小 VLM 校准差、OOD 过度自信），需 temperature scaling 或 learned mapping 校准后才适合做路由信号。因此 Phase 1 先收集数据，Phase 2 在 held-out set 上校准后再用。

## 3. 三层失败分析体系

### 3.1 第一层：GLM Pipeline 自动归因（定量 + 深度）

利用 GLM-5.1 作为 sidecar，对每个失败 episode 输入 step log + AXTree 片段 + 截图描述，输出结构化归因。**不是浮于表面的分类**——GLM 真正阅读了每一步的 thought、action、观测变化，给出 root_cause 和证据链。

**DOM 模式 213 条失败归因**（覆盖率 100%，置信度 96.7% high）：

| 类别 | 数量 | 占比 | 平均步数 |
|------|------|------|----------|
| 目标不可达 | 61 | 28.6% | 17.3 |
| 搜索循环 | 42 | 19.7% | 19.3 |
| 导航循环 | 30 | 14.1% | 28.0 |
| 执行停滞 | 23 | 10.8% | 7.0 |
| 过早结束 | 18 | 8.5% | 2.5 |
| 事实推理错误 | 17 | 8.0% | 7.5 |
| 答案对齐错误 | 12 | 5.6% | 6.1 |
| 视觉属性 DOM 不可达 | 9 | 4.2% | 18.6 |

**根因归属**：

| 归因 | 数量 | 占比 |
|------|------|------|
| 脚手架/表征结构性缺陷 | 109 | 51.2% |
| 模型能力问题 | 104 | 48.8% |

**核心发现**：过半失败（51.2%）归因于 DOM 表征的结构性限制（主要是视觉信息不可达 99 例），而非模型能力不足。这意味着即使换更强模型，DOM 模式在 Classifieds 站的理论成功率上限约 55%。

**示例**：

> **task_133** — 搜索循环
> Agent 发现结果按"最新"排序，却试图通过滚动查找"最旧"商品，未使用排序功能。步骤 5 thought: *"listings are sorted by newness, so I should scroll to see older listings"*。归因：模型策略不足。

> **task_0** — 目标不可达
> 任务要求找"cheapest blue kayak"，但 DOM 不含颜色信息。Agent 搜索后只看到价格和标题，无法验证颜色属性。归因：脚手架/视觉信息不可达。

### 3.2 第二层：Gallery 手动分析（定性 + 深度）

**[现场演示]**

构建了截图标注 + HTML 画廊系统：
- 每步截图叠加 action summary + thought + 元素高亮框
- 双视图：Home 总览（按 condition 分组统计）→ Episode 焦点（逐步截图浏览）
- 键盘导航，自动刷新

通过 Gallery 手动检查发现的深层问题（程序化分析无法捕获的）：
- **SoM text-over-vision bias**：4B VLM 系统性忽略截图视觉细节，依赖 SoM 文字标签决策——SoM 对小模型提供了"不看图的捷径"
- **95% 的详情页 AXTree 不含商品描述文本**——DOM 信息瓶颈比预期更严重
- **标注遮挡**：SoM 青色 mark 框覆盖缩略图左上角，遮挡关键视觉区域

### 3.3 第三层：Analysis 脚本分析（定量 + 统计）

**[现场展示图表]**

自动化分析脚本（每个 condition 完成后自动运行）：

- **`analyze_experiment.py`**：condition 级成功率、步数分布、成本汇总

  - C4/C5: 跨模式置信度对比

## 4. 实验保障基础设施

- **Watchdog 守护进程**：自动检测 benchmark 噪声错误并触发重跑、session 丢失检测（连续 ≥3 task 未登录 → urgent 告警）、GLM digest 自动预处理、截图标注 + gallery 自动刷新
- **busy:1 修复**：页面加载中间态检查提前到 LLM 调用之前，不消耗步数预算——消除了模式间对比的公平性问题
- **数据质量**：JSONL restart 去重、N/A reference task 假阳性标记、cycle detection 误杀修复
