## §1 Epistemic Structure (why this pre-registration shape)

This pre-registration adopts a **Hero + Drop-in + Structural + Framing-Rule** hierarchy rather than the more conventional "all hypotheses pre-committed strict" pattern. The rationale (developed via 2026-05-03 design discussion):

1. **Phantom-SoM is the deployment hero**: 4-fold drop-in property (cost ≈ DOM, latency ~50% lower, signal AUROC ≥ baseline, drop-one positive) is the headline practical contribution. This is pre-registered strict.

2. **Phantom space is a structural claim, not a 3-arm deployment claim**: P-text and P-prompt are not pre-registered as deployment-grade routing arms. They are pre-registered as **structural ablation evidence** validating that phantom space (the cube image-off half) is a 2-axis multi-region empirical structure rather than collapsed to the single P-SoM point.

3. **Framing decision is data-conditional, not data-prediction**: paper §1 hook framing depends on which combination of H1-H3 holds. The rule is pre-registered (R1-R5 below) so reviewers can verify the framing-to-data mapping is not post-hoc.

4. **Theory predictions (别扭, capability-modulated reversal) are post-hoc explanatory**: these frameworks were developed *after* observing N=4 pre-Phase-A cells; treating them as pre-registered hypotheses would be epistemically dishonest. Paper prose explicitly marks them as post-hoc.

5. **Multiple-comparison family discipline**: gating tests (PRIMARY + STRUCTURAL) have explicit Holm-corrected family m count. Exploratory tests (EXPLORATORY family + post-hoc) are reported with adjusted p-values for transparency but NOT used to gate paper claims.

This structure compresses garden-of-forking-paths degree-of-freedom to a small, pre-committed set of tests, while preserving epistemic honesty about which findings emerged from data vs were predicted a priori.

## §2 Hypotheses

### PRIMARY family (gates paper claim)

#### H1 — Hero deployment claim (P-SoM is hidden routing arm)

**Estimand (locked 2026-05-14, decision "3A"; cell count expanded to k=6 per 2026-05-14 B2 addition)**: H1 estimates the **fixed-effects
inverse-variance-weighted average P-SoM drop-one oracle ceiling lift over the 6
*planned* (site, model) cells** — (cls,B0), (cls,B1), (cls,B2), (red,B0), (red,B1), (red,B2). The 6
cells are NOT a random sample from a larger universe of site/model conditions;
they are the specific conditions this study characterizes. Therefore the estimand
is the average effect across *exactly these 6 cells*, not the mean μ of a
hypothetical population. **No between-cell variance τ² is in the estimand** — this
is a deliberate choice (see Appendix A 2026-05-14): it avoids estimating τ² at
k=6. The k<10 random-effects fragility documented in the literature (DerSimonian-Laird τ² downward-bias per Veroniki et al. 2016; random-effects Wald CIs anti-conservative per IntHout et al. 2014; small-k Knapp-Hartung modifications per Röver-Knapp-Friede 2015) is **NOT** invoked here as a recommendation for FE substitution — those papers actually recommend **HKSJ-adjusted random-effects** at small k. The FE choice here is defended **on design grounds**: the 6 cells are the complete pre-registered decision family (decision "3A" 2026-05-14), NOT a random sample from a hypothetical superpopulation, so the FE average over exactly these 6 cells is the principled point-estimand regardless of between-cell heterogeneity. The k<10 RE fragility lit is cited only to justify **appendix-only** status for `aggregate_phantom_meta.py` DL/HKSJ output (B-1305~B-1307 partial retire, B-1308 cite-disambiguation per /stress A2.3d 3-AI overlap OOB F3/F7/C1). HKSJ-adjusted random-effects is reported as Appendix-D sensitivity per the standard small-k recommendation while the primary gate stays FE; see paper §8 Limitations for explicit acknowledgment of this deliberate divergence from the lit recommendation.

**H1 — single PRIMARY gate**: the fixed-effects pooled drop-one effect θ_FE
**significantly exceeds the +1.0pp substantive-effect threshold** via a one-sided
superiority test: reject H0: θ_FE ≤ +1.0pp at α=0.05 (PRIMARY family m=1, no
within-family correction).

This single test implies both (a) θ_FE ≠ 0 and (b) θ_FE point estimate > +1.0pp;
the prior H1(i) "pooled meta ≠ 0" and the separate "magnitude ≥ 1.0pp" check were
redundant with it and have been folded in (2026-05-14 simplification).

**Pooling (operational)**: For each (site, model) cell containing all 6 modes (DOM,
SoM, Vision, P-text, P-prompt, P-SoM), compute oracle ceiling SR over {6 modes}
minus oracle ceiling SR over {5 modes drop P-SoM} per task, then average across the
cell's task pool → per-cell effect θ_i with paired 1000-resample task-level
bootstrap SE_i. Pool via fixed-effects inverse-variance weighting: w_i = 1/SE_i²,
θ_FE = Σ(w_i·θ_i)/Σw_i, SE_FE = sqrt(1/Σw_i). **Primary superiority test (B-1009 2026-05-18 amend per /stress A2.4a P1-17-C* gemini Mode C OOB; B-1303 2026-05-18 amend per /stress A2.3d B-1009 operational-semantics-lock + P1-4-B* codex Mode B OOB)**: one-sided **bootstrap percentile p-value** = `P(θ_FE* ≤ 1.0pp)` over 1000 paired-bootstrap pool replicates, gate `p < α=0.05`. The legacy normal-Z superiority statistic `z = (θ_FE − 1.0) / SE_FE` is retained as a transparency check column (emit `z_one_sided` + `p_one_sided_normal_approx`) but does NOT drive the gate decision. **Operational definition (B-1303 locked semantics for B-1009)**: at each bootstrap iteration b ∈ [1, B=1000], (1) per-cell paired bootstrap replicates θ_i_b are sourced from each cell's `boot_pp` array cached by `_cell_drop_one_theta_se` (B=1000, seed=42 per B-176, +per-axis SHA seed per B-1006); (2) per-cell IV weights `w_i = 1 / SE_i²` use the **point-estimate** SE_i (cell's full bootstrap std, subject to B-1003 Agresti-Coull threshold floor at 0.68pp → 1.0pp); weights are held **fixed** across the B pool iterations (Davidson & MacKinnon 2000 / Hall 1992 standard paired-bootstrap pool: bootstrap captures cell-level signal variability under fixed precision weighting; per-iteration SE re-estimation would require nested 1M-resample inner loop with marginal accuracy gain at k=6); (3) per-iter pool: `θ_FE_b = Σ(w_i · θ_i_b) / Σw_i`; (4) `p_one_sided_bootstrap = (1/B) · |{b : θ_FE_b ≤ 1.0pp}|`; (5) percentile 95% two-sided CI = `[q_0.025(θ_FE*), q_0.975(θ_FE*)]`. **Implementation (B-1301)**: `aggregate_phase1_full_prereg_decision._pool_bootstrap_percentile_p()` emits `p_one_sided_bootstrap` + `ci95_lo/hi_pp_bootstrap` + `theta_fe_bootstrap_median_pp`; primary gate `h1_pass = pooled_h1_bootstrap.gate_passed_bootstrap`; normal-Z `h1_transparency_p_one_sided_normal_approx` retained per amendment. Rationale: at N≈200/cell + baseline SR 10-22% the normal-Z asymptotic assumption is suspect for boundary cases (p≈0.045-0.055); bootstrap percentile uses the empirical pool distribution that already drives the CI, so test statistic + descriptive CI share distributional substrate. **Smoke-check (B-1304 reproducible artifact)**: `docs/checkpoints/probes/b1009_b1301_smoke_2026-05-18.json` synthetic 3-cell archive-like recreation at archive signal (θ ≈ 2.4pp, SE ≈ 0.5pp): bootstrap percentile p = 0.0000 vs normal-Z p = 0.0041 at H₀=1.0pp → decision direction agrees (both reject α=0.05). The earlier pre-B-1301 smoke claim quoting "percentile p = 0.0000, normal-Z p = 5e-06 — bit-identical decision direction" mixed FE vs RE Wald p-values from `meta_phantom_lift.csv:4 p_re_one_sided` (which tests H₀: θ_RE = 0 under DL random-effects, NOT FE bootstrap percentile at H₀ = +1.0pp); the corrected B-1304 smoke artifact verifies the proper apples-to-apples comparison. Closes B-1009 reviewer attack ("Z vs percentile internal inconsistency"; gemini F6 OOB) + B-1301 OSF audit-trail gap ("prereg promise + production code emitting different statistics"; A2.3d 3-AI overlap OOB) + B-1304 smoke-provenance gap (codex F2 OOB on wrong-null citation). **Why FE Wald is sound at k=6 here**: each per-cell
θ_i is approximately normal (CLT on ~210-234 paired tasks); θ_FE is a linear
combination of 6 approximately-normal estimates → approximately normal. The k=4
fragility of the *prior* design came from τ² estimation, which is now absent (the prior wording referencing "k=4" is retained as historical justification — the FE argument applies at any k including k=6).

**Degenerate-cell SE floor protocol (locked 2026-05-17 per /stress A1.19 P0-1, gemini Mode C OOB + Claude data-grounded analysis; reaffirmed 2026-05-17 per /stress A1.21 P0-10 gemini reframe-attack + Claude data-grounded defense)**:
when a cell's paired bootstrap SE_i = 0 exactly (occurs when the drop-one diff vector
is identically constant across all bootstrap resamples — i.e., P-SoM neither uniquely
adds nor uniquely removes any task in the cell), the cell would otherwise receive
w_i = 1/0 = ∞ weight in the FE pool, hijacking θ_FE. We apply an **Agresti-Coull-style
finite lower-bound floor** of `SE_floor = 1.0pp` (i.e., w_i = 1pp⁻²) to such cells.
Rationale: (a) **data-anchored** to archive P-SoM drop-one cells (`results/phantom_paper/meta_phantom_lift.md` archive 2026-05-09: B0 cls SE=0.981pp, B0 red SE=1.096pp, B1 cls SE=0.766pp → archive median SE ≈ 0.98pp ≈ 1.0pp at N≈200-234 paired tasks with baseline SR 10-22%; archive showed zero degenerate cells in 3-cell observation); (b) **conservative** — assigns the degenerate cell a weight no larger than a normally-informative cell, so the FE pool is not dominated by a zero-information observation; (c) **fixed-cells design fidelity** — the cell stays in the FE pool (preserving "all 6 planned cells contribute to θ_FE" estimand integrity per §2 decision "3A") rather than being excluded; (d) **transparently reported** — the `aggregate_phase1_prereg_gate.py` output emits `n_zero_se_floored_cells` for each FE pool decision, and paper §6 prose must disclose this count if > 0. **Implementation**: `aggregate_phase1_prereg_gate.py:185-187` (B-184 producer). **Pre-registered prior to Phase 1a data lock; no post-hoc tuning of floor value permitted**.

**A1.21 P0-10 reframe-attack defense (2026-05-17)** — gemini Mode C attacked this protocol arguing "SE ≈ 1/√N ≈ 0.07pp for a Bernoulli process at N=200" and that the 1.0pp floor "de-weights failures-to-lift, artificially inflating θ_FE". This attack has two arithmetic errors: (i) `1/√200 = 0.0707` in **proportion units** is **7.07pp**, not 0.07pp — gemini conflated unit bases; the correct Bernoulli SE at N=200, p∈[0.05, 0.20] is `√(p(1-p)/N) × 100 = 1.5-2.8pp`, **larger** than our 1.0pp floor, not smaller; (ii) FE weight is `1/SE²`, so a *lower* floor would *increase* the degenerate cell's weight (e.g., SE_floor=0.07pp → w=204×, hijacking the pool — exact opposite of gemini's claimed "de-weight"). Resolution: protocol retained at `SE_floor = 1.0pp`. Cross-checked against (i) Agresti-Coull binomial SE at x=0, N=200: `√(p_AC × (1-p_AC) / (N+z²)) ≈ √(0.0094 × 0.99 / 204) ≈ 0.68pp` ≤ floor (cushion); (ii) archive empirical median SE 0.98pp ≈ floor (anchor); (iii) `aggregate_phase1_prereg_gate.py:186-188` SE floor fires only when `(ses <= 0).sum() > 0` — pre-Phase-1a-fire empirical state showed 0 degenerate cells across 3 archive P-SoM observations, so floor is edge-case backstop (Phase 1a user empirical intuition: "psom unique 应该不会是 0"). Paper §6 disclosure: "We apply a 1.0pp finite lower-bound SE floor on degenerate cells (≡ Agresti-Coull pseudo-count on x=0/N≈200 binomials, archive-median-anchored at 0.98pp); `n_zero_se_floored_cells` reported in `phase1_prereg_gate.json` for each pooling decision." A sensitivity table over floor values {0.5pp, 1.0pp, 2.0pp} on archive data is provided in Appendix-D — paper §1 hero θ_FE is robust within ±0.05pp across that range when degenerate cells are absent (current archive state), and the sensitivity becomes relevant only post-Phase-1a-fire IF any cell yields exactly-zero bootstrap SE.

#### H2 — Drop-in property (P-SoM specifically)

**Scope (revised 2026-05-13 codex stress audit T2; refined 2026-05-14 decision "3A")**:
The R1 framing rule depends on **H2(a) cost** only, and H2(a) is a *by-construction
property with a falsification check* (not a statistical gate — see below). H2(b)
latency and H2(c) signal AUROC are **EXPLORATORY transparency reports** (NOT gating
R1). H2(d) drop-one magnitude is already covered by the H1 superiority gate. Rationale:

- (a) is a by-construction model property (regex filter ≡ no image tokens), verified
  by a falsification check, not a sampling-theory hypothesis test
- (b) latency depends on serving infrastructure (DGX vs A100 vs proxy), not a model
  property; should be characterized but not gated
- (c) signal AUROC depends on routing-signal universe choice (`aggregate_routing_auroc.py`
  top-1 selection), which is exploratory characterization per §5 — including AUROC
  in R1 gating would force a circular dependency
- (d) folded into the H1 superiority gate

**H2(a) — BY-CONSTRUCTION property with falsification check (locked 2026-05-14, decision "3A")**:
P-SoM cost ≈ DOM cost is **not an empirical hypothesis to be gated by a statistical
test** — it is a *by-construction* property. P-SoM's observation is `[SOM_MARKS]` =
a regex filter over the *same* VWA accessibility-tree text the DOM baseline already
consumes, plus *no image tokens*. The token count therefore cannot be substantially
higher than DOM by construction; it is bounded by DOM cost + a regex-pass overhead
that is provably negligible. Running a sampling-theory equivalence test (TOST) or a
K-of-N count on a near-deterministic token-count quantity would be a category error.

- **By-construction argument**: stated in paper §3.2 (regex-filter derivation).
- **Empirical falsification check (pre-registered, amended 2026-05-17 per /stress A1.21 P0-9 + user-confirmed prereg amend; further amended 2026-05-17 per /stress A1.22 P0-1-ABC* cross-baseline contract sealing)**: report observed **per-task median ratio** of `cost(P-SoM)/cost(DOM)` per (site, model) cell in §4. **Estimand: `median over tasks of (cost_psom[t] / cost_dom[t])`** — paired (same `task_id` in both DOM and P-SoM mode, intersection of common observed tasks per `generate_per_task_sr.py:200-211` paired-CSV producer). **NOT** the prior implementation's median-of-marginals (`median(P-SoM costs across tasks) / median(DOM costs across tasks)`) which silently ignored paired structure and was the wrong estimand for the paper §1 per-task framing. **Falsification threshold**: if ANY cell shows per-task median ratio > **1.20×** (= +20% margin), the by-construction claim is contradicted and must be investigated (regex not filtering / hidden overhead / tokenizer surprise) before H2(a) can be asserted. **H10 OPERATIONAL DEPLOYMENT GATE (locked 2026-05-18 per A2.8 P0-2-AB* user-directive resolution, B-1551)** — two-layer criterion, no across-cells binomial inference:

- **Cell-level (statistical)**: per cell, paired bootstrap (B=1000, seed=42) on the cell's common task set evaluating (Cost, SR). A cell **passes cell-level** if the learned router is Pareto non-dominated by any of the 5 pre-registered single-mode baselines in **≥95% of bootstrap replicates**. This is a task-level paired-bootstrap statistical inference *within* each cell — the cell's per-task pass/fail labels are the resampled unit, NOT cells across the grid. Per-cell paired bootstrap operates on (Cost, SR) jointly: at iteration b ∈ [1, B=1000], sample N tasks with replacement (paired across router + each baseline arm), compute (Cost̄_router_b, SR̄_router_b) + (Cost̄_baseline_m_b, SR̄_baseline_m_b) for each baseline m; router is non-dominated in iter b iff no baseline m simultaneously satisfies Cost̄_m_b ≤ Cost̄_router_b AND SR̄_m_b ≥ SR̄_router_b with at least one strict. The cell's `fraction_non_dominated` is the count of non-dominated bootstrap iterations / B; cell passes if fraction ≥ 0.95.

- **Grid-level (operational robustness criterion)**: H10 is **considered deployable** if at least **5 of 6 pre-registered cells pass cell-level**. **This 5/6 threshold is a fixed-cell operational deployment criterion for the paper §6 deployability claim — NOT a binomial significance test over a population of cells**. The 6 cells are the complete pre-registered decision family per decision "3A" 2026-05-14 finite-population framing (§2 H1 estimand); the prereg does not interpret 6 cells as a random sample from a larger universe of (site, model) tuples, so a binomial inference over cells (e.g., K=5/6, p-binomial) is not a coherent frequentist test at this design. The 5/6 grid-level threshold is a **pre-registered engineering deployment criterion** stating that the learned router must work in at least 5 of the 6 pre-registered (site, model) conditions for paper §6 to claim deployable learned routing — interpretable as a fixed-cell operational robustness requirement, parallel to how engineering benchmarks require a service to meet SLA in N of M shards rather than asserting a binomial population claim. **K-of-N fake-precision argument (§2.4 transparency-only K-of-N reclassification) does NOT apply here** because the K-of-N retired-doctrine targets *across-cells binomial inference at α* (which inflates Type-I error at small N), whereas this 5/6 threshold is an *operational engineering criterion not interpreted as a frequentist test* (no across-cells α, no Type-I/Type-II coupling, no "fake precision" of a 0.75 vs 0.67 ratio because the threshold is exact 5/6 = 0.833 chosen as an engineering deployability margin, not a significance level).

**H10 passes the operational deployment gate** iff (a) per-cell paired bootstrap shows ≥95% Pareto non-dominance support for at least 5 cells AND (b) those ≥5 cells span the 6 pre-registered (site, model) tuples (no cell-level missing-data exclusion). Failing the operational deployment gate does not by itself constitute a statistical rejection of any null hypothesis at α=0.05 (there is no across-cells null here); it characterizes the router as **not robust enough across the pre-registered grid** for paper §6 to claim deployable learned routing — paper §6 under H10-FAIL reports per-cell descriptive (Cost, SR) operating points + Appendix-D FE-pool sensitivity row, and paper R-rule branching applies (R3 cap if H10 FAIL alone, R5 paper-death if H1 also fails).

### §2.6 Observation-mode scope clarification (added 2026-05-15 evening, /stress A1.1 v8 Mode C catch)

## Appendix D-bis — HKSJ-adjusted random-effects sensitivity (B-1309 /stress A2.3d P1-3 Q4(A) + codex Mode B F5 OOB non-shrink guard)

**Purpose**: address the lit-divergence reviewer attack vector (P1-3 cite-conclusion drift caught as 3-AI overlap OOB 2026-05-18). Veroniki et al. 2016 / IntHout et al. 2014 / Röver-Knapp-Friede 2015 recommend HKSJ-adjusted random-effects as the standard small-k correction; our primary gate (FE pooled bootstrap percentile per B-1009 + B-1301) deliberately diverges from this recommendation on **design-based grounds** (decision 3A: 6 cells are the complete pre-registered decision family, not a population sample). To close the methodologist objection vector, this Appendix-D-bis reports HKSJ-adjusted RE alongside FE primary as a sensitivity row.

**Method (modified Knapp-Hartung per Röver-Knapp-Friede 2015 §4 non-shrink guard)**:
- HKSJ multiplier `q_hk = Σ w*_i · (θ_i − θ_RE)² / (k − 1)` where `w*_i = 1 / (SE_i² + τ²_DL)` (Sidik-Jonkman 2002).
- `SE_HKSJ = sqrt(q_hk / Σ w*_i)`.
- **Modified-Knapp-Hartung non-shrink guard (codex Mode B F5 catch /stress A2.3d 2026-05-18)**: when `q_hk < 1`, unmodified HKSJ shrinks `SE_HKSJ` below the DL `SE_RE` — an undesirable property because the t-distribution premise of HKSJ is to *widen* CI for small-k uncertainty. Modified rule: `SE_HKSJ_mod = max(SE_HKSJ, SE_RE)` (always at least the RE Wald SE; never shrinks). Archive 3-cell P-SoM hero arm empirical: `se_re = 0.529pp`, `se_hksj_unmodified = 0.466pp` (12% shrinkage), `se_hksj_modified = 0.529pp` (non-shrink guard restores RE Wald SE).
- HKSJ CI uses `t_{k-1, 0.975}` quantile (k=6: t = 2.571; k=3 archive: t = 4.303).
- One-sided p reported at H₀ : θ = 0 (consistent with `meta_phantom_lift.csv` columns) AND at H₀ : θ ≤ 1.0pp (consistent with FE primary gate).

**Hero arm archive smoke (B-1309 reproducibility witness from `meta_phantom_lift.csv:4` row `4psom_vs_3`)**: θ_RE = +2.34pp, SE_RE = 0.53pp (`hk_se_hk` unmodified = 0.466pp, `hk_se_hk_modified` non-shrink = 0.529pp, t_stat = 5.01, df = 2, t_crit = 4.30, `hk_p_one_sided` at H₀=0 = 0.0188); under modified-HK non-shrink guard `SE_HKSJ_mod = 0.529`, `t_stat_mod = (2.34 − 0)/0.529 = 4.42`, `p_one_sided_mod` at H₀=0 still rejects (p < 0.025 since t_stat > t_crit/√2 in one-sided regime), and at H₀=1.0pp the modified t = (2.34 − 1.0)/0.529 = 2.53 with df=2 (one-sided p ≈ 0.06, marginal — Phase 1a k=6 expected to reduce SE / increase t-stat). **Qualitative direction agreement**: FE primary (p_bootstrap = 0.0000) and HKSJ-modified Appendix-D-bis (p_one_sided > 0 but small) both reject the trivial null H₀ = 0 on hero arm strongly; on H₀ = +1.0pp the FE gate passes decisively at archive while HKSJ-modified is marginal — consistent with the prereg L85 rationale that bootstrap percentile + design-based FE is the more powerful tool for the design-fixed-cell estimand, while RE/HKSJ remains valuable as conservative sensitivity.
