## 1. Introduction

Multimodal web agents that combine browser screenshots with DOM-derived text act through representations (the scope this paper validates; see §8.1 for the bounded-comparison disclosure of the agent-scaffolding class — text-only or coordinate-only agents fall outside this scope, B-1281 /stress A2.6b P1-9-AC 2026-05-18). A browser state can be serialized as a DOM or Accessibility Tree, shown as a screenshot, or annotated with Set-of-Mark (SoM) labels that connect visible regions to discrete element IDs. Existing benchmarks and agents treat these as different observation modes: WebArena and Mind2Web popularized DOM-derived text for realistic web tasks, while VisualWebArena and SeeAct introduced visually grounded settings where screenshots and action grounding become central \citep{zhou2024webarena,deng2023mind2web,koh2024visualwebarena,zheng2024seeact}. Set-of-Mark prompting was designed for this multimodal setting: a marked image is paired with a textual legend so the model can refer to visual objects by number \citep{yang2023som}. Later multimodal-agent systems, including SeeAct and Magma, further explored marked-screenshot and omni-modal action-grounding paradigms rather than treating mark text as an isolated scientific variable \citep{zheng2024seeact,yang2025magma}. These are important precedents. We therefore do not claim to be first to deploy text-only, marked, or SoM-style observations. Our claim is about controlled characterization: isolating what changes when the annotated image is skipped while the text payload and prompt family are varied under the same task, model, and evaluation protocol.

This paper questions that bundling assumption as an experimental object. We characterize the **phantom routing space**: the set of agent configurations **formed by varying text-payload format (AXTree ↔ `[SOM_MARKS]`) and prompt family (DOM-prompt ↔ SoM-prompt) from the DOM baseline**, all on the "skip annotated image" boundary that removes the **marked page screenshot**.[^image-scope] [^phantom-boundary-formulation] [^scaffolding-class-scope] DOM is the **origin baseline** (axis-0 in the 2×2 ablation diamond); the three perturbation arms are **P-text** (text-axis alone: `[SOM_MARKS]` under DOM-prompt), **P-prompt** (prompt-axis alone: SoM-prompt over AXTree), and **P-SoM** (compound: `[SOM_MARKS]` under SoM-prompt). P-SoM is the deployment-relevant representative — the agent receives the SoM prompt and the `[SOM_MARKS]` textual element list, but no marked screenshot. At the start of this project, P-SoM looked like a broken ablation. The natural expectation was that removing the marked screenshot would collapse SoM into either a weak DOM surrogate or a nonsensical configuration: the prompt still suggests visual marks, but the visual substrate is absent. The data reject that expectation. Phantom-SoM solves tasks that DOM, full SoM, and Vision all miss, and on B0 reddit it matches or modestly exceeds full SoM by VWA-Success (N/A excluded) (**13.81% vs 10.48%, N=210**; the gap is within 2σ under the run-to-run variability we observe in same-condition repeats), while avoiding the per-step marked-screenshot encoding cost. On classifieds, full SoM remains clearly stronger (**21.37% vs Phantom-SoM 14.53%, N=234**), the expected sanity check when marked screenshots carry real visual information.

[^scaffolding-class-scope]: **Phantom space scope is bounded by the agent-scaffolding class (B-1280 /stress A2.6b P0-1-AC* 2026-05-18, Claude Mode A + gemini Mode C overlap).** The phantom routing space construct presupposes three scaffolding properties: (a) the agent uses screenshot-based observation pipelines (text-only LLM agents like AutoGPT or TaskWeaver do not exhibit this boundary because they never had an image to skip); (b) the agent uses SoM-style numbered visual grounding paired with a textual element legend (coordinate-only agents or raw-pixel agents like Tarsier do not have the `[SOM_MARKS]`/marked-screenshot bundle to ablate); (c) the deployment backend treats image encoding as a non-trivial cost stage (sub-100M-parameter vision towers or future cheap-vision VLMs would shrink the cost gap toward zero). Within this scaffolded class — VisualWebArena, SeeAct, Magma, and successor SoM-style multimodal web agents — the phantom space exists by construction; outside this class, the "no annotated image" boundary either does not arise (no image to begin with) or arises in a structurally different form (different bundle). The paper's empirical claims are scoped to this class. See §8.1 cross-family bounded-comparison stack for the parallel multi-baseline disclosure.

Our first contribution is a controlled scientific evaluation of this phantom boundary. Across completed B0 VisualWebArena classifieds and reddit runs, we compare DOM, full SoM, Vision, and Phantom-SoM on the same task sets (**N=234 classifieds; N=210 reddit; same-task VWA-Success (N/A excluded)**) and use the P-text/P-prompt controls to test whether the effect collapses to one prompt trick or one text-format swap. Phantom-SoM is not the best single arm on every site, and we do not claim that it replaces full SoM. Its value is complementarity. The principal hero metric is the **drop-one oracle**, not the single-mode SR difference. The numbers reported here are from the **archive 4-mode universe** {DOM, SoM, Vision, P-SoM}: Phantom-SoM contributes **3.33 percentage points** of incremental oracle value on reddit with a **task-resampling 95% two-sided CI of [+0.95, +6.19]** (per-task paired bootstrap, B=1000 resamples; the prereg-locked H1 superiority gate is a **single one-sided fixed-effects pooled bootstrap percentile test** against δ=1.0pp at α=0.05 over the 6 planned (site, model) cells per prereg §2 H1 decision 3A — NOT a family of per-cell tests; the 95% two-sided CI shown here is the descriptive-uncertainty channel for the per-cell archive estimate, while §4 reports per-cell drop-one + bootstrap CI as a transparency table accompanying the single pooled gate decision — B-1008 /stress A2.4a P1-16-C* + B-1311 /stress A2.3d P1-11-C* pooled-vs-per-cell prose disambiguation per gemini Mode C unique OOB), comparable to full SoM at +1.90pp [+0.48, +3.81], and **2.56 percentage points** on classifieds with CI [+0.85, +4.70].[^hero-estimand-scope] [^null-framing] Cross-mode Jaccard similarity falls in the **0.29-0.49 range** against other arms; this is **3-5× higher than the random-independent baseline** (E[J] ≈ 0.06-0.10 given the observed marginal pass rates), indicating substantial pass-correlation across modes. The complementarity claim therefore rests on the **residual unique-pass set** being large enough to drive non-trivial drop-one oracle excess. **Within the sampled VisualWebArena classifieds + reddit task pool (N=234 + N=210 respectively), P-SoM solves a unique subset (on the order of 7 reddit + 6 classifieds tasks) that no other mode in the 4-mode archive universe solves; §4 success-pool table** (B-1283 /stress A2.6b P0-4-C* 2026-05-18, gemini Mode C OOB — the unique-pass count is a finite-sample property of (P-SoM, this 6-cell design, this task pool), not an inherent super-population property of the P-SoM mode; cross-task-distribution generalization is future work via Phase 1b shop fire + WebArena cross-benchmark pilot per §8 future-work). To verify the unique-pass set is not driven by a single task-type cluster (B-1235 /stress A2.4b Chunk β P1-7-AC, 2026-05-18), §4.X cross-references the per-task-category heatmap showing the P-SoM-unique tasks distribute across multiple intent categories (search, comparison, navigation) rather than concentrating in one anomalous task family — site-level effects therefore reflect cross-task-type breadth rather than a task-distribution artifact. **Drop-in property — constructed vs measured.** By construction, phantom-space arms inherit DOM's cost profile and lower per-step latency: the `[SOM_MARKS]` block is produced by a regex pass over the same accessibility-tree text the DOM agent already consumes (interactive elements come pre-numbered as `[N] role 'label'` under VisualWebArena's Playwright accessibility-tree serialization; the deployment portability claim therefore covers **VWA-AXTree-equivalent observation pipelines**, with cross-benchmark serialization adaptation needed for environments lacking pre-assigned numeric element IDs — see §3.2 boundary table for the per-mode serialization dependency and §8 future-work for the cross-benchmark generalizability speculation, B-1282 /stress A2.6b P0-2-AC* 2026-05-18 Claude Mode A + gemini Mode C overlap), so a deployment that can run DOM can run Phantom-SoM by changing what it forwards to the model — no bounding-box pipeline, no per-step marked screenshot, no extra inference modality at every browser step. These are **architectural consequences of the image-off boundary**, not empirical discoveries. On top of this constructed substrate, we **empirically validate two non-trivial signal properties**: (c) routing signal AUROC ≥ baseline (§4.X) and (d) strictly-positive drop-one oracle excess over fixed-marginal permutation null (§4.Y).[^cost-basis-cross-baseline] **The drop-one number is an oracle ceiling, not a realized router gain; Section 6 reports realized lift after router classification overhead and misrouting regret, alongside the oracle bound for context.**

Our third contribution is a **representation-axis cost-aware router** that exploits the phantom routing space. **Unlike model-routing systems (FrugalGPT \citep{chen2023frugalgpt}, RouteLLM \citep{ong2025routellm}, and the uncertainty-decomposition framework of \citep{peale2026flexibleRouting}) whose arms differ in *model* under fixed input representation, the phantom routing space holds the model fixed and varies the *representation*; the deployment cost asymmetry comes from representation choice rather than from model scale.** The behavioural two-knob account predicts a routing signal at the *task* level: tasks whose intrinsic structure rewards quick decision-and-commit behaviour (forum-style lookup, list-traversal queries) should benefit from the flat `[SOM_MARKS]` text representation, while tasks rewarding sustained exploration (multi-step navigation, comparison shopping) should benefit from the hierarchical AXTree representation (**observed on VWA cls/red task pools at the prereg-locked 6-cell scope; cross-pool task-structure generalization remains future work — see §8 future-work cube-concept generalizability paragraph**, B-1293 /stress A2.6b P1-15-A* 2026-05-18 — the task-structure-based prediction is a super-population claim about task-feature → mode mapping but is empirically supported only by the finite 6-cell task pool). The phantom arms' **constructed** cost-equivalence with DOM provides the **substrate** for cost-aware representation routing; whether **realized** router lift compensates router classification overhead and misrouting regret is reported in §6 alongside the oracle ceiling for context.
