## 2. Background and Related Work

### 2.1 Web Agent Observation Modes

Modern web agents differ less in the browser actions they expose than in the observation representation they give to the language model. Text-only agents typically serialize the Document Object Model or Accessibility Tree (AXTree) into a hierarchical text observation. WebArena uses this style of realistic browser environment to evaluate language-guided agents on shopping, forum, map, and software-development tasks \citep{zhou2024webarena}. Mind2Web similarly frames web interaction as selecting actions from structured page elements collected across real websites \citep{deng2023mind2web}. This line of work makes DOM-derived text the default low-cost representation: it is cheap, symbolic, and compatible with language-only models, but it can be verbose and blind to visual appearance.

Multimodal web agents add screenshots to the observation. VisualWebArena extends WebArena with visually grounded tasks and evaluates agents that combine page text, screenshots, and visual grounding cues \citep{koh2024visualwebarena}. A common grounding device is Set-of-Mark prompting, introduced by Yang et al. as a way to overlay numbered or speakable marks on image regions so a multimodal model can refer to visual objects by discrete IDs \citep{yang2023som}. SeeAct likewise studies GPT-4V as a generalist web agent and finds that visual understanding must still be paired with reliable action grounding \citep{zheng2024seeact}. Magma pushes the same broad direction into an omni-modal agent foundation model with action grounding and multimodal pretraining \citep{yang2025magma}. Vision-only baselines remove the DOM/AXTree channel and ask the model to act from the screenshot alone; these baselines test whether visual perception can substitute for structured symbolic grounding.

Across this literature, DOM, SoM, and Vision are treated as orthogonal observation modes. SoM in particular is treated as a multimodal bundle: a marked screenshot plus a text legend that maps mark IDs to elements. The `[SOM_MARKS]` text is normally an auxiliary index for the marked image, not a controlled standalone variable. This convention is the gap our paper targets. We ask what routing behavior emerges when the annotated image is skipped while the remaining factors are held apart: AXTree versus `[SOM_MARKS]` text, DOM versus SoM prompt family, and image-off versus image-on evaluation. The resulting object is not a claim that marked or text-only observations are new artifacts; it is a controlled characterization of the phantom routing space around **Phantom-SoM**.

### 2.2 Routing in LLM Systems

Routing has become a standard response to heterogeneous cost and capability. FrugalGPT frames inference as a cascade over multiple LLM APIs, learning when cheaper models can answer and when to escalate to stronger models \citep{chen2023frugalgpt}. RouteLLM similarly learns routers from preference data to choose between weaker and stronger LLMs under cost-quality tradeoffs \citep{ong2025routellm}. More recent agent-routing work broadens the *compute* arm without touching the representation: DMR routes numeric precision per step between a bf16 and a quantized variant of the *same* model \citep{li2026dmr}, and PANDO routes model capacity (an expensive planner versus a cheap actor) inside a single VisualWebArena agent \citep{li2026pando}. These systems are important precedents for cost-aware inference, but their arms are models, capacity tiers, or numeric precisions. The input representation is usually fixed while the backend computation changes.

Web-agent routing has begun to appear at the modality or expert level. Avenir-Web proposes a Mixture of Grounding Experts for multimodal web agents, using human-experience imitation and expert grounding components to improve long-horizon deployment \citep{li2026avenirweb}. Systems work on multimodal serving also motivates modality-aware scheduling: image-heavy requests create different prefill, encoding, and time-to-first-token bottlenecks than text-only requests, so serving systems can separate resources by modality and stage \citep{qiu2025modserve}. These works route over computational pathways, modalities, or grounding experts.

What is missing — and the precise novelty pivot we claim — is a **learned, cross-modal, per-task representation router within a single model**: selecting at task time between representations generated from the same browser state, where the arms differ in modality composition (image-on vs image-off) and text format. Two adjacent systems bound this claim and we differentiate both rather than ignore them. Agent-E selects among DOM-variant *text* observations per task (text_only / input_fields / all_fields), but its arms stay within one text modality and the selection is not learned — an agent-internal choice among hand-specified DOM content variants \citep{dhondt2024agente}; WebRouter routes queries across *models*, not across representations of the same state \citep{webrouter2025}. Neither routes a fixed model across the image-on/image-off representation boundary that the phantom space exposes. DOM/AXTree and `[SOM_MARKS]` carry the **same element semantics** (every valid accessibility-tree node — interactive and static — its role, its label, its URL — both views are produced from the same accessibility-tree pass; §3 reports the matched payload-length medians), but their **representation contract** differs along two bundled dimensions: (i) **structural format** — one preserves hierarchical nesting and parent-child indentation, the other is flattened into a flat indexed list; and (ii) **identifier contract** — the AXTree-native view exposes each element by its native accessibility-tree node id, while the `[SOM_MARKS]` view uses a deterministic 1..K sequential selection id (the standard SoM-interface convention; see §3.5 and Amendment 07). We therefore characterise axis-1 as **AXTree-native representation → SoM-indexed selection representation**, not "pure flattening" alone. Prior routing work does not ask whether a single model should see the same page as a hierarchical AXTree for some tasks and as a flat indexed selection list for others. Phantom-SoM makes that missing routing axis explicit.

This distinction also separates our setting from ordinary prompt selection. A representation arm is not just a different instruction template; it changes the observation object that enters the agent loop at every step. If two formats derived from the same browser state route the same model into different exploration policies, then representation becomes a deployable control surface. The router need not choose a larger model or a visual encoder first. It can choose a cheaper textual view of the page, observe whether the trajectory stalls, and escalate only when the cheap representation appears misaligned with the task.

### 2.3 Prompt-Format Sensitivity in LLMs

The plausibility of Phantom-SoM rests on a broader fact about language models: semantically equivalent prompts can induce different behavior when their surface form changes. Sclar et al. quantify language-model sensitivity to spurious prompt-format features and show that small formatting choices can produce large accuracy differences, even when the underlying task semantics are unchanged \citep{sclar2024promptformat}. Mishra et al. show a related effect for instructional prompting: reframing instructions into forms better aligned with a model's learned language can change few-shot performance \citep{mishra2022reframing}.

These studies do not study web agents, but they explain why web observations should not be treated as neutral containers. A page serialized as AXTree text is not merely "the same information" as a page serialized as `[SOM_MARKS]`. The model receives different punctuation, ordering, indentation, repeated role tokens, ID patterns, and local neighborhoods. Those surface-form differences are associated with different downstream action distributions (the model-internal account of *how* is deferred to the mechanism follow-up paper).

Recent circuit-level analysis sharpens this from a correlational observation into a mechanistic one. Judge Circuits \citep{feldhus2026judgecircuits} uses causal edge-attribution patching on text LLM-as-judge across Qwen2.5, Gemma-3, and Llama-3 backbones — lineages overlapping (but not identical to) our Qwen3-VL and Gemma-3 baselines — and localizes a sparse, format-conditional sub-computation in mid-to-late MLPs, where a continuous judgment signal is mapped through fragile, format-specific terminal branches to a discrete output. Two caveats bound the transfer to our setting, and we state both rather than over-claim a mechanism: the "format" they manipulate is the judge's *output* format, not an agent's *input* observation, so the link is conceptual rather than evidential; and their key finding — that the separability of format-conditional computation from world knowledge is family- and scale-dependent (modular in Gemma-3-27B but *entangled* in the smaller Gemma-3-12B) — predicts a cross-family confound for our still-smaller B2 = Gemma-3-4B, where the format/content separability the phantom axis assumes may be weaker than for the Qwen baselines (we return to this as a predicted, not settled, risk in §7.3 and §8.1).

For a web agent, prompt-format sensitivity matters at the trajectory level. The model is not producing a single label; it is choosing whether to search, click, scroll, revisit a page, or finish. Section 4 and Section 5 build on this theoretical anchor: the flat marks list tends to shift exploration toward quick element selection, while AXTree hierarchy tends to support sustained navigation and search. Prompt wording also matters, but our two-knob account separates the layers: text representation shapes how the agent explores, while prompt family tunes when it commits.

### 2.4 Cost-Efficient Inference for Web Agents

Cost-efficient web-agent inference has usually meant pruning or scheduling expensive context. AXTree observations are long, noisy, and security-sensitive. FocusAgent addresses this by using a lightweight retriever to trim AXTree observations before sending them to the main agent, reducing context while preserving the hierarchical representation \citep{kerboua2025focusagent}. This is a natural text-efficiency strategy: keep the DOM-derived tree, but remove irrelevant lines.

Multimodal inference adds a second cost source: visual encoding. Image inputs increase prompt-processing time, memory pressure, and time-to-first-token. ModServe characterizes large multimodal model serving and shows that multimodal workloads have heterogeneous stages and resource requirements, motivating modality- and stage-aware resource disaggregation \citep{qiu2025modserve}. In web agents, full SoM therefore has two costs: it prepares a marked screenshot and it sends image tokens to the model.

A complementary visual-efficiency line prunes redundant image content rather than scheduling it. ReVision \citep{abaskohi2026revision} learns a keep-mask over consecutive-frame screenshot patches and fine-tunes the backbone on the filtered trajectory stream, cutting roughly 46% of visual tokens at a small SR gain across OSWorld, AgentNetBench, and WebTailBench. This contrasts with Phantom-SoM in two ways that clarify what our representation routing is *not*: ReVision requires fine-tuning the backbone, so it is not an inference-time drop-in; and it prunes *temporal, patch-level* redundancy *within* the kept image stream, whereas Phantom-SoM drops the *entire* annotated image, exploiting the *cross-modal* redundancy between the marked screenshot and the flattened `[SOM_MARKS]` text that already encodes the same element index. ReVision is a contrast point, not a method we reuse.

A behavioural literature explains why dropping the marked screenshot need not erase the visual-grounding signal the model actually uses. Vision-language models frequently answer from language priors rather than from pixels: MIRAGE reports that frontier VLMs generate detailed image descriptions and reasoning traces — and score highly on standard benchmarks — even when no image is supplied \citep{asadi2026mirageillusionvisualunderstanding}, and the Scaffold Effect shows that merely *mentioning* an available modality in the prompt drives most of the apparent multimodal gain in clinical VLM evaluation \citep{vu2026scaffold}. Diagnosing Visual Ignorance sharpens this into a quantitative, layer-resolved claim: across twelve VQA benchmarks, 20–40% of samples receive an identical answer when the image is fully occluded as when it is shown — the prediction never depended on the pixels — and the authors localize a two-stage suppression in which middle layers still carry the visual signal but late layers re-inject text-space priors \citep{zhou2026visualignorance}. Two caveats bound the transfer and we state both: these are single-image VQA studies, not multi-step web agents; and their *visual ignorance* is a model discarding a **present** image, whereas Phantom-SoM **removes** the image while **preserving** its element index in `[SOM_MARKS]` text. The connection is therefore motivational — it predicts that a model already underusing the marked screenshot, handed the same element index as text, can retain much of the SoM signal at DOM-like cost — not a mechanism we measure here (the layer-resolved account is deferred to the follow-up paper).

Phantom-SoM explores a different kind of efficiency. It is not text pruning and it is not image scheduling. It is text reformatting. The `[SOM_MARKS]` list can be generated from the same browser/AXTree metadata already available to the agent, then sent without the marked screenshot. This removes image-token cost while preserving a discrete element index. In our runs the text observation is comparable in token length to the corresponding AXTree (within ±7% on reddit and classifieds, holding the system prompt fixed); the difference is in structure — flat indexed list versus nested hierarchy with url/tab metadata — rather than in length. The open question is whether such a representation is only a structural rewrite of DOM, or whether its format creates a distinct success pool. Our empirical sections answer the latter.

This matters because many cost reductions trade away information: smaller models, shorter context windows, lower image resolution, or fewer retrieved lines. Phantom-SoM instead tests whether a cheap re-arrangement of already available text can expose a different reasoning path. If it succeeds on tasks missed by DOM, the gain is not merely compression; it is complementarity. That is why Section 4 reports both single-mode success and drop-one oracle value rather than treating token savings alone as the contribution.

### 2.5 Position of This Work

This paper positions Phantom-SoM at the intersection of four literatures that are usually studied separately. First, SoM and its descendants, including Magma and Ferret-UI 2, use marks or related visual-grounding devices and generally keep text tied to the marked image \citep{yang2023som,yang2025magma,li2025ferretui2}. Second, web-agent benchmarks compare DOM, SoM, and Vision modes, but do not use the mark-text-without-image condition as a controlled axis for routing characterization \citep{zhou2024webarena,koh2024visualwebarena,zheng2024seeact}. Third, routing systems optimize over models, modalities, or experts, not over representations of the same browser state \citep{chen2023frugalgpt,ong2025routellm,li2026avenirweb} — the nearest neighbours, Agent-E's hand-designed within-text DOM-variant selection \citep{dhondt2024agente} and WebRouter's query→model routing \citep{webrouter2025}, are differentiated in §2.2. Fourth, prompt-format work predicts sensitivity to representation syntax, but has not measured task-pool complementarity in interactive web agents \citep{sclar2024promptformat,mishra2022reframing}.

There are important artifact precedents, and this paper treats them as context rather than as targets to out-claim. Set-of-Mark prompting already pairs textual mark references with visual marks \citep{yang2023som}; SeeAct explores marked-screenshot web-agent grounding \citep{zheng2024seeact}; and Magma incorporates related SoM-style and action-grounding ideas into an omni-modal agent model \citep{yang2025magma}. These systems show that marked observations, textual references, and multimodal action grounding are not new merely as artifacts. The contested point is different: whether the behavior of the image-skipped configurations has been scientifically isolated, compared against DOM/SoM/Vision on identical task pools, and explained behaviourally (the mechanistic account is deferred to a follow-up paper).

The resulting gap is therefore a characterization gap, not a first-deployment gap. Published systems and benchmarks have not, to our knowledge, provided a controlled scientific evaluation of the phantom boundary: `[SOM_MARKS]` isolated from the screenshot, crossed with prompt family in a 2-by-2 control, compared through low-overlap success pools and drop-one oracle value, and explained by a behavioural two-knob account (text-representation × prompt-family) across three baselines (B0 Qwen3-VL-235B-A22B, B1 Qwen3-VL-4B, B2 Gemma3-VL 4B cross-family control). This is also where the 4-fold drop-in property belongs. It is an empirical finding about a controlled configuration: zero image tokens, no new model, usable routing signal, and positive incremental oracle value. Mid-layer mechanism analysis (activation patching, layer probes, logit lens) is deferred to a follow-up paper per advisor 2026-05-14; the present paper does not claim a preregistered mechanism circuit. It is not a claim that text-only browser control or marked observations were first introduced here.

Our contributions follow directly. We define **Phantom-SoM** as the deployment-relevant representative of the phantom routing space: marks text plus SoM prompt family, with the image removed. We show empirically (on archived pre-fire runs; Phase 1a clean-rerun confirmation pending) that Phantom-SoM is not a degenerate DOM surrogate: it contributes independent oracle value and has substantial task-pool non-overlap with DOM, SoM, and Vision. The P-text and P-prompt controls establish specificity by separating text-payload flattening from prompt-family effects, rather than attributing all gains to a single novel arm. We then provide a behavioural two-knob account — representation format shapes exploration, while prompt wording tunes commitment confidence — and a cost-aware router that exploits the phantom space (a learned per-task classifier, Section 6; rule-based escalation and cascade composition are deferred to a follow-up paper per the v7 walk-back). This motivates the experimental design in Section 3, the controlled evidence in Section 4, and the routing results in Section 6. **Scope clarification (B-1290 /stress A2.6b P1-10-AC 2026-05-18, Claude Mode A + gemini Mode C 2-AI overlap):** the gap this paper fills is **representation-level routing for textual-flattening-vs-nested-hierarchy on AXTree-style observations in VWA-style SoM-scaffolded multimodal web agents** — not a general claim about representation-level routing across arbitrary LLM systems or observation modalities. The positioning above situates the gap within four established literatures; broader applicability to other observation paradigms (raw screenshot, pixel-coordinate, audio-grounded agents) or other system classes (cross-document QA, robotics, multimodal VQA) is registered as future work (see §1 footnote `[^scaffolding-class-scope]` for the agent-scaffolding bound + §8 future-work paragraph for the cube-concept generalizability speculation).
