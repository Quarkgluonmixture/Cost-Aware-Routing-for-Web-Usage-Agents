## 2. Sidecar 大模型逐任务诊断（2026-04-05） [infra]

利用 GLM-5.1 作为 sidecar 模型对每个 episode 进行自动诊断（step log + AXTree 片段输入），生成结构化归因。示例：

> **phase1_dom_router_0 / task_133** — 交互失败
>
> - **脚手架缺陷**：否
> - **目标**：找到最旧的 Xbox 游戏集合并评分
> - **诊断**：Agent 发现结果按"最新"排序，却试图通过滚动查找"最旧"商品，未使用排序功能调整顺序。
> - **证据**：步骤 5 thought 提到 *"listings are sorted by newness, so I should scroll to see older listings"*，表明 Agent 在已知排序方式错误的情况下选择了无效的滚动策略，未尝试寻找排序控件。

共完成 DOM 模式 211 条自动归因 + 2 条人工补充（task_184、task_187），置信度 96.7% high / 3.3% medium。

## 3. 程序化失败模式分析（2026-04-05） [finding]

`analyze_reason_diagnostics.py` 对 213 条 DOM 失败 episode 自动归因：

| 失败类型 | 数量 | 占比 | 平均步数 |
|----------|------|------|----------|
| 目标不可达 | 61 | 28.6% | 17.3 |
| 搜索循环 | 42 | 19.7% | 19.3 |
| 导航循环（click-back 死循环） | 30 | 14.1% | 28.0 |
| 执行停滞 | 23 | 10.8% | 7.0 |

| 事实推理错误 | 17 | 8.0% | 7.5 |
| 视觉属性 DOM 不可达 | 9 | 4.2% | 18.6 |

根因归属：脚手架/表征缺陷 109（51.2%，avg 16.8 步）vs 模型能力问题 104（48.8%，avg 14.0 步）。步数浪费热点：搜索+导航循环合计 ~1,649 步；视觉类任务若能提前路由可再省 ~1,676 步。对 Phase 2 影响：循环检测信号和视觉任务分流是主要 headroom 来源。

## 4. 手动逐模式分析（2026-04-06） [finding]

详见 `docs/analysis/classifieds/B1_DOM_digest.md` 和 `B1_SOM_digest.md`。

**DOM**：脚手架缺陷 109 例（51.2%），其中视觉不可达 99 例（91%）；95% 详情页 AXTree 无商品描述；理论上限 ~55%（非视觉任务占比），实际 adjusted SR 仅 0.85%（见 §20）。

**SoM**：四类结构性缺陷——标注遮挡（~200×170px mark 覆盖缩略图）、空间布局丢失（多列 grid→一维序列）、深度滚动 ID 幻觉、text-over-vision bias（30 例，占 86%，4B 模型系统性忽略截图依赖文字标签）。后续修正（§23）：Mirage Effect 是 SoM >> DOM 的主因，非文本差异。

## 5. busy:1 中间态问题发现与修复（2026-04-04） [bug]

症状：VWA `networkidle timeout=2000` 过短，远程站经常半加载，DOM 含 `busy:1`，LLM 推理已浪费后才覆盖 action 为 wait。旧 Run：DOM 11.8%/SoM 24.5% 步数被侵蚀，SoM 受影响 task 高达 80.1%（处理链更长）。修复：busy:1 检查提到 LLM 调用前，且免费等待不计 max_steps（`runner.py`）。修后两模式均降至 0%。

## 7. Logprobs 置信度信号提取（2026-04-07） [infra]

在 `qwen3vl_agent.py` 中实现 `_compute_confidence()`（`output_scores=True`），提取 6 个指标：`mean_logprob`/`min_logprob`（绝对信心）、`mean_margin`/`min_margin`（top-1 vs top-2 区分度）、`mean_entropy`/`max_entropy`（§15 新增，分布散度）。关键设计决策：entropy 与 margin 互补——margin 只看 top-2 差距，entropy 捕获多候选散射场景。

分析脚本 `analyze_confidence_calibration.py` 已就绪，实际 token-level AUROC = 0.497（接近随机），Phase 2 路由改用行为信号（详见 §24）。

## 8. 延迟数据不可比性说明（2026-04-07） [design]

`total_latency_ms` 和 `p95_step_latency_ms` 受 GPU 争抢影响，不能直接用于跨时段比较。DOM 和 SoM 是串行执行的——DOM 先跑完（争抢少），SoM 后跑（争抢多），两个 condition 的延迟不具可比性。后续分析中不将延迟作为跨 condition 对比指标。

## 9. 表征选择与模型能力的交互效应（2026-04-07） [finding]

Read More, Think More（论文 [2]）发现：高能力模型用 HTML 反而更好（+17.5pp），低能力模型用 a11y 更好。这和我们在 SoM 上观察到的 text-over-vision bias 是同一个底层现象——**最优表征不是绝对的，是模型能力的函数**。

这意味着 Phase 2 router 的理论框架可以更丰富：不只是"根据任务难度选表征"，而是"根据任务难度 × 模型能力选表征"。在单模型（4B）实验里这个交互效应看不到，但如果后续引入 B0（API 模型），可以直接测试：4B 用 DOM 最好的任务，API 模型是不是用 SoM 反而更好？如果是，router 就不只是 cost-aware，而是 **capability-aware**。

## 18. Mirage Effect 与 Text-Over-Vision Bias（2026-04-09） [literature]

Mirage 论文（Asadi et al., arXiv:2603.21687, Stanford, 2026-04）：VLM 无图时仍自信描述视觉特征，无图准确率达有图的 70-80%（mirage-mode > guess-mode）。P79 映射：

| Mirage 论文发现 | B1 实验观察 |
|---|---|
| 无图准确率 70-80% 有图 | DOM 模式 90.5% "成功"是 visual lucky hits |
| Mirage-mode > Guess-mode | SoM-without-image bug 成功率反而提升 |
| 消息格式触发推理路径切换 | SoM prompt 暗示截图存在 → 激活隐藏文本-视觉关联 |

**Phantom-SoM 路由中间层**：DOM（Guess-mode）→ Phantom-SoM（SoM marks 文本+无图，Mirage-mode，成本≈DOM）→ Full SoM（真实多模态）。第一次升级零成本，第二次才付图片成本。理论根基：为 text-over-vision bias 提供机制解释；`(SoM-DOM)_B0 > (SoM-DOM)_B1` 可直接验证模型规模对 mirage 的调节作用。消融设计见 §25。→ `docs/literature/phantom_som.md`

## 25. Phantom-SoM Ablation：混淆变量分析与消融设计（2026-04-10） [literature]

DOM↔SoM 有三层混淆变量：① prompt（DOM 无坐标 schema，SoM 有坐标 fallback）、② 文本格式（AXTree 层级树 vs SoM marks 扁平列表）、③ 图片暗示（SoM prompt 提及 screenshot）。需 5 组设计分解：

**消融矩阵**：

| 组 | Prompt | 文本内容 | 图片 | 隔离目标 |
|---|---|---|---|---|
| **A: DOM baseline** | DOM prompt | AXTree | 无 | 基准（复用 B1 数据） |
| **B: Phantom-SoM** | SoM prompt | SoM marks | 无 | ①+②+③ 混合 |
| **C: Full SoM** | SoM prompt | SoM marks | 有 | 纯图片贡献（复用 B1 数据） |
| **D: DOM-text + SoM-prompt** | SoM prompt | AXTree | 无 | 纯 ① prompt/scaffold 效应 |
| **E: SoM-text + DOM-prompt** | DOM prompt | SoM marks | 无 | 纯 ② 格式效应 |

因果分解：`D-A`=纯 prompt，`E-A`=纯格式，`C-B`=纯图片，`B-D-E+A`≈mirage。**D 是最关键判别组**：Scaffold Effect（Vu & Balloccu 2026 — prompt 仅提及 MRI 可用就解释 70-80% 性能变化）提示 D≈B 则效果全来自 prompt 层，非 mirage。

样本量：A/C 复用 B1 数据（234 tasks），B+D（+可能 E）各 234 tasks（paired McNemar test，FDR q=0.05）。实现前提：解耦 `observation_mode`（当前原子选择），支持 prompt/obs 交叉组合。P79 novelty：首个 intra-model observation-mode routing 研究 + 系统性四因素消融 + 把 mirage effect 当 feature 而非 bug。→ `docs/literature/phantom_som.md`

## 31. click vs type 混淆与 baseline retry 副作用（2026-04-11） [finding][bug]

### 问题

Agent 在需要输入内容时（如价格筛选）用 `click` 而非 `type`。当前 wrapper 的 `type` 已自带"click 聚焦 → Meta+A 清空 → keyboard.type"完整流程，agent 无需先 click 再 type。三模式 prompt 均未说明 `type` 自动聚焦、`click` 仅用于按钮/导航。

### baseline_retry_on_no_progress 定量评估

Runner 在 click/type 后 `page_changed=false` 时自动注入一次 scroll down。

| 模式 | Retry 触发率 | Retry 后 page_changed=true |
|------|-------------|--------------------------|
| DOM | 6.7%（235/3495 步） | **100%** |
| SoM | 9.7%（270/2760 步） | **100%** |
| Vision | 9.6%（27/280 步） | **100%** |

100% retry scroll 后页面必然变化（无信息量）。失败 episode 中有 retry 者平均多浪费 **8 步**——因 retry 的 page_changed=true 清空 soft cycle signatures，**阻止早停机制触发**。对成功 episode 影响小（89-95% 会切换 element，但 agent 自己也会 scroll）。

**五个问题**：100% 假阳性；破坏 cycle detection；三模式不公平（Vision scroll 后坐标全部失效）；破坏输入框焦点；agent 无跨步自纠正能力（task 48 验证：misclick 后以相同坐标重复点击，auto-scroll 无"重试机会"可抢）。

**修复**：prompt 加明确 type 语义（§33 实施）；`baseline_retry_on_no_progress` 默认改为 False（§33 实施）。
