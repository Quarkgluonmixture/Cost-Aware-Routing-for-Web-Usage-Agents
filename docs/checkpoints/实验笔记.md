## 4. 手动逐模式分析

对 DOM 和 SoM 模式分别进行了人工分析，结论见 `docs/analysis/classifieds/`：

### DOM 模式（`B1_DOM_digest.md` §四）

**脚手架/DOM 结构性缺陷（109 例，51.2%）**：
1. **视觉信息结构性不可达** — DOM 不含图片语义，颜色/款式匹配类任务结构性无法完成（99 例，占 scaffold 缺陷的 91%）
2. **非视觉脚手架问题**（10 例）— 筛选器 UI 定位困难、AXTree 信息不足、JS 弹窗不可达等

**模型能力问题（104 例，48.8%）**：搜索循环（29）、导航循环（18）、事实推理错误（15）、过早结束（12）等

**信息瓶颈**：95% 的详情页 AXTree 不包含商品描述文本。DOM 模式理论成功率上限约 55%。

### SoM 模式（`B1_SOM_digest.md` §二）

**SoM 表征结构性缺陷（4 类）**：
1. **标注遮挡** — 青色 mark 框覆盖缩略图左上角（~200×170px），遮挡关键视觉区域
2. **空间布局丢失** — marks 为线性序号列表，多列 grid 退化为一维序列
3. **深度滚动 ID 幻觉** — viewport 外元素无 mark，模型引用不存在的 ID
4. **text-over-vision bias（30 例，占 86%）** — 4B VLM 系统性忽略截图视觉细节，依赖 `[SOM_MARKS]` 文字标签决策。SoM 对小模型反而提供了"不看图的捷径"

> **关键发现**：SoM 表征对模型视觉能力有最低门槛要求。4B 模型上 SoM ≈ DOM（文字主导），与 GPT-4V 上 SoM 有效性的文献结论形成对比。

## 5. busy:1 中间态问题发现与修复

实验运行中发现 VWA 底层的 `wait_for_load_state("networkidle", timeout=2000)` 超时过短，远程 Classifieds 站点经常来不及加载完，导致 DOM 包含 `busy: 1` 标记。

**原始实现的问题**：busy:1 检查在 LLM 调用之后，仅覆盖 action 为 wait，但 LLM 推理（tokens + latency）已经浪费：

```
1. 拿到 obs（busy:1 的半加载页面）
2. 准备 SoM（只有 1 个 mark）
3. 调用 LLM 推理 ← 浪费
4. 检查 busy:1 → 覆盖 action 为 wait
```

**旧 Run 影响量化**：

|                           | DOM        | SoM        |
|---------------------------|------------|------------|
| busy:1 步数占比           | 11.8%      | 24.5%      |
| 受影响 task 比例          | 55.6%      | 80.1%      |
| 到 max_steps 失败的 task 平均浪费步数 | 4.7 步（15.7%） | 9.8 步（32.8%） |

SoM 的 busy:1 率是 DOM 的 2 倍——SoM 处理链更长（截图 → CDP bbox → 标注渲染），更容易在 2s 内来不及加载完。这是一个**公平性问题**：SoM 的有效步数预算被 busy:1 大量侵蚀，DOM vs SoM 的成功率对比被污染。

**修复方案**（已实现并验证）：将 busy:1 检查提到 LLM 调用之前，且 busy:1 步不计入 max_steps 预算（免费等待）。重跑后 DOM 和 SoM 的 busy:1 占比均降至 **0%**。

## 7. Logprobs 置信度信号提取

实验中途加入了 logprobs 提取模块，作为 Phase 2 confidence-based routing 的前置依赖。

### 为什么必须做

文献中两篇直接相关工作验证了 logprobs 在 cost-aware agent 中的基础设施地位：

| 论文 | logprobs 用法 | 效果 |
|------|--------------|------|
| **AVR**（Adaptive Vision-Language Routing, arXiv:2603.12823） | VLM grounding 坐标的 logprob 作为置信度，低于阈值 → 升级到更强模型/表征 | ScreenSpot-Pro 上成本降低 78%，准确率仅降 0.8pp |
| **CATTS**（Agentic Test-Time Scaling, arXiv:2602.12276） | margin-gated confidence（top-1 − top-2 logprob），低 margin → 多采样 + 语义去重投票 | WebArena-Lite 上 token 消耗降低 56%，成功率反升 4.7% |

### 对 P79 的三个不可替代角色

1. **路由决策的量化依据**：当前 router 仅依赖 DOM 节点数量和连续无变化步数（外部观测），logprobs 直接回答"模型对当前 action 有多确信"
2. **小模型置信度校准的研究空白（文献 Gap 6）**：4B 模型的 logprob 是否与成功率单调相关？是否 overconfident？Phase 1 数据可填补此空白，构成论文 Section 4.2 的实证贡献
3. **Phase 2 阈值设定的数据基础**：500+ 步的 (logprob, success) 样本可用 ROC 曲线精确设定路由阈值，避免凭经验盲设

### 实现情况

已在 `qwen3vl_agent.py` 中实现 `_compute_confidence()` 方法（`output_scores=True, return_dict_in_generate=True`），提取四个指标：
- `mean_logprob` / `min_logprob`：平均/最低 log probability
- `mean_margin` / `min_margin`：平均/最小 top-1 与 top-2 gap

分析脚本 `analyze_confidence_calibration.py` 已就绪，待 Reddit 站点跑完后进行校准分析，输出包括 reliability diagram、ECE/MCE、AUROC 等。

## 8. 延迟数据不可比性说明

`total_latency_ms` 和 `p95_step_latency_ms` 受 GPU 争抢影响，不能直接用于跨时段比较。DOM 和 SoM 是串行执行的——DOM 先跑完（争抢少），SoM 后跑（争抢多），两个 condition 的延迟不具可比性。后续分析中不将延迟作为跨 condition 对比指标。

## 9. 表征选择与模型能力的交互效应

Read More, Think More（论文 [2]）发现：高能力模型用 HTML 反而更好（+17.5pp），低能力模型用 a11y 更好。这和我们在 SoM 上观察到的 text-over-vision bias 是同一个底层现象——**最优表征不是绝对的，是模型能力的函数**。

这意味着 Phase 2 router 的理论框架可以更丰富：不只是"根据任务难度选表征"，而是"根据任务难度 × 模型能力选表征"。在单模型（4B）实验里这个交互效应看不到，但如果后续引入 B0（API 模型），可以直接测试：4B 用 DOM 最好的任务，API 模型是不是用 SoM 反而更好？如果是，router 就不只是 cost-aware，而是 **capability-aware**。

## 10. 数据质量保障

### 任务重启去重

Watchdog 重启会在 JSONL 中产生重复行（step_idx 从 0 重置）。已创建统一的 `io_utils.read_jsonl_dedup()` 函数，替换了 5 处独立实现，所有分析脚本均自动去重。

### VWA 结构性不可达任务

在 VWA 中发现了一批结构性不可达任务（`<select>` 三层过滤 bug、viewport 限制等），Agentic Web 评测框架中是直接绕过的。我们的处理方式：

- **判定标准**：同一 task 在所有 condition（dom + som + vision）下均失败 → 强候选 structurally unsolvable
- **区分假阳性**：若有 B0 强模型 baseline，可交叉验证；否则同时报告 raw 和 adjusted 成功率
- **实施方式**：纯数据驱动，等三站全部跑完后在分析脚本中一行 `groupby` 即可算出，不需修改 runner 或 hardcode 列表

```
raw success rate:      X%  (N tasks)
adjusted success rate: Y%  (N - K tasks, excluding K tasks failed across all conditions)
```

### N/A Reference Task 假阳性

VWA 的 `ua_match` 评测器使用 LLM 判断 agent 答案是否与 reference 语义匹配。当 reference 答案为 "N/A"（不可回答类任务）时，agent 未调用 `finish` 而由 runner 自动追加的空 answer（`create_stop_action("")`）也能通过匹配，产生虚假成功。

**影响范围**：Classifieds 站 234 个 task 中有 11 个 N/A reference task，部分可能因空 answer 匹配 "N/A" 而获得假阳性。

**修复方案**：
- `analysis.py` 中新增 `_load_na_task_ids(site)`，扫描 VWA task config 中 `eval.reference_answers.fuzzy_match == "N/A"` 的 task
- `ep_df` 中标记 `is_na_reference` 列，输出 `na_reference_tasks.csv`
- `analysis_summary.json` 中同时报告 `raw_success_rate` 和 `adjusted_success_rate`（排除 N/A 假阳性）

### Type 操作全选变蓝

VWA 底层 Playwright 的 `type` 方法在执行搜索框输入时，偶尔导致页面文本被全选高亮（蓝色覆盖）。选区从输入框扩散到整个页面，后续截图中所有文本呈蓝色高亮状态（如 task_17 step 9）。

**影响**：DOM 模式无影响（读 AXTree 不看截图）；SoM/Vision 模式会严重干扰视觉理解。属于 VWA/Playwright 环境层面已知行为，详见 `docs/analysis/classifieds/B1_overall.md` 第 4 节。

## 12. Cycle Detection 误杀修复

发现 strict cycle detection 会把连续 3 次相同方向的 scroll（page_changed=True）误判为死循环并早停。实际上页面在正常滚动，agent 在浏览搜索结果。

**影响**：classifieds 站 3 个 task（6/16/18）被误杀，已删除 summary 触发重跑。

**修复**：scroll + page_changed=True 时不加入 strict signatures，保留 soft 检测作为兜底。

  3. 清理 digest 中的旧记录（基于过期 cookie 的归因无效）

- **"新完成"推送修复**：task ID 子串匹配从 `"in k"` 改为 `endswith(exact_filename)`，修复 task 3 匹配 task 30 的误报

## 15. Predictive Entropy 信号补充（2026-04-09）

### 文献调研结论

基于 8 篇相关文献的系统调研（见 `docs/literature/logprob_signals.md`），核心发现：

1. **原始 logprob 不可靠**：小 VLM 的 raw token logprob 校准差，分布偏移时过度自信，多步轨迹中误差累积
2. **校准是关键**：temperature scaling 或 learned mapping 在 held-out set 上校准后，logprob 才适合做路由信号
3. **Entropy 与 margin 互补**：margin 只看 top-2 差距（分布是否尖锐），entropy 看整个分布散度（捕捉"top tokens 都不确定"的情况）
4. **Semantic entropy / attention entropy**：前沿但证据不足，不值得在 4B 模型上投入

### 新增指标

在 `_compute_confidence()` 中增加两个 predictive entropy 指标：
- `mean_entropy`：各 token 预测熵的均值（H = −∑ p log p），衡量整体不确定性
- `max_entropy`：最大单 token 熵，标识最不确定的决策点

计算开销几乎为零（复用已有的 `log_softmax` 结果，一行 `-(probs * log_probs).sum()`）。

### 数据覆盖

| 数据段 | 有 entropy | 估计量 |
|--------|-----------|--------|
| DOM classifieds 0-186 | ❌ | 186 tasks |
| DOM classifieds 187-233 | ✅ | 48 tasks |
| SoM / Vision classifieds | ✅ | 468 tasks |
| 其他 3 站 × 3 模式 | ✅ | ~2100 tasks |

>95% 的未来数据将包含 entropy 指标。分析脚本对缺失 entropy 的旧 episode 自动跳过（optional field）。

### 完整置信度信号集（6 指标）

| 信号 | 维度 | 用途 |
|------|------|------|
| mean_logprob / min_logprob | 绝对信心 | 模型对 action 的整体/最弱信心 |
| mean_margin / min_margin | 区分度 | top-1 vs top-2 的选择确定性 |
| mean_entropy / max_entropy | 分布散度 | 全分布不确定性（捕捉 margin 遗漏的多候选散射） |

Phase 2 路由计划：B1 全部跑完 → `analyze_confidence_calibration.py` 评估 AUROC → held-out set 上 temperature scaling → percentile-based 阈值设定。

## 18. Mirage Effect 与 Text-Over-Vision Bias（2026-04-09）

### 文献关联

Mirage 论文（Asadi et al., arXiv:2603.21687, Stanford, 2026-04）发现 VLM 在**完全没有收到图片**时，依然能自信地描述视觉特征并在多模态 benchmark 上取得 70-80% 的原始准确率。论文称之为 "mirage effect"——模型构建虚假的感知叙事，表现得好像图片存在。

这一发现与 B1 实验中的三个独立观察形成 1:1 对应：

| Mirage 论文发现 | B1 实验观察 |
|---|---|
| VLM 无图仍自信描述视觉特征 | DOM 模式 8.97% 成功率中 90.5% 是 visual lucky hits——模型无视觉输入，纯靠文本线索导航到正确页面 |
| 无图准确率达有图的 70-80% | SoM text-over-vision bias：4B 模型系统性忽略截图，依赖 `[SOM_MARKS]` 文字标签决策 |
| Mirage-mode > Guess-mode（假装有图 > 明确告知无图） | SoM 曾因 bug 未传入图片（仅 SoM marks 文本），成功率反而提升 |

### Mirage-mode vs Guess-mode 机制

论文 Section 4.1 揭示了两种不同的推理机制：

- **Guess-mode**（对应 DOM 模式）：模型意识到没有图像 → 保守的纯文本推理，依赖先验和答案分布
- **Mirage-mode**（对应 SoM-without-image bug）：消息结构暗示图像存在 → 模型进入不同推理路径，利用训练中学到的隐藏文本-视觉关联模式

论文原文：*"In mirage-mode, the model appears able to exploit additional hidden structure... it behaves as though an image exists, constructs a plausible perceptual narrative, and in doing so accesses cues or associations that are not captured by standard 'no-image guessing' controls."*

SoM-without-image 的消息格式（`[SOM_MARKS]` 列表 + 暗示截图存在的结构）恰好触发了 mirage-mode，激活了比 DOM 模式更强的推理路径。

### Phantom-SoM：一种低成本的路由中间层

这个发现暗示了一种非正统的路由策略——在 DOM 和完整 SoM 之间插入一个"幻影 SoM"层：

| 模式 | 内容 | 成本 | 推理模式 |
|---|---|---|---|
| DOM（cheap） | AXTree 纯文本 | 低 | Guess-mode |
| **Phantom-SoM**（cheap） | SoM marks 文本 + **无图** | ≈ DOM | Mirage-mode |
| Full SoM（expensive） | SoM marks + 截图 | 高 | 真实多模态 |

路由链：`DOM → [confidence low?] → Phantom-SoM → [still low?] → Full SoM`。第一次升级几乎零成本（只改文本格式），第二次升级才付出图片成本。

### 局限性

1. **利用训练 artifact**：mirage effect 是 VLM 联合训练的副作用，不是真实能力。模型特异性强——4B 上可能有效（text-over-vision 本来就强），235B 上可能反而有害（大模型可能真的在用视觉信息）
2. **不可解释性**：难以向 reviewer 解释"故意不传图片让模型产生视觉幻觉来提升成功率"
3. **Benchmark 污染**：如果 VWA 的 `url_match` 评测让无图模式也能得高分，说明 benchmark 本身有 mirage 漏洞

### 对论文的价值

即使不作为正式路由策略，这个发现有三个方向的贡献：

1. **独立复现 Mirage 效应**（Section 4 Analysis）：在交互式 web agent 场景（非静态 QA）中观察到 mirage effect，比论文的 benchmark QA 场景更强
2. **为 text-over-vision bias 提供理论根基**：之前只有经验观察（"4B 模型不看图"），Mirage 论文提供了机制解释——这是 VLM 联合训练的系统性 artifact
3. **B0 vs B1 的 mirage 强度对比**：如果 235B 的 mirage effect 更弱（真的在用视觉信息），那 `(SoM - DOM)_B0 > (SoM - DOM)_B1`，直接支撑"最优表征是模型能力的函数"假设
4. **Phantom-SoM ablation**：小规模（~50 tasks）ablation 即可量化 4B 模型对视觉信息的真实依赖度，insight 密度高、成本低

### 后续计划

- 等 B1 三模式 + B0 初步数据就绪后，补做 Phantom-SoM ablation（~50 tasks classifieds）
- 对比 B0 vs B1 的 `SoM成功率 - DOM成功率` 差值，量化模型规模对 mirage effect 的调节作用

## 19. Tool Calling 线性电路与 Action Selection（2026-04-09）

### 文献关联

"Tool Calling is a Linear, Steerable Circuit in Language Models"（Anonymous ACL submission, 2026）发现 LLM 的 tool 选择决策住在残差流的一个低维线性子空间中。论文**明确测试了 Qwen 3 4B**（B1 使用的同一模型家族），主要发现：

1. **15 个 tool 只需 ~10 个方向**即可分离（PCA top-10 捕获 90.2% 方差）
2. **三阶段流水线**：早期层（0-10%）→ tool-specific 特征激活；中间层（50-80%）→ attention head 从 context 读取 tool name 和实体 token；晚期层（85-100%）→ 线性子空间中做最终选择
3. **Steering 有效**：加一个 mean-difference 方向向量可以 80-93% 准确率切换 tool 选择，模型自动重写整个 JSON argument 以匹配新 tool
4. **模型"知道"但"说不出"**：base model 内部已编码正确 tool（77-89%），但生成输出只有 3-61%。Instruction tuning 教会模型表达已有知识
5. **Error prediction**：top-2 tool 的 cosine gap 小 → 错误率高。标记低于中位数的 gap 可捕获 92% 的错误

### Action Type = Tool Selection

P79 agent 的输出 `{"action_type": "click", "element_id": 175}` 在结构上就是 tool calling：

- `action_type` ∈ {click, type, scroll, wait, back, forward, finish, tab_focus} = **8 个 tool**
- `element_id` / `text` / `delta` = **tool arguments**

论文对 Qwen 3 4B 的发现（steering 在 L23+ 有效，PCA 90.2%）直接适用于 B1 的 action selection。8 个 action type 比论文的 15 tool 更少，线性子空间可能只需 ~7 维。

### 对 Phase 2 路由的启示：表征层置信度信号

| 信号层级 | 信号 | 来源 | 优势 | 限制 |
|---|---|---|---|---|
| 输出层（当前） | logprob / margin / entropy | token 概率 | B1 + B0 均可用 | Mirage 论文表明可能过度自信 |
| **表征层**（论文） | action type 间 cosine gap | 倒数第二层 activation | 直接测量决策确定性，不受输出层校准影响 | 需白盒访问，仅 B1 可用 |

论文的 cosine gap 信号比 logprob 更强：它在模型内部决策层面直接测量"click 和 scroll 谁赢"的确信度，绕过了输出层的校准问题。对 Phase 2 router，如果 logprob 校准不够好（4B 模型大概率如此），activation-level cosine gap 可作为补充路由信号。

### 解释 B1 观察到的失败模式

"模型知道但说不出来"直接解释了两个系统性失败：

- **极少 scroll up**（B1_DOM_digest §5）：DOM 模式 scroll up 仅 3.7%（24/646），SoM 为 11.2%（48/430）。模型不是完全不会，但在需要主动回翻的场景下严重不足。视觉信息帮助感知空间位置（SoM 3x），说明内部表征可能存在但输出层激活不充分
- **未点进详情页就 finish**（§2.3）：模型内部犹豫在 click 和 finish 之间，但 finish 方向在输出层更容易被选中

### Cosine Select + Generate ↔ M4 两阶段模块

论文的流水线：(1) 从 activation 读取 tool 身份 → (2) 填入 tool name → (3) 模型只生成 arguments。

这和 Phase 3 M4（planner + grounder）结构等价：
- Planner = cosine select（决定 action_type）
- Grounder = generate（生成 element_id、text 等参数）

论文证明 action selection（线性）和 argument generation（非线性）的分离在 Qwen 3 4B 上 match 或 beat 端到端生成，为 M4 设计提供了 mechanistic 理论支撑。

### 与 Mirage 论文的交叉

| 论文 | 发现 | 对应 P79 启示 |
|---|---|---|
| Mirage | 消息格式影响推理模式 | Phantom-SoM：改格式触发多模态推理路径 |
| Tool Calling | Action selection 线性可操控 | 在 residual stream 加方向向量修正 action type |

组合后的极端方案：不换观测模式、不重新推理——在 Qwen 3 4B 的 L23 层加方向向量，增强 scroll up 方向的激活（当前 DOM 3.7% / SoM 11.2%，仍有很大提升空间）。零额外 token 成本。需要白盒访问 + 预计算方向向量，超出当前范围但作为 future work 有吸引力。

### 对论文的实际价值

**可直接引用**：
1. M4 两阶段设计的理论基础——action selection 和 argument generation 的分离有 mechanistic 证据
2. Output-level confidence 之外存在 representation-level 信号（discussion 中补充）
3. Qwen 3 4B 的具体数据直接可引用（steering L23+, PCA 90.2%）

**Future work——离线 Activation 提取与信号评估**：

核心思路：B1 baseline 已有全部 episode 数据（observation + prompt + success label），**不需要重跑实验、不需要环境交互**。离线对已有输入做 forward pass（不 generate），截取中间层 hidden states 即可。

**Step 1：离线 Forward Pass 提取 Activation**
- 从已有 episode JSONL 读取每步的 observation（DOM text / SoM image）+ 完整 prompt
- 喂给 Qwen 3 4B 做一次 forward pass（`output_hidden_states=True`，不调 `generate`）
- 保存倒数 3-5 层的 last-token hidden state（~4096 dim × 5 层 × float16 ≈ 40KB/step）
- 预计规模：234 tasks × ~10 steps ≈ 2300 次 forward，4B 模型在 GB10 上几分钟

**Step 2：Action Type 子空间 PCA**
- 按 action_type 标签分组（click/type/scroll/finish/...），计算各组 mean activation
- PCA 降维，测量 8 个 action type 需要多少维度分离（论文 15 tool → 10 维，预期 8 action → ~7 维）
- 可视化 action type 在子空间中的分布

**Step 3：Cosine Gap 路由信号评估**
- 计算每步 top-2 action type 方向的 cosine gap
- 和已有 output-level 信号（logprob margin / entropy / verbalized confidence）做 AUROC 对比
- 预期：cosine gap 在 4B 模型上显著优于 logprob margin（因为输出层校准差，但内部表征可分性强）
- 若验证成功，cosine gap 可作为 Phase 2 router 的补充/替代信号

**Step 4（可选）：Activation Steering 修正系统性偏差**
- 预计算方向向量：`scroll_up - scroll_down`、`click - finish` 的 mean-difference
- 在 forward pass L23+ 层注入方向向量，测试能否翻转 action 选择
- 零额外 token 成本，零额外推理调用——只需在 forward 中间插一个向量加法
- 目标：修正 "69/69 scroll 全部向下"、"premature finish" 等系统性偏差

**关键约束**：仅对 B1（本地白盒模型）可行，B0（API）无法访问 intermediate activations。这反而强化了 cost-aware routing 的价值——本地小模型可以做 API 做不到的 representation-level 优化。

## 20. Visual False Positive 检测接入 Cross-Representation Analysis（2026-04-09）

### 问题

DOM 模式 21 个成功 episode 中有 **19 个是假阳性**——visual task（需要看图/辨颜色/匹配图片的任务）在无图的 DOM 模式下碰巧通过文本匹配得分（`url_match` 类评测器只检查 URL 是否到达目标页，agent 碰巧导航到了正确页面）。

这导致所有 cross-representation 分析指标严重失真：

| 指标 | Raw（失真） | Adjusted（修正后） |
|------|------------|-------------------|
| DOM SR | 9.0%（21/234） | **0.85%（2/234）** |
| Oracle ceiling（union SR） | 12.4% | **4.7%** |
| DOM 独占成功集（only_dom） | 19 tasks | **1 task** |
| Best single mode | dom | **som** |
| R3 oracle DOM 选择数 | 20 | **2** |

修正前 DOM 看起来是最强模式、oracle ceiling 看起来有 12.4%，实际上绝大部分 DOM "成功" 都是假阳性。

### 检测逻辑

复用 `p79/experiment/analysis.py` 已有的 `_load_visual_task_ids(site)` 函数，该函数通过两个信号检测 visual task：
1. Task config 中有 `image` 字段（显式图片输入任务）
2. Task intent 包含视觉关键词（`_VISUAL_TASK_KWDS`：颜色词、"in the image"、"same item" 等）

假阳性标记规则：**仅 DOM 模式**——visual task + success = false positive。SoM（有截图）和 Vision（有截图）的 visual task 成功是真阳性。

### 三站 Visual Task 比例

| 站点 | has_image（显式图片任务） | kwd_only（颜色/外观关键词） | 非视觉 | visual 合计 |
|------|--------------------------|----------------------------|--------|------------|
| classifieds | 68 (29%) | 94 (40%) | 72 (31%) | 162 (69%) |
| reddit | 150 (71%) | 27 (13%) | 33 (16%) | 177 (84%) |
| shopping | 169 (36%) | 100 (21%) | 197 (42%) | 269 (58%) |
| **合计** | **387 (43%)** | **221 (24%)** | **302 (33%)** | **608 (67%)** |

VWA 三站合计 **67% 的任务是 visual task**，其中 43% 是显式图片任务，24% 是颜色/外观关键词匹配。

### kwd_only 标记的合理性验证

初看之下，"find the cheapest blue kayak" 这类 `kwd_only` 任务似乎可以纯文本解决——颜色只是筛选条件，标题里应该写着 "Blue Kayak"。但实际实验观察表明，**这些任务在 DOM 模式下同样结构性不可达**，原因有三：

1. **详情页缺乏颜色确认信息**：agent 点进了正确的商品详情页，但 DOM（AXTree）中没有颜色描述文本。agent 无法确认当前商品是否符合颜色要求，认为"不是白色车"而退出，陷入无效循环
2. **商品标题不含颜色关键词**：卖家发布时写的是 "Toyota Camry 2019" 而非 "White Toyota Camry 2019"，颜色信息只存在于商品图片中。DOM 的 AXTree 里完全没有颜色线索，agent 在列表页就无法选中正确的商品
3. **站内搜索匹配失败**：agent 几乎必然会搜索 "white car" 这样包含颜色的具体搜索词，但站内搜索基于标题关键词匹配——标题里没有 "white"，搜索结果为零，任务从搜索阶段就直接卡死

这三个机制说明：**在 classifieds/shopping 类电商站上，颜色等视觉属性在结构化数据（标题、描述、DOM）中是系统性缺失的，只存在于商品图片里**。因此 `kwd_only` 标记没有过度，当前的 visual FP 检测逻辑是准确的。

### VWA Benchmark 的视觉偏重与现实场景的差异

VWA 67% visual task 比例显著高于真实 Web 使用场景。现实中大量 Web 任务是纯文本的（搜索信息、填写表单、阅读文档、管理账户等），真正需要图片理解的任务占比远低于 67%。这意味着：

## 23. DOM vs SoM 差距根因修正（2026-04-10）

### 背景

B1 Classifieds DOM adjusted SR = 0.9%，SoM SR ≈ 19.8%（96 episodes 完成时），差距巨大。需要准确归因 SoM 的优势来源，以指导 Phase 2 路由设计。

### 错误假设的纠正

最初提出三个假设解释 SoM >> DOM，经实证验证后其中两个被推翻：

| 假设 | 结论 | 证据 |
|------|------|------|
| ~~文本压缩 10-20x~~ | **错误** | 实际 DOM = 2326 chars vs SoM = 2377 chars（task_0 step_000 artifacts），内容完全一致，仅格式不同（缩进树 vs `[id=N]` 扁平列表） |
| ~~Coordinate fallback 兜底~~ | **非主因** | SoM 模式碰到下拉菜单交互同样全部陷入循环，坐标兜底在实际中未被有效利用 |
| **Mirage Effect** | **确认为主因** | 与 §18 分析一致：图片存在触发不同推理路径，模型行为模式质变（scroll up 从 DOM 3.7% 提升至 SoM 11.2%，回退策略更丰富） |

### Prompt 差异与公平性

三模式 prompt 的关键差异：

```
DOM:  "ALWAYS use element_id. Do NOT guess coordinates."
SoM:  "Prefer element_id. Use coordinate only when the target is visible
       in the image but has no ID in [SOM_MARKS]."
      + Click by coordinate (fallback) action
```

**结论：当前设计公平。** 理由：

1. **Phase 1 是配置筛选，不是单变量消融** — 每个模式是完整的"配置包"（文本格式 + 适配 prompt + 图片），目的是筛选最优配置往 Phase 2 带
2. **Prompt 差异是功能必需** — DOM 没有图片，给坐标动作没有意义；SoM 有图片，自然需要坐标 fallback
3. **变量隔离由 Phantom-SoM ablation 负责**（§18 已规划）：
   - Phantom-SoM（SoM prompt + SoM text + 无图）vs DOM → 隔离 prompt/格式 的贡献
   - Phantom-SoM vs Full SoM → 隔离图片的贡献

### 修正后的因果模型

```
DOM 模式                          SoM 模式
  AXTree 文本 ≈ SOM_MARKS 文本     (文本信息量相同)
  无图片                            有截图（带标注）
  "你只有文本"                      "你有文本+图片"
       ↓                               ↓
  Guess-mode 推理                   Mirage-mode 推理
  (保守、纯文本先验)                (激活隐藏的文本-视觉关联)
       ↓                               ↓
  SR = 0.9% (adjusted)             SR ≈ 19.8%
```

SoM 的优势**几乎完全来自 Mirage Effect**：相同的文本信息，仅因图片存在（以及暗示图片存在的 prompt 结构），模型进入了质变的推理路径。

### 对 Phase 2 路由设计的影响

- DOM ↔ SoM 路由无意义：routing headroom (adjusted) = 0.4%，DOM 独占成功仅 1 个 task
- 有意义的路由方向：Phantom-SoM ↔ Full SoM（成本差在图片，推理路径可能相近）
- Phantom-SoM ablation 优先级提升：不仅是机制验证，更是 Phase 2 路由可行性的前置实验

## 25. Phantom-SoM Ablation：混淆变量分析与消融设计（2026-04-10）

### 问题

§18 提出的 Phantom-SoM（SoM marks 文本 + 无图）效果，如果存在，无法直接归因于 mirage effect。DOM 和 SoM 之间存在**三层混淆变量**：

| 层 | DOM | SoM / Phantom-SoM | 差异性质 |
|---|---|---|---|
| ① **Prompt** | "Use element IDs from Accessibility Tree"，无坐标 action | "You receive [SOM_MARKS] + screenshot"，含坐标 fallback schema | Action space 扩大 |
| ② **文本格式** | `Accessibility Tree:\n` + 完整 AXTree | `[SOM_MARKS]...[/SOM_MARKS]` 标注块 | 信息编码方式不同 |
| ③ **图片暗示** | Prompt 未提及图片 | Prompt 明确说"A screenshot — normally with bounding boxes" | Mirage trigger |

直接对比 Phantom-SoM vs DOM 是 ①+②+③ 的混合效应，无法分离 mirage effect 的真实贡献。

### Prompt 差异的具体影响

**坐标 fallback 是最大的混淆因素：**

- DOM prompt（line 139）：`ALWAYS prefer element_id. Only use coordinate as last resort.` 但 action schema 中**没有给坐标格式**，模型事实上无法输出坐标动作
- SoM prompt（line 200-201）：`Click by coordinate (fallback): {"action_type": "click", "coordinate": [x, y], "coordinate_type": "normalized"}` 明确给出了坐标 action schema
- 这意味着 SoM 模式下模型在 element_id 匹配不上时有**额外操作通路**——这是纯 action space 差异，与 mirage 无关

**文本格式的潜在影响：**

- AXTree 是层级缩进结构，包含所有节点（含不可交互节点）
- SoM marks 是扁平列表，只包含可交互元素 + 短描述
- 虽然 §23 已确认 token 量级相当（DOM 2326 ≈ SoM 2377 chars），但信息密度和结构不同，可能激活不同的 pretrain 知识路径

### 消融矩阵设计

| 组 | Prompt | 文本内容 | 图片 | 隔离目标 |
|---|---|---|---|---|
| **A: DOM baseline** | DOM prompt | AXTree | 无 | 基准 |
| **B: Phantom-SoM** | SoM prompt | SoM marks | 无 | ①+②+③ 混合（原计划） |
| **C: Full SoM** | SoM prompt | SoM marks | 有 | ③→真实视觉 vs B |
| **D: DOM-text + SoM-prompt** | **SoM prompt** | **AXTree** | 无 | 纯 ① prompt 效应 |
| **E: SoM-text + DOM-prompt** | **DOM prompt** | **SoM marks** | 无 | 纯 ② 格式效应 |

**因果分解：**

- `B - A` = prompt + 格式 + mirage 混合效应
- `D - A` = 纯 prompt 效应（坐标 fallback action space 的贡献）
- `E - A` = 纯文本格式效应（SoM marks vs AXTree 的信息结构差异）
- `B - D` = 在 SoM prompt 下，SoM marks 相对 AXTree 的增量贡献（② given ①）
- `B - E` = 在 SoM marks 下，SoM prompt 相对 DOM prompt 的增量贡献（① given ②）
- `C - B` = 纯图片贡献（真正的 mirage isolation：声称有图 vs 真的有图）

### 实验 D 详细设计：DOM-text + SoM-prompt

**目的：** 隔离 SoM prompt 中坐标 fallback action space 对性能的影响。如果 D ≈ B，说明 prompt（坐标 fallback）才是主因，mirage effect 不成立。

**实现方式：**
- 使用 `_make_som_prompt()` 生成的 system prompt（含坐标 fallback schema、"screenshot" 提及）
- 文本观测使用 DOM 模式的 AXTree（`Accessibility Tree:\n` + obs_text）
- 不传入图片
- 需要在 `qwen3vl_agent.py` 中新增 `observation_mode="phantom_dom"` 分支，或在 runner 层做 prompt/obs 组合覆盖

**预期结果与解读：**
- `D ≈ A`：坐标 fallback 无用（模型没有图就不会用坐标），prompt 差异不是主因
- `D > A`：坐标 fallback 偶尔命中（随机坐标点击到目标），或 prompt 中"screenshot"暗示激活了 mirage
- `D ≈ B`：SoM marks 文本格式没有额外贡献，全部效果来自 prompt

### 实验 E 详细设计：SoM-text + DOM-prompt

**目的：** 隔离 SoM marks 文本格式对推理质量的影响。SoM marks 是可交互元素的扁平列表，比 AXTree 更聚焦——这种信息结构差异可能本身就足以改善决策质量，无需 mirage effect。

**实现方式：**
- 使用 `_make_dom_prompt()` 生成的 system prompt（无坐标 fallback、无 screenshot 提及）
- 文本观测使用 SoM 标注块（`[SOM_MARKS]...[/SOM_MARKS]`）
- 不传入图片
- prompt 中 element_id 引用仍然有效（SoM marks 也用 `[id=N]` 格式）
- 需要调整 prompt 中 "Accessibility Tree" 的措辞为更通用的描述，或保持原样（模型应能理解列表格式）

**预期结果与解读：**
- `E ≈ A`：SoM marks 格式本身无优势，信息内容等价
- `E > A`：扁平列表（只含可交互元素）比层级 AXTree（含全部节点）更利于 4B 模型决策——信息过滤/压缩有贡献
- `E ≈ B`：prompt 差异（坐标 fallback）没有额外贡献，全部效果来自文本格式

### 文献综述关键发现（2026-04-10，详见 `docs/literature/phantom_som.md`）

基于 SciSpace 深度调研（43 篇论文，6 个主题），以下发现直接影响消融设计：

#### Scaffold Effect：最大威胁

Vu & Balloccu (2026, [19]) 发现**仅在 prompt 中提及 "MRI 可用" 就能解释 70-80% 的表观性能变化**，与实际是否传入图片无关。这直接命中 Phantom-SoM 场景——SoM prompt 写了 "You receive a screenshot with bounding boxes"，这句话本身可能就是 Phantom-SoM 效果的主要驱动力，而非 mirage effect。

**→ 实验 D 变成了整个消融中最关键的判别组：它同时包含 scaffold（prompt 提及截图）和 action space（坐标 fallback），如果 D ≈ B，则 SoM marks 文本格式无额外贡献，效果全部来自 prompt 层。**

#### 额外混淆因素确认

| 混淆源 | 文献支撑 | 影响 |
|--------|----------|------|
| **Element ordering** | Chi et al. [17]：随机化元素顺序的性能下降**等同于删除可见文本** | AXTree 层级 vs SoM marks 扁平列表的排序差异是独立混淆因素 |
| **Action space** | Szot et al. [15]：action adapter 选择**显著改变** agent 性能和 grounding 保真度 | 坐标 fallback vs element-ID 是独立于观测模式的性能驱动力 |
| **Prompt framing** | Verma et al. [14]：ReAct prompting 的表观增益主要来自 exemplar-query 相似度，非推理链本身 | 需要控制 prompt 中与观测模式无关的措辞差异 |

#### 文献空白 → P79 novelty

综述确认 6 个 gap，其中 3 个直接对应 P79 贡献：

1. **Gap: Intra-model observation-mode routing** — 无人做过同一 VLM 内切换观测模式（DOM/SoM/Vision）的路由研究。现有 cascading 全是 inter-model（小模型→大模型）。P79 是第一个。
2. **Gap: 系统性四因素消融** — 无人同时消融 prompt + 格式 + action space + modality。个别因素有独立研究，但无 factorial design 覆盖全部。5 组设计填补此空白。
3. **Gap: 把 mirage effect 当 feature** — 现有文献全部把 text-over-vision bias 当 bug 来修（M3ID [5]、attention amplification [6]、VA-neuron detection [2]）。P79 反其道而行之，利用 bias 省成本。

#### 路由信号候选

| 信号 | 来源 | 成本 | 与 P79 关系 |
|------|------|------|------------|
| Linear probes on mid-layer activations | Pacchiardi [37]：中间层线性探针预测答案正确性 | 零（forward pass 内） | 需要白盒访问，4B 本地模型满足 |
| BrowseConf verbalized confidence | Ou et al. [35]：web agent 的 verbalized confidence 与准确率强相关 | 零（已在输出中） | B1 token-level AUROC=0.497 已失败，verbalized 是否不同待验证 |
| WebArbiter step-level PRM | Zhang et al. [29]：step-level 过程奖励模型 | 高（7B verifier） | 4B actor 旁跑 7B 太贵，不适合 B1 |
| VA-neuron detection | Kim et al. [2]：检测视觉缺失 token | 低（探针） | 可作为 Phantom-SoM → Full SoM 升级信号 |

#### Task 54 案例佐证

SoM 模式下 task 54（"Find the most recently listed item related to this game I used to play"，带参考游戏截图）的 30 步 trajectory 证实了 text-over-vision bias：

- 模型知道有图（Step 13/17/19 提到 "as seen in the screenshot of the game"）
- 但**从未识别出图片中的游戏名称**，无法用图片内容做匹配
- 决策完全靠文本线索（"Newly listed" 排序→选第一个），图片形同虚设
- 陷入 item 详情页↔列表页的死循环（30 步中 20+ 步重复相同模式）

这是 4B 模型 text-over-vision bias 在参考图场景下的直接体现，支撑 Phantom-SoM（无图）与 Full SoM（有图）对 4B 效果接近的假设。

### 样本量修正

文献建议 n ≥ 200/组（1000 total）检测 Cohen's d ≈ 0.3 的小效应（[19] scaffold effect 分析）。原计划 50/组不足。

**修正方案：复用 B1 baseline 数据 + 自适应停止。**

- **A 组**：复用 B1 DOM baseline 全部 234 tasks（不需重跑）
- **C 组**：复用 B1 SoM baseline（目前 135 tasks 已完成，最终 ~234 tasks）
- **B/D/E 组**：使用与 A/C 相同的 task set，确保 paired comparison
- 实际新增工作量：B + D（+ 可能的 E）= 234×2 ~ 234×3 = **468-702 tasks**

**paired design 优势**：同一 task 跨组配对比较，所需样本量大幅下降（paired t-test 控制 task 内变异），234 tasks 的 paired comparison 统计功效远优于 200 tasks 的 independent comparison。

**统计方法**：
- 主要分析：McNemar's test（paired binary outcomes）或 paired permutation test
- 多重比较校正：Benjamini-Hochberg FDR（q=0.05），10 个 pairwise comparison
- 报告：uncorrected + FDR-corrected p-values + Cohen's d + 95% CI

### 决策树（修正版）

```
Phase 1: 跑 B + D（各 234 tasks，与 A/C paired）
         ↓
D ≈ B ?  （McNemar test, FDR-corrected）
├── YES → 结论：prompt/action-space 是主因（scaffold effect 确认）。
│         Phantom-SoM 效果 = prompt 效应，非 mirage。
│         → 无需跑 E，但发现本身有价值（scaffold effect 在 web agent 中的首次量化）
│
└── NO → D ≈ A ?
    ├── YES → prompt 无贡献。跑 E 分离格式 vs mirage。
    │         E ≈ B → 格式是主因（SoM marks 信息过滤/压缩的贡献）
    │         E ≈ A → mirage 是主因（prompt 暗示图片存在触发推理路径变化）
    │
    └── MIDDLE → prompt 有部分贡献（D 显著优于 A 但劣于 B）。
                 跑 E 做三方分解：效应 = prompt_share + format_share + mirage_share
```

### 实现注意事项

1. **A 组不需重跑**：直接复用 B1 DOM baseline 数据
2. **C 组不需重跑**：直接复用 B1 SoM baseline 数据
3. **B/D/E 使用相同 task set**：与 A/C 完全 paired，消除 task 难度变异
4. 需要在 agent 或 runner 层支持 prompt/observation 的交叉组合，当前代码 observation_mode 是一个原子选择，需要解耦
5. **Element ordering 控制**：E 组的 SoM marks 喂给 DOM prompt 时需保持与 B 组相同的元素排序策略，避免引入新混淆（[17]）
6. **Scaffold 控制组（可选）**：如果资源允许，增加 D' 组——SoM prompt **去掉 "screenshot" 提及** + AXTree + 无图——进一步分离 scaffold effect 和 action space effect

### 26.1 动机

B1 token-level confidence（logprob-based）的 AUROC 仅 0.497-0.566，接近随机，无法用于 routing 决策。文献中 verbalized confidence（模型在输出 JSON 中自我报告 0.0-1.0 置信度）在部分场景下表现优于 token-level 信号，且与 logprob 弱相关，适合作为补充或替代信号。

### 26.2 实现变更

**Prompt 修改**（`qwen3vl_agent.py`, `qwen_api_agent.py`）：
- 在三种模式（dom/som/vision）的 JSON schema 中新增 `"confidence": 0.0 to 1.0` 字段
- 明确语义：`your self-assessed probability (0.0–1.0) that this action makes meaningful progress toward the task goal`

- 从 `action["confidence"]` 提取，clamp 到 [0,1]，写入 `step_record["confidence"]["verbalized"]`

## 27. N/A 任务评测深度分析与 ua_match 根因（2026-04-10）

### 背景

Classifieds 站有 10 个 N/A reference task（24, 135, 164, 167, 189, 191, 194, 195, 196, 220），reference answer 均为 "N/A"。此前分析（B1_overall.md §7）声称 "DOM 10/10 误判为 success，SoM 0/10"——经逐任务核实，**SoM 已完成的 9 个 N/A task 同样全部 score=1.0**，原结论有误（当时 SoM 多数 N/A task 未跑完）。

### 10 个 N/A Task 逐任务判定

| Task | Reference 不可行原因 | SoM 步数 | SoM 结束方式 | FP 类型 |
|------|-------------------|---------|-------------|---------|
| 24 | Miles not listed for this car | 15 | page_unchanged_streak | Type A（空 answer） |
| 135 | No pink items on the page | 24 | finish("Light Pink Depression Glass Candy Dish") | Type B（离开起始页搜索到的） |
| 164 | No yellow items on the page | 8 | finish(item 5636 URL) | Type B（搜索 "yellow car" 找到的） |
| 167 | No green instruments on the page | 30 | max_steps | Type A |
| 189 | No items with Mario | 6 | page_unchanged_streak | Type A |
| 191 | No blonde horse items | 5 | page_unchanged_streak | Type A |
| 194 | No Mickey Mouse items | 6 | finish("Mickey Mouse item not found") | 特殊* |
| 195 | No yellow motorcycles ≥$25k | 12 | page_unchanged_streak | Type A |
| 196 | No red trucks MD ≥$50k | 30 | max_steps | Type A |
| 220 | Only red microwave doesn't turn on | — | 未完成 | — |

\* Task 194 是唯一 agent 真正理解不可行性的 case（confidence=0.0），但提交了自然语言而非精确 "N/A"。

**Reference 验证**：task_135 和 task_164 通过起始页 AXTree + 截图验证，起始页确实不含 pink/yellow item。Agent 违反了 intent 中 "on this page" 约束，导航到其他页面找到了匹配 item。Reference N/A 全部正确。

### ua_match LLM Judge 根因分析

评测流程（`evaluators.py:257-270`）：N/A task 先 exact_match "N/A" → 失败 → 调 `llm_ua_match` 语义判断。

`llm_ua_match` prompt（`helper_functions.py:621-631`）将 agent answer 包装为 `reported unachievable reason`，要求 GPT-4o-mini 判断是否与 `actual unachievable reason`（string_note）一致，"even if implicitly"。

**三个缺陷**：
1. **字段名误导**：agent answer 被标记为"失败原因"，但 agent 实际在提交成功答案
2. **"even if implicitly" 过于宽松**：空 answer 被解读为"隐式表示做不到"；错误答案被脑补为"隐式说明目标不存在"
3. **缺前提验证**：prompt 预设 agent 知道任务不可行，但 agent prompt 无 N/A 出口（Rule 4: "NEVER give up"）

判定逻辑也有偏差：只要 GPT-4o-mini 回复不含 "different" 就返回 1.0，默认倾向是通过。

### Agent Prompt 无 N/A 出口

Agent prompt 中：
- Rule 1: "Do NOT answer or finish immediately. You MUST navigate to find the item."
- Rule 4: "NEVER give up early."
- Finish action 定义无 "如果不可行，answer 填 N/A" 的说明

结果：agent 在 N/A task 上必然循环到被截断 → 空 answer → ua_match FP。DOM 和 SoM 走同一条路径，FP 机制完全一致。

### 对 adjusted SR 的影响

10 个 N/A task 全部是 visual task，已被 `_mark_visual_false_positives()` 从 adjusted SR 中扣除。**ua_match FP 不影响 adjusted 数字**，但影响 raw SR 和模式间 N/A 行为的对比分析。

### Task 192 评测严格性边界案例

非 N/A task。Intent: "tell me the primary color of the cars"，reference: must_include ["red", "white"]。

SoM agent thought: "shows two cars: one red and one white. The red car is prominently displayed"，但 answer 只写 "red"。模型视觉理解完全正确（识别了两个颜色），因 "primary color" 理解为"主色"而非"各车主色"，answer 不完整导致 score=0。属于 answer 格式/语义理解边界问题。
