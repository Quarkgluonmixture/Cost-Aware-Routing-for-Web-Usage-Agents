## 写作规范

> **原则**：笔记是**索引+关键结论**，不是详细记录。详细分析放 `docs/analysis/`，文献综述放 `docs/literature/`。每个 § 写完后按此检查，超限则压缩。

| `[bug]` | **3-5 行** | 症状 → 根因（1 句）→ 修复文件 → 影响数字 |

## 2. Sidecar 大模型逐任务诊断（2026-04-05） [infra]

利用 GLM-5.1 作为 sidecar 模型对每个 episode 进行自动诊断（step log + AXTree 片段输入），生成结构化归因。示例：

> **phase1_dom_router_0 / task_133** — 交互失败
>
> - **脚手架缺陷**：否
> - **目标**：找到最旧的 Xbox 游戏集合并评分
> - **诊断**：Agent 发现结果按"最新"排序，却试图通过滚动查找"最旧"商品，未使用排序功能调整顺序。
> - **证据**：步骤 5 thought 提到 *"listings are sorted by newness, so I should scroll to see older listings"*，表明 Agent 在已知排序方式错误的情况下选择了无效的滚动策略，未尝试寻找排序控件。

共完成 DOM 模式 211 条自动归因 + 2 条人工补充（task_184、task_187），置信度 96.7% high / 3.3% medium。

## 7. Logprobs 置信度信号提取（2026-04-07） [infra]

在 `qwen3vl_agent.py` 中实现 `_compute_confidence()`（`output_scores=True`），提取 6 个指标：`mean_logprob`/`min_logprob`（绝对信心）、`mean_margin`/`min_margin`（top-1 vs top-2 区分度）、`mean_entropy`/`max_entropy`（§15 新增，分布散度）。关键设计决策：entropy 与 margin 互补——margin 只看 top-2 差距，entropy 捕获多候选散射场景。

## 18. Mirage Effect 与 Text-Over-Vision Bias（2026-04-09） [literature]

Mirage 论文（Asadi et al., arXiv:2603.21687, Stanford, 2026-04）：VLM 无图时仍自信描述视觉特征，无图准确率达有图的 70-80%（mirage-mode > guess-mode）。P79 映射：

| Mirage 论文发现 | B1 实验观察 |
|---|---|
| 无图准确率 70-80% 有图 | DOM 模式 90.5% "成功"是 visual lucky hits |
| Mirage-mode > Guess-mode | SoM-without-image bug 成功率反而提升 |
| 消息格式触发推理路径切换 | SoM prompt 暗示截图存在 → 激活隐藏文本-视觉关联 |

**Phantom-SoM 路由中间层**：DOM（Guess-mode）→ Phantom-SoM（SoM marks 文本+无图，Mirage-mode，成本≈DOM）→ Full SoM（真实多模态）。第一次升级零成本，第二次才付图片成本。理论根基：为 text-over-vision bias 提供机制解释；`(SoM-DOM)_B0 > (SoM-DOM)_B1` 可直接验证模型规模对 mirage 的调节作用。消融设计见 §25。→ `docs/literature/phantom_som.md`

## 19. Tool Calling 线性电路与 Action Selection（2026-04-09） [literature]

"Tool Calling is a Linear, Steerable Circuit"（ACL 2026）在 Qwen 3 4B 上验证：15 tool → 10 方向（PCA 90.2%），cosine gap 低 → 错误率高（捕获 92% 错误），steering L23+ 层可 80-93% 准确率切换 tool，"知道但说不出"（内部 77-89% 正确，输出 3-61%）。

P79 映射：

| 论文发现 | P79 对应 | 价值 |
|---------|---------|------|
| Action type = tool（8类） | click/type/scroll 等 | Qwen 3 4B 数据直接可用 |
| Cosine gap 预测错误 | Phase 2 表征层路由信号（仅 B1 白盒） | 绕过输出层校准问题 |
| Action selection（线性）+ argument generation（非线性）分离 | M4 两阶段：planner（cosine select）+ grounder（generate）| mechanistic 理论支撑 |
| "知道但说不出" | scroll up 3.7%→11.2% 系统性偏低 | future work：L23 steering 修正 |

Future work：离线 forward pass（`output_hidden_states=True`，~2300 次，无需重跑环境）提取 activation → PCA cosine gap → AUROC 对比 logprob（仅 B1 白盒可行）。

## 25. Phantom-SoM Ablation：混淆变量分析与消融设计（2026-04-10） [literature]

DOM↔SoM 有三层混淆变量：① prompt（DOM 无坐标 schema，SoM 有坐标 fallback）、② 文本格式（AXTree 层级树 vs SoM marks 扁平列表）、③ 图片暗示（SoM prompt 提及 screenshot）。需 5 组设计分解：

**消融矩阵**：

| 组 | Prompt | 文本内容 | 图片 | 隔离目标 |
|---|---|---|---|---|
| **A: DOM baseline** | DOM prompt | AXTree | 无 | 基准（复用 B1 数据） |
| **B: Phantom-SoM** | SoM prompt | SoM marks | 无 | ①+②+③ 混合 |
| **C: Full SoM** | SoM prompt | SoM marks | 有 | 纯图片贡献（复用 B1 数据） |
| **D: DOM-text + SoM-prompt** | SoM prompt | AXTree | 无 | 纯 ① prompt/scaffold 效应 |
| **E: SoM-text + DOM-prompt** | DOM prompt | SoM marks | 无 | 纯 ② 格式效应 |

因果分解：`D-A`=纯 prompt，`E-A`=纯格式，`C-B`=纯图片，`B-D-E+A`≈mirage。**D 是最关键判别组**：Scaffold Effect（Vu & Balloccu 2026 — prompt 仅提及 MRI 可用就解释 70-80% 性能变化）提示 D≈B 则效果全来自 prompt 层，非 mirage。

样本量：A/C 复用 B1 数据（234 tasks），B+D（+可能 E）各 234 tasks（paired McNemar test，FDR q=0.05）。实现前提：解耦 `observation_mode`（当前原子选择），支持 prompt/obs 交叉组合。P79 novelty：首个 intra-model observation-mode routing 研究 + 系统性四因素消融 + 把 mirage effect 当 feature 而非 bug。→ `docs/literature/phantom_som.md`

## 53. confirm 弹窗自动接受修复（2026-04-14） [bug]

## 72. Scroll 跨模型/跨 API 验证（2026-04-16） [finding]

**目标**：判定 B0 scroll 单向性（96% down-only）是 (a) Bedrock proxy artifact，(b) Qwen3-VL 模型行为，还是 (c) prompt/环境通病。

**实验设计**：20 个 scroll-heavy classifieds tasks，SoM 模式，三条线控制变量：

| 条件 | 模型 | API | 目的 |
|------|------|-----|------|
| Claude SoM | Claude Sonnet 4.6 | Bedrock proxy（免费） | 跨模型对比 |
| DashScope SoM | Qwen3-VL-235B-instruct | DashScope 官方（免费额度） | 跨 API 对比 |
| B0 Qwen DOM | Qwen3-VL-235B | Bedrock proxy | 已有 baseline |

**代码改动**：`proxy_api_agent.py` 新增 `api_format`（anthropic/openai）+ `api_key_env` + `image_format` 自动检测（Claude→anthropic_native，其他→openai image_url）；`api_proxy.py` 透传新字段。

**核心结果**（10 个共享 task）：

| 指标 | DashScope 官方 | Qwen proxy DOM | Claude SoM |
|------|---------------|----------------|------------|
| SR | **50% (5/10)** | 30% (3/10) | 30% (3/10) |
| Scroll up 比例 | 3.2% | 6.9% | **36.2%** |
| Stuck scroll | 19.4% | 26.4% | **0%** |
| Parse error | 0% | 0% | 0% |

**结论**：
1. **Scroll 单向性 = Qwen3-VL 模型行为**：DashScope 官方 3.2% ≈ proxy 6.9%，同模型不同 API 一致；Claude 38%，差异 10 倍
2. **Stuck scroll = 模型行为**：DashScope 19.4% ≈ proxy 26.4%，Claude 0%（到底部即停）
3. **Claude 20 tasks 全集**：SR 40% (8/20) vs Qwen DOM 20% (4/20)；平均 12.4 步 vs 24.9 步；成本/episode $0.070 vs $0.102
4. DashScope SR 略高于 proxy（50% vs 30%），可能因官方推理更稳定

**决策：B0 继续使用 Bedrock proxy + Qwen3-VL-235B**。理由：(1) proxy 免费，DashScope 收费且免费额度已用 69%；(2) 两套 API scroll 表现一致（3.5% vs 3.2%），parse error 均为 0，API 不是差异来源；(3) DOM 和 Vision 已跑完 234 tasks，切换意味着全部重跑；(4) 同系列 weak→strong（Qwen-4B→235B）路由是原始研究设计，换 Claude 改变实验变量。Claude 20 tasks 数据作为 discussion 素材保留。

**文件**：`configs/exp_v2_scroll_test_claude.yaml`、`configs/exp_v2_scroll_test_dashscope.yaml`、`scripts/dgx/run_scroll_comparison.sh`
