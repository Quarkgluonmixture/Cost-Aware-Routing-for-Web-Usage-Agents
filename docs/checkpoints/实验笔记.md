## 写作规范

> **原则**：笔记是**索引+关键结论**，不是详细记录。详细分析放 `docs/analysis/`，文献综述放 `docs/literature/`。每个 § 写完后按此检查，超限则压缩。
> **[finding] 不写正文**：实验发现直接写入对应 digest 文件，笔记索引表保留一行 + 正文仅写 `→ 见 {digest}` 指针。

| 类型 | 行数上限 | 格式要求 |
|------|---------|---------|
| `[bug]` | **3-5 行** | 症状 → 根因（1 句）→ 修复文件 → 影响数字 |
| `[finding]` | **1 行** | `→ 见 {digest 文件路径}` 指针，正文写入 digest |
| `[literature]` | **8-12 行** | 核心主张（1-2 句）→ P79 映射表（≤3 行）→ `docs/literature/` 指针 |
| `[infra]` | **5-10 行** | 构建了什么 → 关键设计决策 → 影响范围 |
| `[design]` | **8-15 行** | 背景（1 句）→ 关键决策 → 依据 → 开放问题 |

**周报原则**：正文直接给出可摘录的完整句子；不写验证过程、不粘贴代码、不写"后续计划"（已在行动规划）。

## 18. Mirage Effect 与 Text-Over-Vision Bias（2026-04-09） [literature]

Mirage 论文（Asadi et al., arXiv:2603.21687, Stanford, 2026-04）：VLM 无图时仍自信描述视觉特征，无图准确率达有图的 70-80%（mirage-mode > guess-mode）。P79 映射：

| Mirage 论文发现 | B1 实验观察 |
|---|---|
| 无图准确率 70-80% 有图 | DOM 模式 90.5% "成功"是 visual lucky hits |
| Mirage-mode > Guess-mode | SoM-without-image bug 成功率反而提升 |
| 消息格式触发推理路径切换 | SoM prompt 暗示截图存在 → 激活隐藏文本-视觉关联 |

**Phantom-SoM 路由中间层**：DOM（Guess-mode）→ Phantom-SoM（SoM marks 文本+无图，Mirage-mode，成本≈DOM）→ Full SoM（真实多模态）。第一次升级零成本，第二次才付图片成本。理论根基：为 text-over-vision bias 提供机制解释；`(SoM-DOM)_B0 > (SoM-DOM)_B1` 可直接验证模型规模对 mirage 的调节作用。消融设计见 §25。→ `docs/literature/phantom_som.md`

## 19. Tool Calling 线性电路与 Action Selection（2026-04-09） [literature]

"Tool Calling is a Linear, Steerable Circuit"（ACL 2026）在 Qwen 3 4B 上验证：15 tool → 10 方向（PCA 90.2%），cosine gap 低 → 错误率高（捕获 92% 错误），steering L23+ 层可 80-93% 准确率切换 tool，"知道但说不出"（内部 77-89% 正确，输出 3-61%）。

## 25. Phantom-SoM Ablation：混淆变量分析与消融设计（2026-04-10，§100 后修订 2026-04-26） [literature]

DOM↔SoM 有三层混淆变量：① prompt（DOM 无坐标 schema，SoM 有坐标 fallback）、② 文本格式（AXTree 层级树 vs SoM marks 扁平列表）、③ 图片暗示（SoM prompt 提及 screenshot）。需 5 组设计分解：

**消融矩阵**（修订版）：

| 组 | Prompt | 文本内容 | 图片 | 隔离目标 |
|---|---|---|---|---|
| **A: DOM baseline** | DOM prompt | AXTree | 无 | 基准（复用 B1 数据） |
| **B: Phantom-SoM** | SoM prompt | SoM marks | 无 | ①+②+③ 混合 |
| **C: Full SoM (broken)** | SoM prompt | SoM marks | 当前实现（含 occlusion bug） | 当前 baseline，复用现有数据 |
| **C': Full SoM (fixed)** | SoM prompt | SoM marks | occlusion 修复后 | 纯图片贡献（**B vs C' 才是干净对比**） |
| **D: DOM-text + SoM-prompt** | SoM prompt | AXTree | 无 | 纯 ① prompt/scaffold 效应 |
| **E: SoM-text + DOM-prompt** | DOM prompt | SoM marks | 无 | 纯 ② 格式效应 |

**§100 引出的 occlusion confound**：当前 SoM 实现存在结构性 occlusion bug（标签实心填充覆盖元素文字前 3-6 字符，§100 probe 实测 B0 在 reddit_task_6 上 OCR recall 78% → 18%）。**B vs C 直接对比污染**——即使 B > C，不能 claim "无图更好"，因 C 的图本身被破坏。引入 C'（修复 occlusion 后的 Full SoM）作为干净 baseline。

因果分解（修订版）：
- `D-A`=纯 prompt 效应
- `E-A`=纯文本格式效应
- `C'-B`=**干净的"图片贡献"**（不再用 C-B）
- `C-C'`=occlusion bug 的 cost
- `B-D-E+A`≈mirage（phantom 的 SR 收益超出 prompt + 格式之外的部分）

**D 仍是最关键判别组**：Scaffold Effect（Vu & Balloccu 2026 — prompt 仅提及 MRI 可用就解释 70-80% 性能变化）提示 D≈B 则效果全来自 prompt 层，非 mirage。

**实施前置**：
1. **C' 的实现需要修 SoM occlusion bug**（`som.py:_draw_label`：半透明 + 优先外侧标签位置）。但**生产代码 som.py 不应轻易改**——颜色 `#00BCD4` 是 commit `5f0952b` 调整后的设计（消除红框颜色 confound），全局改会污染 in-flight 实验数据一致性。建议：（a）先用 §100 mode-NoMarks 数据判断 occlusion 修复是否值得做（如果 NoMarks 已能解释反转，说明标签存在本身是负担，C' 边际收益小）；（b）如果决定做 C'，用独立渲染函数（不修 production som.py），仅作 isolated D 实验
2. 解耦 `observation_mode`（当前原子选择），支持 prompt/obs 交叉组合 —— D/E 的实现前提

样本量：A/C 复用 B1 数据（234 tasks），B+C'+D（+可能 E）各 234 tasks（paired McNemar test，FDR q=0.05）。

P79 novelty：首个 intra-model observation-mode routing 研究 + 系统性四因素消融 + 把 mirage effect 当 feature 而非 bug。→ `docs/literature/phantom_som.md`

## 51. select_option action type 实现 + bid 陷阱修复（2026-04-14） [bug][infra]

  - `select_option` coordinate 路径（Vision）：归一化坐标 → 像素 → 同上 JS 路径

- `p79/backends/action_utils.py`：`ALLOWED_ACTION_TYPES` 加 `select_option`；`validate_action()` 验证

## 72. Scroll 跨模型/跨 API 验证（2026-04-16） [finding]

## 80. VWA viewport ratio 计算 bug — 修复与重跑（2026-04-19） [bug]

**Bug**：`external/visualwebarena/browser_env/processors.py:218` 运算符优先级错误：
```python
# 前: ratio = overlap_width * overlap_height / width * height   # ((ow*oh)/w)*h → 远超 1.0
# 后: ratio = (overlap_width * overlap_height) / (width * height)  # 面积比 0~1
```
阈值 `IN_VIEWPORT_RATIO_THRESHOLD=0.6` 形同虚设，任何 1px 可见的元素全部保留完整文本。

**双层影响**（DOM 和 SoM 共享同一 filtered AXTree，对称受影响；Vision 不受影响）：

**修复后阈值 0.6 的数学保证**：ratio ≥ 0.6 → 元素中心必在 viewport 内（证明：center_y ≤ 720 - 0.1h < 720），功能性失败完全消除。语义误导大幅缓解（<60% 可见元素被排除），残余不公平是 DOM 元素级全有/全无的结构性限制。

**决策：修复 + 重跑所有 DOM/SoM condition**（B0+B1，所有站点）。Vision 不受影响不需重跑。
- 修改：`processors.py:218` 加括号，一行改动

## 89. Visual FP 公平性论证：Non-visual Subset + WA 平衡（2026-04-23） [finding]

**背景**：导师质疑 visual FP 过滤是否不公平——(1) DOM 模式"误打误撞"完成了 visual task，也算完成了任务；(2) DOM 天然无法完成 visual task，在 VWA 67% visual 占比下对比不公平。

### 论点 1：Visual FP 是方法论正确的

DOM 模式在 visual task 上的 success 不可归因于 agent 能力：
- **信息通道不存在**：AXTree 无颜色/图案/图像内容，agent 根本无法做出正确的视觉判断
- **成功来自评测机制碰巧**：`url_match` 只查 URL、`string_match` 的 GPT-4o-mini 容错高，首个搜索结果碰巧匹配即得分
- **不可复现**：换 seed/初始状态后大概率失败

类比：盲人答对视力表不能说明视力正常。

### 论点 2：Non-visual subset 证实 DOM 劣势不依赖 visual task

在完全不需要视觉信息的 non-visual 子集上，DOM 仍显著落后：

**B0 Classifieds**（72 个 non-visual tasks / 234 总）：

| 模式 | Adjusted SR (全集 224) | Non-visual SR (72) |
|------|----------------------|-------------------|
| DOM | 8.48% | **1.39%** |
| SoM | 20.98% | **15.28%** |
| Vision | 12.05% | — |

**B1 Classifieds**（72 个 non-visual tasks / 234 总）：

| 模式 | Adjusted SR (全集 224) | Non-visual SR (72) |
|------|----------------------|-------------------|
| DOM | 4.91% | **0.42%** |
| SoM | 13.84% | **13.89%** |
| Vision | 7.14% | **6.94%** |

DOM 在 non-visual subset 上 SR 0.42%~1.39%，远低于 SoM 13.89%~15.28%。这说明 DOM 的劣势是结构性的（Mirage Effect §23、viewport 信息密度 §80），不仅是 visual task 不公平所致。

### 论点 3：WA 引入从实验设计层面缓解占比偏斜

| 方案 | 总 tasks | Visual | Non-visual | Visual 占比 |
|------|---------|--------|-----------|-----------|
| VWA only | 910 | ~608 | ~302 | **67%** |
| VWA + WA | ~1390 | ~608 | ~782 | **44%** |

WA 480 个 task 全部为 non-visual（`_load_visual_task_ids(benchmark='webarena')` 返回空集），引入后 visual 占比从 67% 降至 44%，给 DOM 充分展示能力的空间。

### 各站 visual task 占比

| 站点 | 总 tasks | Visual tasks | 占比 |
|------|---------|-------------|------|
| VWA Classifieds | 234 | 162 | 69.2% |
| VWA Reddit | 210 | 177 | 84.3% |
| VWA Shopping | 466 | 269 | 57.7% |
| WA Shopping | 192 | 0 | 0% |
| WA Shopping Admin | 182 | 0 | 0% |
| WA Reddit | 106 | 0 | 0% |

### 论文展示建议

1. **主表**：同时报告 raw SR + adjusted SR（透明度）
2. **Robustness check**：non-visual subset SR 表，证明控制 visual task 后 DOM 劣势依然存在
3. **Discussion**：DOM 在 visual task 上的结构性劣势是 finding（表征选择决定能力边界），不是 confound
4. **实验设计**：说明引入 WA 的 fairness motivation（67%→44%）

## 94. SoM max_marks=80 截断导致 B1 Reddit 模式反转（2026-04-24） [finding]

### 问题

B1 Reddit 出现模式排序反转：DOM adj SR 6.83% > SoM 5.85%，与 Classifieds（SoM 13.84% >> DOM 4.91%）和全部 B0 结果相矛盾。SoM 在信息量上应为 DOM 超集（含截图+标注），理论不应更差。

### 根因：`_extract_text_marks()` 的 `max_marks=80` 截断

`som.py:24` 提取 AXTree 中的 `[id]` 元素构建 `[SOM_MARKS]` 列表，硬编码上限 80 个元素后 break。Reddit 页面元素密集（论坛帖子/评论/链接），viewport 内元素频繁超过 80 个。

| 指标 | Reddit | Classifieds |
|------|--------|-------------|
| **步骤级截断率（mark_count=80）** | B0 33.9% / B1 28.7% | B0 0.2% / B1 0.5% |
| 任何步骤被截断的 task 比例 | B1 74.3%（156/210） | ≈0% |
| DOM-only 成功 7 task 中被截断 | 5/7 | — |

SoM 模式在 Reddit 上丢失了页面下方元素的文本信息，而 DOM 模式的 AXTree 无元素数量上限。4B 模型依赖文本信号（text-over-vision bias），截断后 SoM 的文本信息反而劣于 DOM。

### 统计检验

| 对比 | McNemar p | 95% CI | 显著 |
|------|-----------|--------|------|
| B1 Classifieds SoM > DOM | **0.014** | SoM−DOM: [+1.7%, +11.1%] | ✓ 是 |
| B1 Reddit DOM > SoM | 0.344 | DOM−SoM: [-1.0%, +4.8%] | ✗ 否（含 0） |

B1 Reddit 反转在统计上**不显著**——10 个不一致 pair（DOM-only 7, SoM-only 3）在 n=210 下无法排除随机波动。

### B0 不反转的原因

B0 Reddit SoM 截断率更高（33.9%），但 B0 SoM adj SR 11.71% > DOM 8.78%。235B 模型有足够能力利用截图弥补文本截断，而 4B 不行。这是**截断 × 模型能力**的交互效应。

### 修复

`som.py` `max_marks` 从 80 提升至 200（覆盖 Reddit p99 页面），清除 B0+B1 Reddit SoM 数据后整站重跑。Classifieds 截断率 <1%，不需重跑。

### max_tokens 已排除

B1 `max_new_tokens=384`，实际输出 mean=98-105 tokens，截断率 0.0%-0.04%，与反转无关。

## 95. FP 体系重构：去掉 visual_fp + 简化 eval_fp + 文献对齐（2026-04-24） [design]

### 背景

原 FP 检测三层：na_fp → visual_fp → eval_fp。经文献调研（10 篇核心论文，见 `docs/literature/结果1.md`、`结果2.md`）+ 实验数据审计，发现 visual_fp 和 eval_fp 存在设计问题。

### 决策 1：删除 visual_fp

**理由**：
1. **无文献先例**：10 篇 WA/VWA 核心论文无一做跨 representation 的 visual FP 过滤。VWA 原文立场："all tasks are visually grounded"；ExACT 用 text-only modality 子集做公平比较。
2. **边界不可判**：DOM 文本常泄露视觉信息（颜色在标题中、物品名暗含外观），无法在 task 级别区分"agent 通过文本理解成功"与"碰巧成功"。
3. **过滤范围过大**：手动审计（Codex）确认 VWA 95.3% task 为 visual（classifieds 96.2%/reddit 99.5%/shopping 92.9%），visual_fp 过滤几乎等于否定 DOM 全部成功。
4. **与 routing 研究冲突**：routing 需在全量 task 上工作，剔除 visual task 后仅剩 43 个 VWA task，无法做有意义的路由分析。

**替代方案**：non-visual subset robustness check（手动审计 43 VWA + 480 WA = 523 tasks）。审计结果存于 `docs/analysis/cross_sites/vwa_manual_non_visual_task_ids.py`。

### 决策 2：简化 eval_fp

**问题**：原三层规则（agent_finished + PUR>0.5 + ¬effective_action∧¬require_reset∧url_unique≤2）在逐 case 手动检查过程中递增构建（§78→§83→§88），有过拟合倾向。PUR=0.5、url_unique≤2 等阈值缺乏系统性验证。

**简化后规则**：
```
string_match:  agent_finished=False → E-FP（agent 未提交答案，匹配为评测器噪声）
program_html:  agent_finished=False ∧ ¬has_effective_action → E-FP（agent 未做状态改变操作）
url_match:     不标（导航到正确页面本身是成功）
```

去掉 PUR 阈值和 url_unique 阈值，规则从 3 层减为 2 条，消除 magic number。

**文献依据**：WebArena Verified 用 network activity monitoring + backend state delta 验证 agent 主动完成；我们的 `agent_finished` + `has_effective_action` 是其轻量代理信号。

**鲁棒性保障**：论文做敏感性分析——展示不同 E-FP 定义（无过滤 / 仅 agent_finished / 简化版 / 原三层）下 adjusted SR 变化幅度，证明结论对定义不敏感。

### 决策 3：论文呈现框架

- **主表**：raw + adjusted（仅 na_fp + eval_fp，不含 visual_fp）
- **Robustness check**：non-visual subset SR（VWA 43 + WA 480 = 523 tasks）
- **Discussion**：承认 VWA 无 Verified 版本（文献空白）；引用 WebArena Verified 说明 eval_fp 设计思路；讨论 DOM 在 visual task 上的结构性劣势，指向 non-visual subset

## 96. SoM marks 包含全部元素的设计合理性 + 非交互点击分析（2026-04-25） [design]

### 设计问题

P79 SoM marks 从 AXTree 提取**所有元素**（含 StaticText/heading/image 等非交互元素），VWA 原版 `ImageObservationProcessor` 仅标注可交互元素。是否应过滤为仅可交互？

### 决策：保留全部元素，不过滤

**理由 1——路由研究控制变量**：DOM 模式 AXTree 包含全部元素。若 SoM 仅保留可交互元素，DOM↔SoM 切换同时改变格式和信息量两个变量，路由效果归因不干净。保留全部元素使差异仅为格式（树 vs 扁平列表）+ 图片（有 vs 无）。

**理由 2——Phantom-SoM 消融前提**（§25）：消融矩阵中 A(DOM) vs E(SoM marks+DOM prompt) 隔离纯格式效应，要求文本内容对等。若 SoM 过滤元素，A vs E 混淆格式与信息量，消融失效。

**理由 3——role 标签已提供区分信号**：`[id=87] StaticText 'Postmill'` vs `[id=79] link 'Home'`——agent 理论上可区分。误点非交互元素是模型能力问题，非数据设计问题。

### Classifieds SoM 非交互点击量化

分析脚本：`scripts/analysis/analyze_noninteractive_click_earlystop.py`

| 指标 | B0 (235B) | B1 (4B) |
|------|-----------|---------|
| 早停率（cycle/stuck） | 24/234 (10.3%) | **109/234 (46.6%)** |
| 非交互 click 占总 click | 66/524 (12.6%) | **307/957 (32.1%)** |
| 早停且含非交互 click | 6/24 (25.0%) | **54/109 (49.5%)** |
| 早停且末 3 步全为非交互 click | 5/24 (20.8%) | **37/109 (33.9%)** |

误点 role 分布：`image` 占 62%（classifieds 商品图与链接紧邻），其次 StaticText (18%)、heading (11%)。

### 机制解读

B1 约 1/3 早停由非交互点击直接触发：click image → page 不变 → 无自纠正 → 重复点击 → cycle detector 早停。这是 Mirage Effect 的具体机制之一：扁平列表格式削弱层级结构信号，4B 模型误判可交互性。B0 凭更强能力准确区分 role（非交互 click 率仅 12.6%），印证**截断 × 模型能力**的交互效应（§94）。

## 101. SoM 设计参数 + 三模式分解 + 韦恩图（2026-04-26） [design]

### 一、P79 vs VWA 原版 SoM 设计差异（confound 重新评估）

修订（2026-04-26）：之前列"3 个 confound"，重新审视后实际是 **1 个 fundamental（标注范围）+ 2 个 minor（颜色 + placement）**。颜色和 placement 在 mechanism 层面影响小（用户审视确认）。

#### 1.1 Fundamental 差异：**标注范围 = 两种 SoM 范式**

| 维度 | P79 "Universal SoM" | VWA 原版 "Action-Affordance SoM" |
|---|---|---|
| **标注范围** | 所有元素（含 StaticText、heading、image，§96 决策） | 仅 `Interactable=True`（按钮、link、input） |
| **文本：内容覆盖** | 都含 `[id=N] role 'label'` | 都含（可交互 `[N] [type] [content]`，不可交互 `[] [StaticText] [content]` 无 ID） |
| **文本：ID 分配** | 所有元素有 ID | 仅可交互有 ID |
| **截图：bbox + 标签** | 所有元素 | 仅可交互（截图视觉密度大幅降低） |
| **Action affordance** | 可 `click(id=N)` 任何元素（含 StaticText） | 只能 click 可交互元素 |
| **设计哲学** | trust model with role info（更多自由 + 更多 mistake） | structural constraint（少自由 + 少 mistake） |

→ **不是数量差异，是质的范式差异**：
- P79: 给 model 全部信息 + role 标记，model 必须自己判断"哪些是 actionable"
- VWA: 结构性约束 model 只能 click 可交互——4B 上 §96 的"32% 误点 StaticText" mechanism 在 VWA 原版下**结构性消除**

#### 1.2 Minor 差异（影响小）

| 维度 | P79 | VWA 原版 | 实验 implication |
|---|---|---|---|
| 颜色 | 固定青色 `#00BCD4` | categorical 多色 | 影响小：数字仍是 high salience，多色不消除 hijack 触发器 |
| placement | 上方外侧 → 内部 fallback (2 候选) | 8 候选角 + 重叠避免 | 影响 occlusion 程度，不改变 hijack pattern |
| 填充 | 实心 | 实心 | 相同 |

#### 1.3 P79 反转的 root causes（实证拆解，2026-04-26）

| **B1 reddit SoM** | 1488 | **9.5%** ⭐ | heading (49) |

- **B1 reddit M2 非显著**（9.5% ≈ B0 10.4%）—— B0/B1 reddit 误点率几乎相同，M2 在 reddit 上**不是 B1 反转主因**
- **B1 classifieds M2 显著**（30.0% vs B0 11.3%）—— 主要误点商品 thumbnail (image)
- 但 classifieds B1 仍 SoM > DOM (+6.4pp) → M2 损失被 visual 收益超过

```
classifieds B1 (SoM > DOM +6.4pp 仍正向):
  M1 (hijack)  : 弱（41 marks B1 num_ids=12, 33 marks=0, 阈值未触发）
  M2 (误点 image) : 显著（30% 误点率）但被 visual 收益 +10pp (C subset) 压过
  Net: SoM > DOM

reddit B1 (SoM < DOM -1.9pp 反转):
  M1 (hijack)  : 强（111 marks num_ids=88, 128 marks=446）
  M2 (误点 heading) : 弱（9.5% ≈ B0 10.4%）
  Net: 反转主要由 M1 解释

reddit B0 (SoM > DOM +0.5pp 微正):
  M1 : 极弱（B0 视觉容量足以分辨标签 vs 内容）
  M2 : 弱（10.4% 但 B0 用 role info 不点）
  Net: 截图微弱视觉收益勉强压过损失
```

VWA 原版下预测（修正）：
- M1 (hijack): 标签数 reddit ~74 vs P79 111；阈值是否触发**未知**，hijack 减弱程度待实证
- **M2: 在 reddit 上本来就不显著**（实测 9.5% ≈ B0），VWA 改进意义有限
- **M2: 在 classifieds 上结构性消除**（B1 30%→0%），但 classifieds 上 SoM 已经赢，进一步提升

### 八、Phantom-SoM 4 价值跨 model 评估

之前 framing："Phantom-SoM 是 small VLM 专用 capability-aware 优化"。

**修正 framing**：**Phantom-SoM 是 universal cost-aware routing 工具，对 small VLM 额外有 capability 收益**。

| 价值 | 描述 | B0 (235B) | B1 (4B) |
|---|---|---|---|
| **V1** | 省 50% token 成本（去掉图片 patches） | ✅ 强（API 按 token 收费） | ✅ 强 |
| **V2** | 避免 attention hijack 损失 | ⛔ N/A（B0 probe num_ids 全 0，无 hijack） | ✅ 独有（reddit B1 hijack 严重） |
| **V3** | 保留 SoM action path（coordinate fallback） | ✅ | ✅ |
| **V4** | 作为 routing 中间层（DOM → Phantom → Full SoM） | ✅（cost motivation） | ✅（capability + cost motivation） |

**4 cell × phantom 净价值**：

| Cell | Phantom-SoM 预测 vs Full SoM | 主要 motivation |
|---|---|---|
| **B0 reddit** | Phantom ≈ Full SoM (gap +0.5pp 几乎可忽略) | **cost-saving win**（保 SR + 省 50% cost） |
| **B1 reddit** | Phantom > Full SoM (+2pp 避免 hijack) | **capability + cost double win** ✨ |
| B0 classifieds | Phantom < Full SoM (-7pp 截图有真实视觉收益) | trade-off，对 cost 敏感 task 仍可用 |
| B1 classifieds | Phantom < Full SoM (-6pp) | trade-off |

**关键 implication**：

→ **Reddit 这种高视觉密度站点的截图对所有模型都几乎无 task 价值**（B0 +0.5pp / B1 -1.9pp），不只是"4B 处理不了"。
→ Reddit 永远应该用 cheap mode（DOM/Phantom），无论 capability。
→ Classifieds C subset（page-screen required）必须保留 Full SoM，因为视觉收益 +10pp 实测。

**Phantom-SoM motivation 不依赖反转 magnitude**：

即便 L4 ablation 显示 VWA 原版下 reddit B1 反转消失（SoM ≈ DOM），Phantom-SoM 仍 motivated：
- SoM 含图片 token (~50% input cost)，DOM/Phantom 无
- 同等 SR 下 → cost-saving win（universal）
- 韦恩图角度：SoM only / DOM only 非空 → 两 mode 解决不同 task → 路由 headroom 存在

→ **Phantom-SoM 是 universal cost-aware tool，不是反转 magnitude 的 hostage**。

**论文 contribution 三轴自适应**：

```
观测模式选择 = f(model_capability, site_visual_density, task_category)

routing 决策树：
  IF task_category == A (text-only) THEN DOM (any model, any site)
  IF site == reddit AND model == B1 THEN DOM/Phantom (avoid hijack)
  IF site == classifieds AND task_category == C THEN Full SoM (visual收益 +10pp)
  IF (cost-sensitive 部署 AND SR drop < ε) THEN Phantom-SoM
  ELSE Full SoM
```

### 九、Lazy minimization 假说（与 §100 lazy 机制层）

4B 信号选择策略（lazy minimization）：
```
优先级：数字标签 (高对比 + 清晰) > 文本 (结构化 token) > 截图内容文字 (低对比 + 遮挡)

机制：
  - 给 [文本 + 截图]: 4B 默认用文本（信息密度高 + 解码 cheap）
  - 给 [数字标签 + 内容文字]: 4B 默认 attend 数字（视觉显著 + OCR cheap）
  - 给 [仅截图]: 4B 被迫 OCR（NoMarks 75% recall ≈ B0 78%）

支持证据 (probe 全部吻合)：
  - B1 SoM 高密度 → num_ids 446 (数字 = easy)
  - B1 WithText num_ids → 0/0/0/0/7 (文本可用就忽略截图)
  - B1 WithText reddit_164/14 96% > B0 50%（B1 切换更彻底）
  - B1 NoMarks ≈ B0 NoMarks（视觉本身可用，只是不优先）

物理解释：
  对 4B small VLM，视觉处理成本/收益比更差
  → text-over-vision bias 在 small VLM 更强 (Asadi 2026 ✓)
  → 这是 capability-aware routing 的 mechanistic 解释
```

### 真实 mechanism (跨 site 验证后)

**Reddit clear gradient**: DOM (search-loop 27%, type 38%, 12.7 steps) → Phantom_som (search-loop 20%, type 32%, 9.9 steps) → SoM (search-loop 12%, type 23%, 8.1 steps)
→ AXTree hierarchy 引导持续探索 (search-driven)，[SOM_MARKS] flat-list 引导 quick decision

**Classifieds 弱 gradient**: DOM 与 Phantom_som strategy metric 几乎相同（type 29% vs 32%, steps 11.6 vs 11.9, search-loop 19% vs 18%）
→ representation 改变 task pool 仍存在（Jaccard 0.40-0.48 与 reddit 同水平）但通过 micro-level element selection ordering manifest，不通过 search-loop 这种 macro-strategy

**统一 mechanism**: representation 改变 model 的 default exploration strategy + decision threshold；site-specific magnitude 但 universal effect。

### Plausibility 升级版 H2'

H2': **[SOM_MARKS] 紧凑 flat-list 文本是独立 text representation**，与 AXTree 在 token 分布、结构上有客观差异（无 hierarchy/url/Tab metadata，flat 索引结构）。注：实测同 prompt 同无图条件下 [SOM_MARKS] 与 AXTree 在 input total 上基本相当（reddit +7%, cls -2%, 见 §103-correction 2026-04-27），早期"~50% 少 token"印象**不准确**——core text token 量相当，差异在 **结构 / 顺序 / metadata**，而非长度。Phantom-SoM 的 cost saving 来自 **去 image** (~600/1100 tokens reddit/cls per step)，不是 text 压缩。

**Literature gap**: 所有 SoM 文献（Yang 2023 / VWA Koh 2024 / etc.）都把 marks-text 与 marked-image 当作 bundle，没人 isolate "marks-text as standalone text representation" vs full AXTree 对比。本工作把 [SOM_MARKS] 从"SoM 辅助 channel"提升到"独立 text routing arm"。

### Two-Layer Mechanism 修正（2026-04-27 N=48 数据）

精确 SR pattern 在 same-task subset (n=48) 揭示 prompt 和 representation 各影响**不同 layer**:

```
                 raw_SR    adj_SR    FP gap   na_fp
DOM-prompt:
  DOM            18.75 →  12.50    6.25     3
  Phantom_dom    18.75 →  12.50    6.25     3   ← 与 DOM 完全一致

SoM-prompt:
  Phantom_som    18.75 →  16.67    2.08     1   ← FP 最少
  SoM            22.92 →  16.67    6.25     3
```

**Sharp framing (用户 2026-04-27)**:

> **文字格式影响探索方式** (text representation shapes **how** the agent explores)
> **Prompt 影响探索自信** (prompt tunes **when** the agent commits)

精确 paper 表述:

| Cognitive aspect | Driver | Mechanism | Evidence (n=48) |
|---|---|---|---|
| **Exploration shape** (which actions to prefer, search vs click, multi-step vs early-finish) | **Text representation** ([SOM_MARKS] vs AXTree) | Token-format priming → trajectory pattern | 5/5 macro metrics phantom_dom = phantom_som (search-loop, type%, scroll%, click-loop, selfcorr) |
| **Commitment confidence** (when to terminate via `finish`, FP rate on N/A tasks) | **Prompt** (DOM vs SoM wording) | Prompt wording → terminal-action decision threshold | DOM-prompt 系列 FP=3, FP gap 6.25pp; SoM-prompt 系列 FP=1, FP gap 2.08pp |
| **Task pool divergence** (Jaccard 0.45-0.55) | **Both contribute** | Joint effect on trajectory + outcome | Each layer contributes ~partial task set non-overlap |

**adj_SR aggregate 数字 collision (12.50 vs 12.50, 16.67 vs 16.67) 不是 task-level identity**:
- 仍是 6/48 vs 6/48 stochastic 数字 collision
- task-level Jaccard 仍 ~0.5
- 所以 pattern 显示的是 **prompt 效应在 aggregate FP 数量层面**而非 task pool 层面

**Plausibility 升级**:
- 用户原 framing "[SOM_MARKS] 是独立 text representation" 仍 plausible
- 早期数据 confirm representation 主导 macro behavior
- 但 **prompt 真的也 matter** — 在 output calibration / FP rate layer
- Paper claim 修正: "**Text representation shapes how the agent explores** (search-driven vs select-driven), and **prompt tunes when the agent commits** (FP rate on terminal decisions). These two effects are disentanglable through 2×2 ablation (DOM/SoM-prompt × AXTree/[SOM_MARKS]-obs) and operate on different cognitive layers. Both are necessary; neither alone explains the data."

**这反而 strengthens paper**:
- ✓ Representation 仍是 main novel routing axis
- ✓ Prompt 是 secondary tuning knob (无需诉诸"神奇" mechanism)
- ✓ 2×2 ablation 是 cleanest experimental design，才能看到这个 nuance
- ✓ 与 Sclar 2023 一致（prompt format affects multiple aspects of output）但 extends 到 web agent + 区分了 macro vs calibration layer

### 论文 Narrative — 精炼版（2026-04-27 上午）

**The story in one sentence**: SoM marks 一直被视为 SoM 视觉方法的"附属文本 channel"，但我们 isolate 出来后发现它**单独**就是有效的 text representation routing arm，效应 LLM-grounded（不依赖任何"神奇激活"假说），且 **deployment cost ≈ DOM**——任何已部署 full-SoM agent **后台切掉 image draw + image inference 两步即可变 Phantom-SoM**，零模型改动 / 零 prompt 改动 / 零 eval infra 改动。

**Paper "drop-in" punchline (2026-04-27 晚上)**: Phantom-SoM 是 deployment-time intervention, 不只是 research-time ablation. 现有 SoM agent 部署方只要把 backend annotation pipeline 后两步（image draw + 把 marked image 挂上 inference 请求）切掉，model interface / prompt / action schema / evaluator 全不变，立即拿到 ≈DOM cost + 与 DOM 30-40% non-overlap task pool + drop-one oracle 1.7-2.4pp routing value. **零接入成本的 representation routing arm**.

**Two value props**:

1. **Literature gap**: 现有 SoM 文献（Yang 2023, VWA Koh 2024 等）全部把 marks-text 与 marked-image 当作 bundle 研究——没人对比 marks-text-alone vs full AXTree 作为 standalone text representation 的 task pool 互补性。本工作首次 isolate 出来。

2. **Routing utility (Phantom-SoM cost ≈ DOM, 提供 distinct routing value)**:
   - **关键代码事实** (`p79/experiment/som.py::_extract_text_marks` line 24): [SOM_MARKS] 是 VWA AXTree 文本的 **regex filter**, 取所有带 `[N]` 标记的行 (interactive elements)。**不需要 bbox 提取**, **不需要 image 处理**, 只是 grep。bbox 只在画 marked image 时才用 (full SoM 专用)。
   - **vs DOM 部署 cost**: 几乎为 0 (regex pass over same AXTree)。text 长度 ±7% (3437 vs 3661 reddit, 3008 vs 2948 cls), 差异在结构 (flat 索引 vs hierarchy/url/tab metadata)
   - **vs SoM 部署 cost saving**: (i) image draw 步骤跳过 ~30ms+$2e-5/step, (ii) image tokens 进 inference 完全省 ~600/1100/step on reddit/cls ⭐ dominant saving
   - 综合: **Phantom-SoM ≈ DOM cost, 替代 SoM 视觉证据用 nothing**, but 提供 distinct routing value
   - drop-one oracle reddit -2.4pp / cls -1.7pp（routing pool 第 2 / 第 4 重要）；与 baseline mode 30-40% task pool non-overlap
   - 但带来实质 routing value: drop-one oracle reddit -2.4pp / cls -1.7pp（routing pool 中第 2 / 第 4 重要）
   - 与 baseline mode 30-40% task pool non-overlap，提供独立 routing dimension

**Mechanism (LLM-grounded, no magic)**:

通过严格 ablation (phantom_som vs phantom_dom，唯一变量是 system prompt) 证明:
- search-loop% / click-loop% / scroll% 等 macro strategy metric 由 [SOM_MARKS] vs AXTree **representation 决定**，不是 prompt
- AXTree hierarchical 文本结构 → 模型默认 "persistent navigation exploration" (search-driven)
- [SOM_MARKS] flat list 文本结构 → 模型默认 "quick element selection" (click-driven)
- 这是经典 LLM **prompt-format-sensitivity** / **token-level induction** 现象，不是任何"latent reasoning channel"假说

**Why this is plausible (LLM literature 已有 footing)**:
- LLM 对 prompt format 微小变化敏感是 known phenomenon（chain-of-thought, format consistency 等）
- 这里 "format" = 整个 observation representation 的 token 分布
- AXTree (hierarchy + url + tab metadata) vs [SOM_MARKS] (flat element list) 是**显著不同的 token distribution**
- Different distribution → different latent state → different exploration policy

**Generalization to text-only benchmarks (e.g. WebArena, Mind2Web)**:
- representation effect 不依赖图，纯文本 benchmark 同样适用
- 任何 AXTree-based agent 可零成本添加 [SOM_MARKS] arm 作 routing pool
