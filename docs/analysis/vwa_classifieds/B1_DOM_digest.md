## 三、AXTree 信息可达性分析

### 3.1 商品描述文本不可达

| 指标 | 数值 |
|------|------|
| 到达过详情页的 episode | 139/217 (64%) |
| 详情页 AXTree 缺失商品描述 | 132/139 (95%) |
| 详情页 AXTree 平均长度 | 3,374 字符 |

**关键发现**：Classifieds 站点的商品描述文本不进入 AXTree。即使 agent 进入正确详情页也无法通过 DOM 读取描述中的答案。

### 3.2 视觉关键词回声

在包含视觉关键词的 thought 中，64% 只是在重复任务描述中的词汇，并未产生新的视觉推理。

## 四、脚手架 / 表征结构性缺陷（118 例，54.4%）

### 4.1 视觉/图片信息不可达（99 例，占脚手架问题的 91%）

这是 DOM 模式最大的结构性瓶颈。纯 DOM 环境无法获取图片、颜色、视觉属性等信息。

> §95 变更：虽然 visual_fp 标记已废弃（不再扣除 DOM 视觉任务成功），但视觉信息不可达仍是 DOM 模式的核心结构性限制，约 99 例失败直接归因于此。

### 4.2 商品描述不进入 AXTree

95% 的详情页 AXTree 不含商品描述文本。

### 4.3 非视觉脚手架问题（10 例）

- **动态 UI 后 element_id 失效**（下拉/弹窗）
- **Gallery 网格布局行列不可区分**：AXTree 将所有 item 序列化为线性列表
- **长表单编辑时滚动丢失上下文**（auto-scroll 造成）
- **过滤器 UI 可操作性不足**

## 五、模型能力问题（104 例，48.8%）

### 5.1 搜索循环（29 例）

反复使用同一关键词搜索，无法组合使用分类下拉框和搜索功能。平均 17.1 步。

### 5.2 导航循环（18 例）

在详情页和列表页之间反复跳转。平均 27.9 步（所有类别最高）。

### 5.3 事实推理错误（15 例）

数值比较、价格判断等基础推理频繁出错。平均 8.0 步。

### 5.4 过早结束（12 例）

仅凭部分信息就给出答案。平均仅 2.8 步。

### 5.5 答案对齐错误（10 例）

错误定位目标元素、捏造商品 ID 等。平均 6.6 步。

---

## 5A. 高频模型能力缺陷：翻页与排序

### 5A.1 无法翻页

模型从不尝试点击分页控件，只会反复 scroll 到页面底部。影响所有需要浏览多页结果的任务。

### 5A.2 无法使用 Sort By 排序功能

"找最贵/最便宜的 X" 类任务，agent 从不尝试切换排序方式。

### 两者叠加效应

翻页 + 排序的双重缺失使 agent 被困在"第一页 x 默认排序"的极小视野内。

## 八、DOM 模式的结构性上限与启示

### 信息瓶颈

- **99/213（46.5%）** 的失败直接归因于视觉信息不可达
- **95% 的详情页 AXTree 不含商品描述**
- 即使模型能力无限，DOM 模式在 Classifieds 站点的理论成功率上限约为 **~55%**

### 效率优化目标

- **搜索循环**（42 例 x 19.3 步）和**导航循环**（30 例 x 28.0 步）合计浪费 ~1,649 步
- 如果能提前识别视觉类任务并切换观测模式，可避免大量无效消耗
