# B3 候选重扫 — 喂给 GPT / 任意带搜索的模型

我在为一项 web-agent 研究挑选一个视觉语言模型 (VLM) 基线。请联网检索并给出候选清单。

## 场景

agent 在真实网页环境 (VisualWebArena / WebArena) 里执行多步任务。每一步:
输入 = 任务指令 + 网页观测 (截图 和/或 无障碍树文本), 输出 = 一个 JSON 动作
(形如 `{"action_type": "click", "element_id": 123}`), 由脚手架解析后在浏览器执行。
零样本, 无微调, 无 few-shot 示例, 贪心解码。

## 硬约束 (四条, 缺一出局)

1. **不地板** — 在这类固定 JSON 脚手架上零样本成功率要显著大于 0。
   参照系: Qwen3-VL-4B 在 VWA classifieds 上约 14%, Gemma-3-4B 约 2% (后者我们视为贴地板)。
2. **守格式** — 能稳定输出合法 JSON 动作, 不依赖 few-shot 示例撑格式。
3. **装得下** — bf16 单卡 **A100 40GB**。(一个 27B 的候选因需约 56GB 已出局。)
4. **开源** — 权重可公开下载。闭源 API 模型 (GPT / Claude / Gemini) **一律排除**。

## 强偏好 (不是硬约束, 但影响排序)

- **视觉架构是 bolt-on 而非 native omni** — 即视觉编码器是接在一个语言模型上的,
  而不是从头做原生多模态。原因是我们研究的现象与「模型是否真的在用图像」有关,
  原生架构会改变这个机制, 因此不是中性替换。
- **模型家族要新** — 不能是 Qwen 系 (已有两个 Qwen 基线), 也尽量避开已用过的 Google Gemma 系。
- **非 thinking / 非 reasoning checkpoint 更好** — 会先输出 `<think>...</think>`
  再给动作的模型, 会跟 token 上限相互作用, 带来额外的可比性麻烦。
  如果某个 thinking 模型很强, 也请列出, 但请注明**它的思考能否被干净关闭**以及关闭方式。
- 参数量 4B–14B 这个区间最合适 (要能跟一个 4B 基线做能力对照)。

## 时间窗口

重点是 **2026 年 6 月至今**发布或更新的模型, 但更早的只要符合上面条件也请列出。

## 输出格式

给一个表格, 每行一个候选, 列:

| HF model id | 参数量 | 家族/机构 | 视觉架构 (bolt-on / native) | thinking? (能否关, 怎么关) | 许可证 | bf16 显存估计 | agent benchmark 数字 | 数字来源 |

然后对每个候选写 2-3 句: 为什么它可能符合 / 最大的风险是什么。

## 三条证据纪律 (请严格遵守)

1. **区分「有数字」和「没数字」。** 绝大多数 VLM 不会报 VisualWebArena / WebArena 成绩。
   如果查不到, 就写「无公开 agent 成绩」—— **不要用 MMMU / MathVista 这类静态 benchmark
   的分数替代, 也不要推测**。没有数字本身就是有用的信息。
2. **注明数字来自什么脚手架。** WebVoyager ≠ VisualWebArena; 带 few-shot 或专用 agent 框架
   (如 GenericAgent / SeeAct) 的成绩 ≠ 裸零样本成绩; 「文本-图像交错」评测 ≠ 网页动作评测。
   同一个模型在不同脚手架上的成绩差几倍很常见, 所以脚手架必须写清楚。
3. **给可点击的来源** (HF model card / 官方 repo / arXiv id)。查不到就明说查不到。
