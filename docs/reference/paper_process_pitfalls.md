# 论文过程的坑 — 按「什么时候会咬你」排

> **这份文档收的不是代码 bug**（那是 [[master_bug_catalog]]），是**分析与写作过程**的失败模式：
> 引错一个数、加错一张表、判错一个缺口、覆盖掉合作者的稿子。
> 它们的共同点是 **编译通过、测试通过、log 干净，而结论是错的**。
>
> **用法**：不要通读。做下面某件事之前，跳到对应那一节扫一遍判据。
> 每条的格式是「**判据**（可复用的那句）」+「实例（它是怎么被发现的）」。

---

## 0. 元规律 — 反复出现的四个形状

单个坑记不住，形状记得住。下面四个形状覆盖了本文档大部分条目。

### 0.1 只取一半的量 ⭐ 出现最频繁

一个量有两半，只报了一半，而**另一半才是参照系**。

| 实例 | 取的那半 | 漏的那半 |
|---|---|---|
| §427.7 patching | 位移（displacement）| 收敛（convergence）—— 随机注入靠破坏续写把位移拉满 |
| §427.8 泄漏审计 | 「访问过侧栏」 | 「到达时是否已订阅」 |
| §427.9 覆盖矩阵 | 矩阵里有没有那一格 | 产物自己 caption 里的限定语 |
| §428 头条数 | max over 8–10 个信号 | 未被选中的那些信号的分布 |
| §430 合取校正 | 128 条腿 | 「两条腿都成立」的 64 个假设 |

> **判据：报告一个经过选择的量时，未被选中的那部分才是它的参照系。**
> 具体动作：写下 `max` / `best` / `top` / `胜出` 时，立刻问「分母是什么，被淘汰的长什么样」。

### 0.2 用坏掉的仪器测量

判据本身失效，于是测出的是**仪器的故障**，不是被测对象的属性。

- **B-1955**：`magento indexer:status` 输出是表格（无冒号），旧判据 `awk -F:` 匹配 0 行 → 完成条件**永远为假** → 每次 reset 空转满 4200s。前后调了三次 timeout，都在补一个**不存在的「慢」**。
- **t35 空表**：生成器点名 5 个产物没有的 key，`if k in pg` **静默跳过** → 表头无行。表编译通过、占了一个 float、什么都没说。

> **判据：连续三次修同一个症状而症状不变时，先怀疑判据，不要再调参数。**
> **判据：绕开原工具、换一条独立观测通道去量同一个东西**（查数据库而不是查脚本输出）。

### 0.3 硬编码结论与产物脱钩

一句话写下时是对的，数据长大后没人重新推导，而**旁边的表已经在说另一个数**。

- 2026-08-03 审计：**5 处**（4 个脚本）。4 处是陈旧分母；**第 5 处错在事实**——cascade 生成器声称 Vision 每格最便宜，`WA·B0` 实为 DOM。
- 2026-08-05 又发现 2 处：t27 caption 写「全项目重跑清单 = 两臂」（实为三臂 + WA 五模式）；`17.4x`/`3.95x` 手打（可从产物算出）。

- 2026-08-06 同一根因的**图**版本：`fig_ceilings` 在 Overleaf 里只有 PDF、仓库没有生成脚本，于是面板间距/图例位置谁都改不了；`fig_partition_forest` 更进一步——修好的图例被另一次「重新生成」覆盖回旧样式，**而二进制 diff 在 review 里不可见**。
  重建脚本时又差点用错字段：`oracle_cost_saving_pct`（13.7–35.3）vs 正文的 9.5–30.6，正确是 `triage_`。

> **判据：散文里的每个数字都要能指出它的产物文件。指不出的，就是下一个脱钩点。**
> **判据：这类扫描只能报下界**——2026-08-03 的 sweep 只匹配 `n/6` 一种文本形状，硬编码的**模式名 / 比值 / 方向**从没扫过。
> **判据：「每个数字渲染时从产物读取」如果只覆盖表格不覆盖图，图就是剩下的那个缺口。**
> 图脚本必须和图产物一起入库，并让脚本**打印关键量与正文标称值的对照**。

### 0.4 检查点选在错误的层

在「更早、看起来更根治」的位置检查，结果误报淹没真报。

- **caption 里的 `*x*`**：会提前闭合 pandoc 包住整个 caption 的 `\emph{}`，PDF 里 caption 断成两块而 **log 零警告**。
  我先在**输入侧**加守卫 → 立刻抓到 28 处 `*x*`，但实测**只有 1 处真的坏**（是否破坏取决于 pandoc 的解析上下文，不取决于输入本身）。改到**输出侧**（检测字面残留 `*`）后误报归零。

- **把视觉现象升格成合规判据**（2026-08-06）：查表格越界时先用版心线（842−2.5cm）报出两页越界，被质疑「第二页看起来没压到页码啊」后，我改用「是否压到页码」当判据并**撤回了那一页**。学长的修复证实第一次是对的——ACL 管的是 *Margins: 2.5cm on all sides*，即**是否超出版心**，不是是否压到页码。
  > 被质疑时换基准，却没验证新基准是不是规范本身。正确回应是**把现象和判据分开报**：「视觉上确实没压页码（796.9 < 805.1），但它超出版心 21.7pt，而规范管版心」，让对方自己判。
  > 附带：原判据 771.1 是算出来的、实测散文页到 775.2——**方向对、常数偏严**。那 4pt 该**校准**，我却整个**替换**了基准。校准 ≠ 替换。

> **判据：当一个检查的误报率是 27/28 时，它检查的是错误的层。**
> 正确的检查点是「缺陷第一次变得可判定」的地方，不是最早的地方。
> **判据：换检查基准之前，先确认新基准是不是规范原文。** 「看起来没问题」不是判据。

### 0.5 把一次性快照当成持久清单

审计报告 / 评审意见 / 上次查到的编号，都是**写下那一刻**的状态，而被审的东西还在变。

- **2026-08-06 REALM 终审**：18 条 P1 里，**两条经核实已不存在**——P1.12 说的 caption 自相矛盾早被改掉；P1.18 要求补 Benjamini–Hochberg 引用，而全文只用 Holm、只引 Holm。若照单执行，会去修早已不存在的问题。
- **同一天写 chronicle**：用了几小时前 grep 到的「最新 §435」，而另一个 session 已写到 §437 → 撞号。
- 更早的同形状：§threats 自曝的 5 处硬编码——「**写下时是对的，此后从未重新推导**」。

> **判据：执行任何清单的每一条之前，重新对当前状态取一次证。**
> 尤其是外部审计——它没有你的上下文，也不知道你在它写完之后改了什么。
> **报告里的「Table N / §N」尤其危险**：它引的是 PDF 渲染号，而你的源码用 `\label`，两者可能是**重排而非偏移**（REALM 终审的 "Table 28" = 我们的 `tab:t19`）。先从 `.aux` 的 `\newlabel` 生成映射再动手。

## 1. 引一个数之前

- [ ] **这个数来自哪个产物 JSON？** 指不出来就别引（§0.3）
- [ ] **它是不是 max / best / 胜出？** 是的话，未选中的分布也要报（§0.1）
- [ ] **分母是什么？** 采集集 vs 计分集；per-attempt vs per-success
  - 实例：VWA reddit **205 是采集集、203 是计分集**（AMENDMENT_08 排除 2 个）。多份产物用 205 生成，与论文的 203 不同源
  - 实例：换分母后**6 格里 4 格最便宜的模式会变**，且每一对区间都重叠
- [ ] **它跨了不该跨的边界吗？** B0 付 API 账单、B1/B2 付电费——**不是同一个量**，只有格内排序有意义
- [ ] **它越过噪声地板了吗？** 而且**用的是哪个地板**（见 §2 第一条）
- [ ] **长度 / token / 字节 / 延迟类的数字实测过吗？** 用 `wc -c` / grep 量，不要估

## 2. 把一个差值称为「效应」之前

- [ ] **两次抽样 ≠ 阈值。** 实测重跑差 0.89–2.23pp 是**一次抽样**；那个量的标准差是 2.32–2.53pp
  → 效应要到 **3.8–4.2pp** 才不像单次重跑自己产生的
  > **判据：拿实测重跑差当门槛，等于拿一次掷骰子的点数判断另一次掷骰子大不大。**
- [ ] **地板是量出来的还是搬过去的？** 本项目只有 2 个 cell 有重跑（`cls·B0` 三臂 + `wa_red·B1` 五模式），其余 6 格的地板都是**搬进去**的
- [ ] **「同名」不等于可比。** 相除之前先数臂——六臂并集对一臂基线不是一个比较
- [ ] **配平了哪一维，就只控住了哪一维。** ⭐ 按处理变量的一个维度配对，不等于控住了混杂
  - 实例（B-1969 污染分析，§442.7→§442.8）：把「受影响 episode」与「同 **task id** 的未受影响
    episode」配对，得 5.13% vs 12.65%、单侧 p=0.024，看着像坐实了污染。但受影响的那批 **53% 落在
    B2 格**（cell SR<2%），而基线均匀铺在 18 个 cell、被 B0 的 15–29% 拉高。按 (model,mode) 分层后
    O=4 vs E=6.31、20000 次 permutation **p=0.24 —— 效应消失**
  > **判据：配对前先问「还有哪个维度同时跟『是否受处理』和『结局』都相关」。** 那个维度没配平，
  > 配对不但没帮忙，反而**比不配更危险**——它带着「我已经控制了混杂」的自信
- [ ] **聚合率高 ≠ 普遍发生。** 先数**有多少个体贡献了它**
  - 实例：同一轮说「这些 episode 每一个 step 位置的长尾率都是对照的 2–3×，整个 episode 都在降级
    时段」。实际 77 个里**只有 19 个**有任何超时 step、58 个一个都没有；且 step\_idx=4 处比值是
    **0.89×**（低于 1）。聚合量被少数个体驱动 = 生态学谬误
- [ ] **事件数只能来自事件计数器，不能从记录条目数推。**
  - 实例：`reset_goto_latency_ms_per_attempt` 每 episode 有 2 条（1 次超时 + 1 次成功重试），
    于是「154 条」被写成了「154 次超时」。真值在 `reset_goto_timeout_count`（=77）里明摆着
- [ ] **Monte Carlo 的 p 不可能是 0。** N 次置换的下限是 plus-one 估计 `1/(N+1)`；报 `p=0.000`
  等于宣布自己没做校正（实例：100 次置换报 p=0.000，真实下限 0.0099）
- [ ] **报了数字，就要有能重跑出这个数字的代码。** 在 heredoc / notebook 里跑出来、没落盘的敏感性
  分析 = 不可复现。审计者第一句话就是 "cannot reproduce their median from the committed artifacts"

## 3. 加一张表 / 改一张表之前

- [ ] **新表的口径必须跟其余表一致，不是跟「哪个更对」一致**
  - 实例：我给 t44 选了 leak-zeroed（那是更新的裁定），而 t42 用 leak-kept → 同一格 `red_B2` 在一篇论文里是 2.46% 和 3.94%
  > **判据：口径统一优先于口径正确。** 不一致是审稿人一眼可见的硬伤；口径选择可以在一处集中论证
- [ ] **新表只能追加编号，绝不插中间。** Overleaf 把源序号烤进 `tables/tabNN.tex` 和 `\label{tab:tNN}`；中插会让其后**每个 `\ref` 静默指错表**——不报错，只是指向别的表
- [ ] **不要整体重生成覆盖。** 合作者的手工修复（断行点等）在渲染产物里，不在生成器里
  → 只渲染那一张（见 `one_table.sh` 的做法），或只替换 caption
- [ ] **caption 里不要用 `*单星号*`**（会闭合外层 `\emph{}`），用 `**粗体**`
- [ ] **不要用 `[:N]` 硬截断代替设计决定**
  - 实例：t33 的 `limitations[0][:220]` 断在词中间；`json.dumps(val)[:150]` 把 JSON blob 塞进单元格再拦腰砍
- [ ] **产物 key 缺失要 raise，不要 `if k in d` 静默跳过**（§0.2）

## 4. 判断「这个量测过没有 / 有没有缺口」之前

- [ ] **先查台账，不要 grep chronicle**：`.venv/bin/python3 scripts/maintenance/known.py <keyword>`
  > 2 万行 grep 只在猜对关键词时有用，而「是不是已经做过」恰恰猜不到关键词
- [ ] **列全矩阵逐格实证**，不要抽样后下全称结论
  - 实例：「fire 数据不写 vda1」是**只验证了一个 benchmark** 就下的全称结论；`results/webarena` 其实是普通目录
- [ ] **没测到 ≠ 测出是零。** 聚合脚本空白显示 `?` 不是 `0`；覆盖率不满就不下 corpus 级结论
- [ ] **检出判据是下界时，它不能授权一个修正后的点估计**
  - 实例：能证明「这 6 个成功靠累积状态」，**不能**证明其余都干净 → 主分析保留，敏感性表单独承载
- [ ] **区分设计层 vs 计量层的缺口**：前者要重跑，后者只要重算
- [ ] **一个工具明确拒绝做某事时，那个拒绝往往就是结论，不是障碍**

## 5. 在共享文档上协作之前（Overleaf）

- [ ] **动之前 `git fetch`**，不是做完要推时才发现
- [ ] **fast-forward 成功 ≠ 我的内容该赢**
  > 2026-08-04 我用 `rm -f sections/*.tex` + 拷贝骨架，覆盖了学长三个 commit 的散文。
  > **根因不是忘了 pull——脚本 pull 了而且 fast-forward 成功。**
  > git 能检测「同一行两边都改了」，检测不了「我整份替换了一个我没读过的文件」
- [ ] **真正的防线不是 fetch，是边界**：只改自己写的文件。fetch 是提醒，边界才是保护
- [ ] **拿到一个「骨架文件」时先问它的配套在哪。** 一个 `\input{sections/...}` 列表不代表那些文件是空的
- [ ] **有破坏性同步分支的脚本，整支删掉比加保护更可靠**（`overleaf_sync.sh` 的 `restructured` 分支已移除）
- [ ] **分层并行反而零冲突**：2026-08-05~06 与学长七次并行改同一份稿，只有 §433 那次造成损失（唯一没先 fetch 的）。他改样式、我改内容时 git 自动合并；两次真冲突都是**同一行两边都改**，而那正是 git 能发现的情形 → **合并两者，不要二选一**
- [ ] **append-only 文件不等于并发安全**：chronicle 取「last § + 1」是经典 read-modify-write 竞态，多 session 下会撞号（2026-08-06 撞了两次）。**写之前重新 grep，不要用上次查到的号**
- [ ] **改编号绝不用全局 `sed`**：`s/^### 436\./### 437./` 会连别人 §436 的子节一起改。要么按行号范围，要么先 `git diff` 看影响面——**以 deletions 归零作为验收**
- [ ] **编译产物入版本控制 + rebase = 特有的静默失败**：把带冲突标记的 `.aux` commit 进去后，`latexmk` 退出码非 0 却**一个 `! ` 错误都不打印**，还把失败缓存进 `.fdb_latexmk`（后续调用直接「up-to-date」，`-g` 也救不了，须 `-C`）。表征是产物内部**本该唯一的东西出现两次**（`content-end` 两行）

## 6. 写自动化 / 长任务之前

- [ ] **`grep` 无匹配返回 exit 1**，在 `set -euo pipefail` 下会杀掉脚本——而且**恰好在检查通过时**触发（成功路径才失败）。加 `|| true`
  > 这个坑在两天内踩了两次（`grep -c` 一次、`grep -o | wc -l` 一次）
- [ ] **done-monitor 的 done-condition 不能自匹配**：`pgrep -f "<X>"` 里 X 出现在 monitor 自己的 bash 命令里 → 永远 STILL_RUNNING
- [ ] **until-loop 之后的 bash 只能 stat-only**，不要嵌 python one-liner（嵌套引号在 `bash -c` 里必炸）
- [ ] **为「无人值守」写的自动化，本身是新的无人察觉的失效点**（§431）。给静默失败加显式信号
- [ ] **pkill 的 pattern 要具体到 port / run_id**，并且**要连 watchdog 一起杀**，否则孤儿 watchdog 会一直 spam

## 7. 诊断一个失败之前

- [ ] **关键词 `Unauthorized` / `Blocked` / `Tool not found` → 先 debug 权限，再 debug 能力**
  - 实例：`gemini -p` 被判定「没有 shell 能力」，实为默认审批模式挡住了 tool call
- [ ] **同一个数低估三次时，检查的不是「慢了多少」而是「正确行为发生过没有」**
  - 实例：B-1955 每次都把「浪费」想成正确行为之上多出的一段，实际**正确行为一次都没发生过**
- [ ] **同形错误要一起找。** 修完一处立刻问「这个形状还在哪里」
  - 实例：`\allowbreak{}` 让 grep 报「0 残留」而实际 118 处仍在——pandoc 在 `+` 后插了断点，我的模式只匹配连续形
- [ ] **别急着信另一个 agent 的结论**（含 codex / gemini / GLM）。它们的正确 finding + 我的错误实现 = 一个只在真实例上暴露的新 bug

## 8. 宣布「完成」之前

- [ ] **视觉检查抓的是编译日志抓不到的**：0 error / 0 warning 的 PDF 里查出过 4 个真问题
  ```bash
  pdftoppm -r 110 -png main_restructured.pdf /tmp/pg && ls /tmp/pg*.png   # 然后逐页看
  ```
- [ ] **`\ref` 解析成功 ≠ 指向对的表**（源序号 vs 显示序号是两个东西）
- [ ] **跑 `/stress`**（milestone 前强制），并 chain Mode B (codex) + Mode C (agy)
- [ ] **cross-AI 输出要先验证再用**：大小 >2KB / 无「File not found」/ 发现数达 scope 下限 / 有 ≥1 条 OOB / 引用了具体行号数字
- [ ] **prompt 里引的路径先存在性检查**：
  ```bash
  grep -oE 'docs/[a-zA-Z0-9_/.-]+\.md' "$PROMPT" | while read p; do [ -f "$p" ] || echo "✗ MISSING: $p"; done
  ```

## 9. 位置约定 — 什么写到哪

| 内容 | 去处 |
|---|---|
| 代码缺陷 | `master_bug_catalog.md`（B-number 单调追加）|
| **过程失败模式** | **本文档** |
| 「这个量测过吗 / 这条裁定过吗」 | `known.py` 台账 |
| 过去发生了什么 + 为什么 | `实验笔记.md`（append-only）|
| 现在在跑什么 / 下一步 | `next_steps.md §0` + `_status/` |
| 跨 session 该记住的规则 | `~/.claude/.../memory/` |

> **本文档的准入判据**：这个坑**未来写论文 / 核证据层时还会遇到**，而且**当时不会报错**。
> 只发生一次、或者会被测试抓到的，不进这里。
